**Goal:** Reconcile every campaign record with a durable disposition and route
each unresolved product direction to exactly one future-facing home.

**Architecture:** A committed TSV is the audit's canonical relationship map;
it names records, dispositions, evidence, and any residue destination without
copying campaign narrative. Focused `docs_consistency` parsing and coverage
checks make its structural claims executable, while human evidence review
resolves aliases and closure conflicts instead of treating filename similarity
as proof.

**Tech Stack:** Markdown, TSV, Rust standard library tests in
`cli/tests/suite/docs_consistency.rs`.

**Spec:** `docs/superpowers/specs/2026-09-04-the-coda-design.md`

## Global Constraints

- Preserve historical specs, plans, chronicles, retrospectives, ledgers, and
  decisions at their existing paths; never delete a completed record.
- A registry row is only for a durable speculative product direction, never an
  ordinary bug, cleanup, or process lesson.
- Treat a loose filename match as a lead only; write an alias only after its
  headers, closure evidence, and relevant committed records agree.
- The TSV is a shelf-mark: cite evidence and paths, do not retell campaigns.
- Decisions remain append-only; supersede rather than edit their substance.
- Use the current `docs_consistency` module and Rust standard library; add no
  dependency or separate parsing tool.

## Canonical TSV schema

`docs/audits/campaign-reconciliation.tsv` begins with exactly this tab-delimited
header:

```text
key\tdisposition\tresidue_kind\tresidue_target\tevidence\tspecs\tplans\tledgers\tchronicles\tretrospectives
```

Every following row has ten cells. `key` is a unique stable audit handle;
the five record cells contain comma-separated repository-relative paths (or an
empty string); `evidence` is a non-empty short pointer/citation; and a record
path appears in exactly one row. Permitted `disposition` values are `active`,
`shipped`, `partial`, `superseded`, `abandoned`, and `unresolved`. Permitted
`residue_kind` values are `none`, `registry`, `successor`, `decision`, and
`retro`.

For `partial` and `unresolved`, `residue_kind` is not `none` and
`residue_target` is non-empty. For `shipped`, `superseded`, and `abandoned`,
`residue_kind` is `none` and `residue_target` is empty. A `registry` target is
an idea-registry ID; other target values are repository-relative paths.

- `ReconciliationRow` carries `line: usize`, `key: String`, `disposition:
  String`, `residue_kind: String`, `residue_target: String`, `evidence:
  String`, and `record_paths: Vec<String>`.
- Later tasks use `record_paths` for total coverage and `residue_*` for
  destination validation.

  Add the literal header from the schema above and no data rows to

  ```rust
  #[test]
  fn reconciliation_parser_keeps_all_five_record_columns() {
      let text = "key\tdisposition\tresidue_kind\tresidue_target\tevidence\tspecs\tplans\tledgers\tchronicles\tretrospectives\n\
                  the-example\tpartial\tregistry\tMAP-example\tledger #1\t\
                  docs/superpowers/specs/example.md\tdocs/superpowers/plans/example.md\t\
                  docs/superpowers/ledgers/example.md\tbook/src/chronicle/example.md\t\
                  docs/retrospectives/example.md\n";
      let rows = parse_reconciliation(text);
      assert_eq!(rows.len(), 1);
      assert_eq!(rows[0].record_paths.len(), 5);

  #[test]

      let text = "key\tdisposition\tresidue_kind\tresidue_target\tevidence\tspecs\tplans\tledgers\tchronicles\tretrospectives\n\
                  the-example\tshipped\tnone\t\tevidence\n";

  }
  ```

- [ ] **Step 4: Reconcile the known blind spots without guessing.**

  Start from the 54 unmatched-plan paths and the 244 ledger-exemption

  renamed relationship, verify the connection from headers and closure
  records, then record every path in one canonical row. If no defensible
  connection exists, create a single-record `unresolved` row with a
  `successor`, `decision`, or `retro` destination that names the required
  human resolution; never fabricate a spec-plan pair.

- [ ] **Step 5: Route residue once and repair only proved omissions.**

  For every `partial` or `unresolved` row, search the registry before adding

  owner/successor, and changed rules in an append-only decision. Update a
  status header or direct link only when the row’s evidence demonstrates the
  current text is stale. Record every repair’s source path in the TSV evidence
