# The Grain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the fine layer vary where it honestly can, and make the document say where it cannot — emit the per-room micro-field a consumer can draw, declare which fields are decided at grid resolution, and surface cave mouths.

**Architecture:** Three additive emits and one new test, all in the producer. `windows/scene`'s `surrounds` gains a `micro` object per cell, a `resolution` disclosure block, and cave marks; `windows/locale` gains the coupling-invariant test its `dominant_corner` doc has always described. No world reading changes. No client work, no new derivation, no seed draws.

> **Task 2 changed shape mid-execution.** It originally banded room water from blended drainage. That was built (`dd523ab2`), passed both hypotheses and the gate, and was **reverted** (`76068e6a`) — it split a documented coupling invariant and shrank a calibrated coarse statistic 29%. Spec §5 records the reasoning; the replacement is disclosure, not refinement. Nothing in this plan may reattempt sub-cell water.

**Tech Stack:** Rust 2024, `serde`, `serde_json`, `libm` only. `cargo nextest`. No new dependencies.

## Global Constraints

Copied verbatim from the spec and the repo's `CLAUDE.md`; every task's requirements implicitly include these.

- **Dependency allowlist**: `serde`, `serde_json`, `libm` only, workspace-wide. No new crates.
- **Layering**: `kernel/` → `domains/*` → `windows/*` → `cli/`. A domain depends on `hornvale-kernel` and nothing else. Enforced by `cli/tests/architecture.rs`.
- **No `HashMap`/`HashSet`, no wall-clock time.** `BTreeMap`/`BTreeSet`/`Vec` only. Enforced by `clippy.toml` `disallowed-types` with `-D warnings`.
- **Every crate sets `#![warn(missing_docs)]`.** Every new public item, field and variant gets a one-line doc comment.
- **Quantize at emit only** (decision 0033): serialized floats go through `hornvale_kernel::quantize` at the serialization boundary, never in the compute path.
- **Type audit is default-deny.** Any untagged primitive at a `pub` boundary fails `make gate`. Every new `pub` field must be added to its struct's `/// type-audit:` line. **A tag goes stale silently when a signature changes** — see `tools/type-audit/CLAUDE.md`.
- **Not an epoch.** No task in this plan may add a seed draw, change stream consumption order, or touch a seed-derivation label. If a task appears to need one, STOP and report.
- **`cargo fmt` is the final step before every commit.** Skipped fmt is this project's most common review finding.
- **Run cost-ordered**: `cargo fmt --check` and `cargo clippy` first, then `cargo test -p <crate>`, and only `make gate` at the end.

/// The sub-cell micro-field at a room: four independent axes in `[-1, 1]`,
/// each drawn from the room's own address noise, so a walk through
/// homogeneous biome still varies room to room.
///
/// A scene-side type rather than a re-export of `hornvale_locale::MicroField`,
/// for the reason every other float on this schema is: the wire type carries
/// the emit-boundary quantization (decision 0033) and the producer's type
/// carries the compute-path value. Coupling the published schema to a
/// window's internal struct would make a refactor there a cross-repo schema
/// change here.
///

/// the room's address and the world seed — so an absent value would mean
/// "this emitter chose not to say", which is the exact confusion the
/// `is_here` gate on the fields above created. See this module's doc.
/// type-audit: bare-ok(ratio: relief), bare-ok(ratio: aspect), bare-ok(ratio: wetness), bare-ok(ratio: openness)

    /// Canopy openness, closed (`-1`) to open (`+1`).
    #[serde(serialize_with = "hornvale_kernel::quantize::quantize_serde::f64_field")]
    pub openness: f64,
}

- [ ] **Step 4: Add the disclosure type**

```rust
/// What resolution this chart's fields are decided at.
///
/// **Why a document says this at all.** A chart at walk depth sits six
/// refinement levels below the canonical grid, so a field decided per grid cell
/// is necessarily constant across the whole view — 4^6 rooms share one cell.
/// Read without this block, that flatness looks like the chart contradicting the
/// room's own prose ("open water" against "buttressed canopy, shaded, in a
/// hollow"); read with it, the flatness is the field's resolution stated out
/// loud. This is the same discipline [`Sight`] applies to colour, where
/// `preserves` names what the projection does *not* carry.
///
/// Declaring a resolution is deliberately NOT refining it. A campaign attempted
/// the refinement for `water` and reverted it: thresholding a blend of a
/// *nominal* field's underlay deletes categories and broke a calibrated coarse
/// statistic, where banding a blend of an *ordinal* field's underlay (which is
/// what `relief` does) moves a value at most one band. Sub-cell water belongs to
/// a hydrology model, not to this document.
/// type-audit: bare-ok(count: grid_level), bare-ok(count: depth_below_grid), bare-ok(identifier-text: grid_resolution_fields)
#[derive(Debug, Clone, PartialEq, Serialize)]
pub struct Resolution {
    /// The canonical grid's refinement level.
    pub grid_level: u32,
    /// How many levels below `grid_level` this chart's cells sit. Each level
    /// quarters a cell, so `4^depth_below_grid` rooms share one grid cell.
    pub depth_below_grid: u32,
    /// The names of this document's fields that are decided at grid resolution
    /// and therefore cannot vary below it, in stable order.
    pub grid_resolution_fields: Vec<String>,
}
```

Populate it in the scene builder, appended last in key order so the change stays additive. `grid_resolution_fields` is `["biome", "color", "water"]` in that stable order — biome and water take the dominant corner, and `color` reads the dominant corner's rock (established by `surrounds.rs`'s own colour-grain test and its "a finer colour would need a finer lithology" comment).

**`relief` is not in the list**, because it bands from the blend and genuinely varies. **`micro` is not either** — it is per-room address noise, the finest thing in the document. Getting either of those wrong makes the disclosure a lie, which is worse than having none.

Derive `depth_below_grid` from the actual depths (`room.depth() - ctx.globe_level()`), never a literal `6` — that literal is `walk_depth`'s business, and a zoomed chart has a different value.
