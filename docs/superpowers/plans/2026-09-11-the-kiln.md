# The Kiln Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open `technologies/`, a sixth corpus family, with two frozen corpora and a resolver that scores Hornvale's technology model — authored before the model that would move it.

**Architecture:** Data/code split per decision 0011 — the corpora are JSON under `technologies/`, the loader and report renderer are `cli/src/technologies.rs`, and the guards are `cli/tests/suite/technology_{corpus,coverage}.rs`. Nothing in `domains/*` or `windows/*` reads a corpus file. Demands are **derived** by transitive closure over a prerequisite lattice (0386), never written into the file. One verdict field carries 0136's five values plus 0936's `grown`/`flat`/`unmeasured` plus the new `lost`.

**Tech Stack:** Rust (edition 2024), `serde`/`serde_json` only. `cargo nextest`. No new dependencies — the allowlist is `ALLOWED_EXTERNAL` in `cli/tests/architecture.rs`.

**Spec:** [`docs/superpowers/specs/2026-09-11-the-kiln-design.md`](../specs/2026-09-11-the-kiln-design.md)
**Ledger:** [`docs/superpowers/ledgers/2026-09-11-the-kiln.md`](../ledgers/2026-09-11-the-kiln.md) — write rulings here as they occur, never to `.superpowers/`.

## Global Constraints

- **Tasks 1 and 2 author the corpora and MUST land before any evaluation code exists.** This is what makes the 0016 freeze structural rather than promised, exactly as decision 0936 did it. Do not reorder. Do not write a line of `cli/src/technologies.rs` until both corpora are committed.
- **No new crates.** `serde`, `serde_json`, `libm` only.
- **No `HashMap`/`HashSet`** — `BTreeMap`/`BTreeSet`/`Vec`. Enforced by `clippy.toml`.
- **`#![warn(missing_docs)]`** — every public item, field and variant gets a one-line doc comment.
- **`cargo fmt` as the final step before every commit.** Skipped fmt is this project's most common review finding.
- **Every commit runs `make gate-commit`** via the pre-commit hook. A prose-only commit runs the prose-subject tests instead; both must be green.
- **Verdict vocabulary (closed):** `present`, `refused`, `deferred`, `absent`, `inapplicable`, `grown`, `flat`, `lost`, `unmeasured`.
- **Anchor kinds:** `test:` / `path:` (mechanism), `decision:`, `registry:`, `reason:`, `doc:`. A `doc:` anchor is admissible **only** against a path `docs/generated-paths.txt` gives a generator (0936).
- **`lost` means: a people that held the capability no longer holds it.** One scope, stated in the direction the resolver enforces. Not one community; not the whole world.

- Produces:

```rust
pub struct Corpus { pub corpus: String, pub unit: String, pub ordered: bool,
                    pub provenance: String, pub frozen: String, pub items: Vec<Item> }

pub struct Item {
    pub id: String, pub title: String, pub source: String,
    pub introduces: String, pub presupposes: Vec<String>,
    pub verdict: Verdict, pub anchor: String,
    pub statistic: Option<String>, pub criterion: Option<Criterion>,
    pub contested: Option<bool>, pub disclosure: Option<String>,
    pub note: Option<String>,
}

pub enum Verdict { Present, Refused, Deferred, Absent, Inapplicable,
                   Grown, Flat, Lost, Unmeasured }

pub fn parse(text: &str) -> Corpus;              // fixture-testable, no file
pub fn load(path: &Path) -> Corpus;              // reads the file, delegates to parse
```

**`Item` carries every field the corpora author** (pre-flight ruling F-A).

every later task needs. The five optional ones are genuinely optional — an
item with no measurable criterion has none.

**Both `parse` and `load` exist** (pre-flight ruling F-B). `parse` takes a
`&str` so the parse tests run against fixtures without touching the corpora;
`load` reads a path and delegates. `Criterion` is defined in Task 6 — until
then it may be a unit placeholder that parses and is not evaluated, or Task 6
may widen it; either is fine as long as Task 1's authored `criterion` objects
survive a round trip.

### Task 6: The criterion and the two-way guard

- [ ] **Step 1: Read the sibling's criterion tests before writing yours**

```bash

```

Three of those tests exist because of specific bugs: inclusivity at both band edges, counting only values inside the band, and measuring against the **world count** rather than the value count. Reproduce all three properties for this family — they are the same arithmetic.

- [ ] **Step 2: Write the failing tests, including the divergence property**

This is spec §5.2a, the defect the design nearly shipped with:

```rust
/// A bare boolean cannot see the pathology this campaign exists to detect.
/// Today every surviving community is Classical, so a holding fraction of
/// 1.0 must NOT read as success — it is exactly as wrong as 0.0.
#[test]
fn a_universal_holding_fraction_fails_a_divergence_band() {
    let c = Criterion::FractionInBand { lo: 0.15, hi: 0.85 };
    assert!(!meets(&c, &[1.0; 10], 10), "every people holding it is not divergence");
    assert!(!meets(&c, &[0.0; 10], 10), "no people holding it is not divergence");
    assert!(meets(&c, &[0.5; 10], 10));
}

/// 0936's guard is two-way. An implementation reddening only one direction
/// has built half a guard, and the half it skipped is the one that lets a
/// corpus quietly under-report the world.
#[test]
fn the_guard_reddens_in_both_directions() {
    assert!(two_way(Verdict::Grown, Verdict::Flat).is_some(), "a regularity was lost");
    assert!(two_way(Verdict::Flat, Verdict::Grown).is_some(), "stale pessimism");
    assert!(two_way(Verdict::Grown, Verdict::Grown).is_none());
}

/// `unmeasured` is a lifecycle state, never a coverage verdict, and raises
/// nothing here — which is what makes Task 7's separate tally necessary.
#[test]
fn unmeasured_raises_nothing() {
    assert!(two_way(Verdict::Unmeasured, Verdict::Unmeasured).is_none());
}
```

**Note the guard is tested against constructed input, deliberately.** Every trajectory verdict in both committed corpora is `unmeasured`, so a guard validated only against the corpora would be vacuous — green because it never fires. The successor campaign is what makes it fire; it must be correct before then.
