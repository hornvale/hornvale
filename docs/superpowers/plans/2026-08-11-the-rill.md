# The Rill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the drainage network space-filling and self-similar — render the
flow tree the world already computes for every land cell, then subdivide below
cell scale under boundary conditions taken from that same tree — so a room can
have a stream running through it.

**Architecture:** Two tiers over one keystone: *the coarse flow graph is a
boundary condition, not a suggestion*. Tier 1 renders every land cell's flow
line instead of only the ~6.7% above the river threshold. Tier 2 subdivides on
`RoomAddr`'s own 4-way descent — byte-identical to `Geosphere::new(depth)` —
where the parent's outflow edge constrains which child is the outlet. Discharge
becomes drained **area** so the width law is scale-free.

**Tech Stack:** Rust 2024, `serde`/`serde_json`/`libm` only. `cargo nextest`.
No new crates.

## Global Constraints

- **No `HashMap`/`HashSet`** — `BTreeMap`/`BTreeSet`/`Vec` only (`clippy.toml`).
- **No wall-clock time**, including `std::time::Instant` in test code.
- **Float sorting uses `total_cmp`** with deterministic tie-breaks.
- **`#![warn(missing_docs)]`** — every public item, field and variant gets a
  one-line doc comment.
- **Type-audit tags on every `pub`-boundary primitive.** Ratified `bare-ok`
  classes are exactly: `ratio`, `count`, `index`, `constructor-edge`,
  `envelope`, `identifier-text`, `prose`, `artifact`, `diagnostic-value`,
  `render-internal`, `flag`. **Radians, unit-sphere positions and areas take
  `pending(wave-1: <name>)`.** Regenerate `docs/audits/type-audit-report.md` in
  the same commit whenever a `pub` boundary moves.
- **Transcendentals via `kernel/src/math.rs`**; `floor`/`sqrt` stay intrinsic.
- **Quantize at emit only** — never in the compute path.
- **All distances are angular** (radians on the unit sphere); areas are
  **steradians**. There is no planet radius; do not introduce one.
- **Never serialize a polyline index or a subdivision path** — both are
  build-order or address-derived, not contracts.
- **A new stream label is a save-format contract.** Declare it in the owning
  crate's `streams` module via `stream_labels!`; never borrow an existing one,
  never change an existing label's draw count or order.
- **`LOCALE_MICRO` keeps exactly four `next_f64()` draws in their current
  order.** Removing one silently shifts `openness` in every room of every world.
- **`cargo fmt` last.** Scope tests with `-p`; the controller runs `make gate`.
- **A crate-scoped green is not a branch-green** — the workspace enforcement
  tests (`claim_shape`, `docs_consistency`, `architecture`, the dep allowlist)
  live in `cli/` and no `-p <crate>` run reaches them. Report that in each task.

### Task 1: Discharge becomes an area

`drainage` is an **upstream land-cell count**. A level-12 triangle is
`4^6 = 4096x` smaller in area than a level-6 one, so counts fed into
`w = a·Q^b` make every sub-cell width wrong by a scale factor while still
looking plausible. This task changes the units **with no change to any rendered
value at level 6** — which is what makes it verifiable.

**Files:**
- Modify: `domains/terrain/src/channel.rs`
- Test: `domains/terrain/tests/rill_properties.rs` (create)

**Interfaces:**
- Consumes: `Geosphere::cell_count()`, `Geosphere::level()`;
  `TectonicGlobe.drainage: CellMap<f64>` (unchanged, still a count).
- Produces: `pub fn drained_area(drainage_count: f64, geo: &Geosphere) -> f64`
  — steradians; and `channel_half_width` retaking its first argument as a
  drained **area** rather than a count. `band_edges`'s first parameter changes
  the same way.

**Do not change `TectonicGlobe.drainage` itself.** It is a globe field with
consumers across the workspace and its own type-audit tag; converting at the
point of use is smaller, reversible, and has the same correctness.

- [ ] **Step 1: Read the calibration you must preserve**

Read `CHANNEL_WIDTH_COEFF`'s doc comment in `channel.rs`. It records the fit:
seed 42's largest drainage is **146**, and the coefficient was chosen so the
widest channel on `Geosphere::new(6)` is **1/100 of a canonical cell edge**,
landing at 1/99.8. That measured target is what the recalibration must
reproduce. Report the doc's stated numbers in your report before changing
anything.

- [ ] **Step 2: Derive the new coefficient on paper, in your report**

A cell's area on the unit sphere is `4π / cell_count`. With
`Q_area = count · A_cell`, the law `w = a · edge · Q^0.5` becomes

```
  w = a_new · edge · (count · A_cell)^0.5
    = a_new · A_cell^0.5 · edge · count^0.5
```

so preserving today's answer at level 6 requires exactly

```
  a_new = a_old / A_cell(level 6)^0.5
```

**This is an exact algebraic identity, not a fit.** Write the derivation and
the resulting constant into your report. Do not round it to two figures the way
the original fit was rounded — the original rounding is already baked into
`a_old`, and rounding again would move level-6 widths.

- [ ] **Step 3: Write the failing test — byte-identity at level 6**

The whole point of this task is that nothing visible moves yet. Write a test in
`domains/terrain/tests/rill_properties.rs` asserting that for seed 42 at the
canonical level, **every** `band_edges` value in the built network is
bit-identical (`f64::to_bits`) to the values the pre-change code produced.
Capture the pre-change values as a committed fixture in Step 4's first action —
a comparison against re-derived values from the new code proves nothing.

Also assert the property the task exists for: `drained_area` scales with the
cell count, so the same drainage count at level 12 yields an area `4^6` times
smaller than at level 6.

- [ ] **Step 4: Capture the fixture, then implement**

First, on **unmodified** code, dump the seed-42 network's `band_edges` to a
committed fixture under `domains/terrain/tests/fixtures/`. Commit that alone.
Then add `drained_area`, retype `channel_half_width` and `band_edges`'s first
parameter, update every call site, and recalibrate `CHANNEL_WIDTH_COEFF` per
Step 2.

Update both functions' doc comments: the parameter is now an area in
steradians, and the type-audit tag moves from `bare-ok(count: drainage)` to
`pending(wave-1: drained_area)`.

- [ ] **Step 5: Run and take the branch**

Run: `cargo test -p hornvale-terrain --test rill_properties`

- **byte-identical** → the recalibration is exact; proceed.
- **differs in the last ULP only** → STOP and report. Do not accept it. A
  last-ULP move means the algebra was implemented as two roundings rather than
  one, and it will compound at depth.
- **differs materially** → STOP and report with the two values.

- [ ] **Step 6: `cargo fmt`, clippy, type-audit, commit**

```bash
cargo fmt
cargo clippy -p hornvale-terrain --all-targets -- -D warnings
cargo run --manifest-path tools/type-audit/Cargo.toml -- check
cargo run --manifest-path tools/type-audit/Cargo.toml -- report > docs/audits/type-audit-report.md
git add domains/terrain/src/channel.rs domains/terrain/tests/rill_properties.rs docs/audits/type-audit-report.md
git commit -m "refactor(terrain): discharge is a drained area, not a cell count

A level-12 triangle is 4096x smaller in area than a level-6 one, so a count fed
into w = a*Q^b makes every sub-cell width wrong by a scale factor while still
looking plausible. The coefficient recalibration is an exact identity, so every
level-6 band edge is bit-identical -- asserted against a fixture captured
before the change."
```

### Task 2: Every run reaches its outlet

`build` stops a run **before** a non-river downhill target and then discards
runs shorter than two cells. A river cell whose downhill target is not a river
and which has no river inflow therefore becomes a one-cell run and is dropped.
Stage 1 verified the consequence as a set intersection: the 39 seed-42 river
cells carrying no polyline and the 39 reading `Dry` at their own centres are
the **same 39 cells**.

**Files:**
- Modify: `domains/terrain/src/channel.rs`
- Test: `domains/terrain/tests/rill_properties.rs`

**Interfaces:**
- Consumes: `TectonicGlobe.downhill: CellMap<Option<CellId>>` — `None` on ocean
  and at terminal sinks only.
- Produces: no signature change. `ChannelNetwork.run_cells` gains terminal
  cells; `polylines` and `band_edges` stay parallel to it.

- [ ] **Step 1: Write the failing test (R-2)**

Assert, over **at least three seeds**, that the last cell of every run is one
of exactly three things: it has no downhill target; or its downhill target is
not a river (it is the outlet the run drains into); or it was already claimed
by an earlier run (a confluence). Any run ending on a river cell whose downhill
is also a river cell is a run that stopped short.

Add a **floor**: at least 25 runs per seed and 300 across the sweep, so a
riverless world cannot pass by having nothing to check.

- [ ] **Step 2: Run to verify it fails**

Run: `cargo test -p hornvale-terrain --test rill_properties reaches_its_outlet`
Expected: FAIL — runs currently stop before their non-river target.

- [ ] **Step 3: Implement**

In `build`'s run loop, a non-river downhill target is **pushed and then
breaks**, rather than breaking before the push. The `run.len() >= 2` filter
then only excludes river cells with no downhill target at all; leave it in
place, because that case is still real.

The borrowed terminal vertex's band geometry is the one genuine decision here:
`band_edges` is computed per vertex from that vertex's drainage, slope and
spacing, and the outlet cell is not a river — an ocean cell's values would give
the mouth a nonsense width. **Use the last river cell's band geometry for the
terminal vertex.** State in your report what the alternative would have
produced, measured, not assumed.

- [ ] **Step 4: Run and report the count**

Run: `cargo test -p hornvale-terrain --test rill_properties`

Report how many runs gained a terminal vertex per seed, and confirm seed 42's
previously-uncovered river cells is now **0** (was 39). If it is not zero,
report which cells remain and why — a terminal sink is a legitimate remainder
and is R-1's known exception.

- [ ] **Step 5: `cargo fmt`, clippy, type-audit, commit**

```bash

cargo clippy -p hornvale-terrain --all-targets -- -D warnings
cargo run --manifest-path tools/type-audit/Cargo.toml -- check
```

### Task 4: Tier 2 — subdivision under boundary conditions

**Files:**
- Create: `domains/terrain/src/subdivide.rs`
- Modify: `domains/terrain/src/streams.rs`, `domains/terrain/src/lib.rs`
- Test: `domains/terrain/tests/rill_properties.rs`

**Interfaces:**
- Consumes: `RoomAddr::child`, `RoomAddr::neighbors`, `RoomAddr::corners`;
  the coarse `downhill` graph; Task 1's `drained_area`.
- Produces: `pub fn flow_at(addr: &RoomAddr, globe: &TectonicGlobe, geo: &Geosphere, seed: Seed) -> Option<SubFlow>`
  where `pub struct SubFlow { pub outlet: RoomAddr, pub drained_area: f64 }` —
  the sub-cell flow target and accumulated area for a room, resolved in
  `O(depth)` with nothing stored. `None` where the containing cell has no
  downhill target.

- [ ] **Step 1: Establish the adjacency facts yourself, before designing**

Two facts decide the whole algorithm and the spec states one of them slightly
wrong. Verify both by reading `kernel/src/room.rs` and write what you find in
your report:

1. `RoomAddr::neighbors()[i]` is across the edge **opposite corner `i`** — its
   doc says so at the function.
2. `child(digit)` for digits 0/1/2 keeps corner 0/1/2 and digit 3 is the
   central inverted triangle `[ab, bc, ca]`.

**Therefore the parent's outflow edge is shared by TWO corner children, not
one** — the two whose kept corners are the edge's endpoints. The spec's §4.2
says the outlet child is "forced"; it is constrained to a choice of two. The
constitutional guarantee is unchanged (the outlet lies on the outflow edge) but
the seeded draw has one more degree of freedom than the spec claims. Confirm
this and say so; if you find it is wrong, STOP, because the design rests on it.

- [ ] **Step 2: Add the stream label**

Add one entry to `stream_labels!` in `domains/terrain/src/streams.rs`,
following the existing entries' shape, for the sub-cell spanning-tree draw.
A label is a permanent save-format contract: name it for what it draws, not
for this campaign.

Then regenerate the stream manifest, because `stream_labels()` publishes into a
committed artifact:

```bash
bash scripts/regenerate-artifacts.sh
git diff --stat book/src/reference/
```

- [ ] **Step 3: Write the failing tests (R-3 and R-4) before the algorithm**

**R-4 — the fine network cannot contradict the coarse one.** For every
subdivided cell across at least three seeds: the sub-network has exactly one
outlet; that outlet lies on the parent's outflow edge; and no child drains
across a parent edge that is neither an inlet nor the outlet. The reference is
the coarse `downhill` graph, outside `subdivide.rs`.

**R-3 — drained area is conserved under subdivision.** For every subdivided
cell, the sum of its children's own areas plus its inflows equals its own
accumulation, to within quantization. Write this test **before** the
subdivision exists — it is the guard for Task 1's units change and the thing
that fails loudly if `Q` is left a count.

- [ ] **Step 4: Run to verify they fail**

Run: `cargo test -p hornvale-terrain --test rill_properties subdivide`
Expected: FAIL — no `flow_at`.

- [ ] **Step 5: Implement**

Resolve flow by descending the address: at each level, the parent's outflow
edge and its inlet edges are known from the level above (at the top, from the
coarse `downhill` graph). Choose the outlet child from the two on the outflow
edge, then build a spanning tree over the remaining three children draining
into it, drawing from the Step 2 stream label seeded by the room's own address.

The central child touches no parent edge, so it can never be the outlet and
must drain into a corner child — that is a property of the geometry, not a rule
you impose.

Accumulate area on the way down: a child's drained area is its own area plus
its upstream siblings' plus any inherited inflow. Use `drained_area` from
Task 1 so the units are already right.

- [ ] **Step 6: Run, then measure R-5 — Horton's laws**

Run the property tests, then measure the campaign's central claim: under
Strahler ordering at walk depth, the **bifurcation ratio** `R_b` and the
**length ratio** `R_l`, on at least three seeds.

Preregistered: `R_b` in **[3.0, 5.0]**, `R_l` in **[1.5, 3.5]**. These are the
empirically observed ranges for **real river networks** and the reference lives
entirely outside this codebase.

**Take the branch, do not tune:**
- **both inside** → report the numbers; this is the campaign's headline.
- **either outside** → a **finding, and you ship it as one.** Do not adjust the
  spanning-tree draw to move the number. If you believe the measurement itself
  is wrong (Strahler ordering misapplied, the wrong population), that is a
  different claim — say which you mean and show the working.
