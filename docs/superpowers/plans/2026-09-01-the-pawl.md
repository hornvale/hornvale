**Goal:** Give `kernel/src/fold.rs`'s `LedgerFold` its first tenants — a session-owned, per-entity resident store in `windows/vessel` — so no production read in `liveness.rs` walks an agent's committed `agent-at` trail per evaluation, byte-identically.

**Architecture:** One `ResidentFolds` value (new module `windows/vessel/src/resident.rs`) holds one `Folded<S>` per tenant; each tenant's state is keyed by `EntityId` internally, so a whole tenant advances in O(new facts) per read and a per-entity read is a map lookup. The seam is at READ: every read calls `advance_to(ledger)` first (idempotent in position), so the walk's two evaluations per `wait` and the `&self` snapshot all share one store. This tick's own emitted facts are passed to a read as an overlay slice, exactly as `decide_step` does today. Past-instant reads (the hazard fold's `emitter_arousal` → `affect_of(m, day)`) are served from the last reset at or before the instant, over the resident trail's range.

**Tech Stack:** Rust 2024, `hornvale_kernel::fold::{Folded, LedgerFold}`, `BTreeMap`/`BTreeSet`/`Vec` only, `std::cell::RefCell` (precedent: `kernel/src/room.rs`, `liveness.rs`). No new crates.

**Spec:** `docs/superpowers/specs/2026-09-01-the-pawl-design.md` — read §2, §3, §5 before any task. **Ledger:** `docs/superpowers/ledgers/2026-09-01-the-pawl.md` — every rule executed and every deviation goes there, in the task's own section, as it happens.

**Decision block:** 0536–0545.

## Global Constraints

- **Byte-identical.** No new fact, predicate, stream label or epoch. Do not touch the `MoveTo` arm that pushes `agent_at_fact(...)`, nor `kernel/src/ledger.rs`. The ledger-hash witness (Task 1) must stay green through every task.
- **No serialized surface.** `ResidentFolds` has no `Serialize`/`Deserialize` and is not reachable from `World`.
- **Absorb is pure in `(self, fact)`.** No terrain, no clock, no batch-size dependence inside `LedgerFold::absorb`. Anything needing `terrain` happens at read time.
- **Every tenant owes FOLD ≡ SCAN through `absorb_at`**, compared against the *existing* scan function — never against `Folded::rebuild` (Tailrace §11, item 1).
- **Both chaos schedules** (discard and rebuild the store every position; every third position) pinned per tenant.
- **Line numbers rot; grep function names.** `liveness.rs` is ~16,200 lines. Every location below is a function name.
- **Spec rules 1–6 (§3) are branch tables.** Execute the witness, record the branch taken in the ledger, then act. Never assume the branch.
- **`cargo fmt` last; `type-audit:` tag on every new `pub` primitive** (`tools/type-audit/src/tag.rs` lists the eleven classes); regenerate `docs/audits/type-audit-report.md` in the same commit as any `pub` change.
- **Every commit passes `make gate-commit`** (the pre-commit hook runs it). A test that hangs is a test reading stdin — never write one.
- **Commits end with** `Claude-Session: https://claude.ai/code/session_01VZbMTxSHFDJLtmyAUVztbc`.

**Why this task exists.** The first readout (spec §11) found H2/H4 NOT MET on `session_length_scaling` while `fold_depth_sweep` shows a 98.8× change of order at depth 10,000. The mechanism, read from the code: `Sustenance` holds reset instants only, and `sustenance_at` integrates from the last reset on EVERY read — O(segments since the last reset), with a terrain sample per segment. For an agent that never resets (21 of 50 on the bench, including H2's probe agent) that is O(history) per read, exactly the cost the campaign exists to remove. Spec §2.4 named the state — "accumulated integral `A`, last sighting `(d_n, p_n)`, the segment-start position, last reset; plus the checkpoint list" — and Task 3 shipped the reset list without the accumulator; the review accepted "no read-side memo at all" as vacuously satisfying the purity clause. This task builds it.

**Files:** `windows/vessel/src/resident.rs` (a read-side memo beside `Sustenance`, or inside `ResidentFolds`), `windows/vessel/src/liveness.rs` (`sustenance_at` reads the memo; nothing else changes), `windows/vessel/tests/suite/resident_folds.rs` (the existing bit-exact FOLD ≡ SCAN sweeps, overlay and past-instant tests MUST pass unchanged — they are the oracle; add the cost witness below).

**The property (the implementer owns the layout):**
- A live read at the ledger's end costs O(sightings absorbed since the previous read of that entity), not O(history). A past-instant read costs O(log history) with NO terrain sample.
- **Bit-identical** to the current `sustenance_at`/oracle: the same `f64` additions in the same order. Today's loop sums windows `[reset, s1], [s1, s2], …, [s_n, t]` in order then clamps the total once. A per-reset-partition prefix accumulator `A_i` = the ordered sum of windows from that partition's reset through sighting `i`, read as `A_{i(t)} + rate_i × (t − d_i)` then clamped, performs identical additions. Prefix sums must restart at 0 at each reset (never subtract two accumulated sums — that is not bit-identical). Trap 3 (the reset's governing position is the latest sighting ≤ the reset) and `bounds.dedup()`'s effect on coincident instants are already pinned by the sweeps; make them pass, do not weaken them.
- The memo is a pure function of (ledger prefix, terrain). `absorb` stays terrain-free; the memo advances lazily on read, one segment per newly-absorbed sighting. **One terrain per store**: the store belongs to one session and one world; state that invariant in the memo's doc and keep every FOLD ≡ SCAN test to one terrain per store instance.
- Both reset rules are served: unfiltered (`last_reset`, the past-day affect path) and at-or-before (`decide_step`/`catch_up`) — the partition is chosen by the reset the caller passes, exactly as today.
- The overlay (this tick's `out` facts) is integrated on top of the memo's frontier, never absorbed into it.
- Discarding the memo is unobservable (both chaos schedules extended to it).

- [ ] **Step 1: cost witness first, and it must be RED today.** Extend the Task 3 cost witness to the NON-drinking population: on the seed-42 session over 200 waits, for an agent with zero `drank` facts, segments integrated per read must not grow with tick index (last-50-ticks mean ≤ first-50 mean × 1.5) AND the per-read terrain-sample count must be ≤ the number of NEW sightings since the previous read (+1 for the open segment). Run it; it must fail on the current tree — paste the failure. A witness that is green before the fix proves nothing.
- [ ] **Step 2: build the memo; make Step 1 green; every existing `resident_folds` test unchanged and green** (`cargo test -p hornvale-vessel --test suite -- resident_folds ledger_hash_witness`).
- [ ] **Step 3: both ledger-hash witnesses green** (seed 42 and seed 28), drift check shows only the type-audit report.
- [ ] **Step 4: re-run `fold_depth_sweep` and `session_length_scaling` once each** (record load averages) and paste the `drive_at` column — this is a smoke, not the readout; Task 6's second measurement does the readout.
