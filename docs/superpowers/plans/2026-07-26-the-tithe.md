> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Status:** **Complete 2026-07-28.** All seven tasks shipped. Task 5 grew from one stage into seven
(5, 5b–5g) as spec amendments 3–5 landed mid-execution; the staged-measurement rule held throughout,
so every stage carries its own seed-42 readout and Task 6's attribution survived. Task 7's cost gate

`HV_CENSUS=1 scripts/regenerate-artifacts.sh`. See the

**Goal:** Give the deep-history bake an *accumulation* term — a raid may end in subordination rather than eviction, the tribute rate is a guess on both sides, and what the dominant accumulates is a **store** of wealth rather than mouths to feed.

**Architecture:** All in `windows/worldgen/src/history_bake.rs` plus its emit path. `Community` gains `stores` (feeds strength, never pressure). `maybe_raid` gains a second outcome gated by *asset mobility*: the cell is the immobile prize (evict, shipped path), the people are the mobile prize (subordinate, new). A relation table on `Bake` carries `(subordinate → patron, assessment)`; each epoch the patron collects. Assessment reads the cell (`eff_capacity`) — what the dominant can *see*; remittance reads the subordinate's growth minus concealment — what it *has*. Adaptive demand closes the loop on observed shortfall.

**Tech Stack:** Rust 2024, `hornvale-worldgen`, `hornvale-history`, kernel. `cargo nextest` + doctests; `make gate` / `make gate-full`.

## Global Constraints

- **Determinism (constitutional):** same seed + pins ⇒ byte-identical skeleton. `BTreeMap`/`BTreeSet`/`Vec` only — no `HashMap`/`HashSet`. Every float comparison via `f64::total_cmp` with a deterministic tie-break. **No new seed draw.** No wall-clock.
- **Lorenz-safe:** every quantity is a total function of frozen epoch state and authored species data. `ADAPT_RATE` carries a **verified** stability bound (Task 5) — first-order feedback *with delay* period-doubles above a critical gain, so this is demonstrated by test, never asserted in a comment.
- **Stores never eat.** `pressure = population * NEED / eff` must not read `stores`. Violating this reintroduces the exact defect the spec's §4.2a exists to prevent: a successful extractor starving itself.
- **One new registered predicate** (`pays-tribute-to`). No new `Fact` shape, no new `CauseOfEnd` variant, no new stream label.
- **type-audit:** every primitive at a `pub` boundary carries a `type-audit:` verdict tag. Tag grammar: `type-audit: bare-ok(<class>)` on the item's doc comment; a struct field's verdict goes on the **struct's** doc comment.
- **measure-don't-narrate:** every gate is a real assertion. Four non-binding assertions were found in The Tumult — three only by mutation-testing. **Mutation-verify every new assertion**: break the feature, watch the test redden, restore it.
- **Staged measurement:** Tasks 3, 4 and 5 each end with a seed-42 `history_for` readout so Task 6 can attribute a change to a cause. Knobs here are *opposed* (assessment raises extraction, concealment lowers it); bundling them destroys attribution.
- **Census regen is a G6 carve-out on `lefford`** (0063) — never run locally, never set `HV_CENSUS=1`.

Add to `Bake`, called once per epoch **after** every community has been stepped (so growth exists to tax):

```rust
    /// Each patron collects from each subordinate: it demands what its
    /// assessment says (set from the cell it can SEE) and receives what the
    /// subordinate hands over (paid from that epoch's GROWTH, never the
    /// standing stock — tribute is a tax on surplus, so a subordinate is
    /// milked, not killed). Deterministic: `BTreeMap` iteration is key-ordered.
    fn collect_tribute(&mut self, era: &EraClimate, year: f64) {
        let relations: Vec<(usize, Tribute)> =
            self.tribute.iter().map(|(&s, &t)| (s, t)).collect();
        for (sub, rel) in relations {
            if !self.communities[sub].alive || !self.communities[rel.patron].alive {
                continue;
            }
            let surplus = self.epoch_growth[sub].max(0.0);
            let remittance = rel.assessment.min(surplus);
            self.communities[sub].population -= remittance;
            self.communities[rel.patron].stores += remittance;
            self.tally.tribute_collected += remittance;
            self.touch(rel.patron, year);
        }
        let _ = era;
    }
```

`epoch_growth` is a per-epoch `Vec<f64>` on `Bake`, written by `grow` (the increment it just applied) and cleared at the top of each epoch. Size it to `communities.len()` as communities are opened.

Call `self.collect_tribute(era, year);` at the end of the epoch loop in `bake()`, after the per-community step loop.

### Task 5: Adaptive demand — the oscillator, with a verified bound

**Files:**
- Modify: `windows/worldgen/src/history_bake.rs`
- Test: `windows/worldgen/tests/history_bake.rs`

**Interfaces:**
- Consumes: `collect_tribute`, `Tribute.assessment`, `ASSESS_MAX`.
- Produces: `const ADAPT_RATE: f64`.

> **REVISED before implementation (spec §4.3, commit `ec42a4af`).** The original rule
> — `assessment += shortfall × ADAPT_RATE` — **could not oscillate**, and the demand it adapted
> **never bound**. Both were caught by the Task-4 review. Read spec §4.3 before starting; it now
> carries the corrected mechanism and the derivation of the constants' coupling.

- [ ] **Step 0: Fix the constant that makes the demand inert.**

`remittance = min(assessment, surplus)`, and the logistic increment
`GROWTH_RATE × N × (1 − N/eff)` is maximised at `N = eff/2`, so **surplus never exceeds
`GROWTH_RATE / 4 × eff` = `0.05 × eff`**. With `ASSESS_RATE = 0.1` the assessment sits at
`0.1 × eff` — at least twice the largest surplus the land can produce — so the surplus branch is
selected on *every* world and adapting the assessment changes no remittance anywhere.

Set `ASSESS_RATE` below `GROWTH_RATE / 4`, and **add a test pinning the relationship, not the
value**, so a future change to `GROWTH_RATE` cannot silently re-inert the mechanism:

```rust
#[test]
fn the_assessment_can_actually_bind_against_the_logistic_ceiling() {
    // The largest surplus a subordinate's own land can ever yield is the
    // logistic increment at its peak, N = eff/2 → GROWTH_RATE/4 × eff. An
    // assessment above that is decorative: min(assessment, surplus) would
    // always take the surplus branch, and adapting it would change nothing.
    assert!(
        ASSESS_RATE < GROWTH_RATE / 4.0,
        "ASSESS_RATE {ASSESS_RATE} must sit below the logistic ceiling {}, or the demand never binds",
        GROWTH_RATE / 4.0
    );
}
```

- [ ] **Step 1: Write TWO failing tests.**

(a) **Behaviour — the error term must be two-signed.** A patron whose subordinate **grew** raises its demand; a patron whose subordinate **shrank** lowers it. Both directions in one test, or two — but a test that only checks the rise would pass against the old ratchet and prove nothing.

(b) **Stability, required by the Global Constraints** — over a long bake, every relation's assessment stays within `[0, eff_capacity × ASSESS_MAX]` and does not diverge. This is the Lorenz claim *demonstrated*, not asserted. Note the corrected rule is multiplicative in `assessment`, so also assert it cannot get stuck at exactly `0.0` (a zero assessment would make `signal × assessment × ADAPT_RATE` zero forever — an absorbing state, which is a different failure from divergence).

- [ ] **Step 2: Run — expect FAIL.**

- [ ] **Step 3: Implement.**

`Tribute` gains the memory the feedback needs — what the patron saw last time:

```rust
    /// The subordinate's population when this patron last collected. The
    /// health signal is measured against it, so the patron reacts to how its
    /// vassal has FARED, not to a shortfall it can never see the far side of.
    last_seen_population: f64,
```

Set it at formation (in `maybe_raid`) and update it at every collection. Then, at the end of `collect_tribute`'s loop body:

```rust
            let now_pop = self.communities[sub].population;
            let signal = if rel.last_seen_population > 0.0 {
                (now_pop - rel.last_seen_population) / rel.last_seen_population
            } else {
                0.0
            };
            let ceiling = self.eff_capacity(era, self.communities[sub].site) * ASSESS_MAX;
            let next = (rel.assessment + signal * rel.assessment * ADAPT_RATE).clamp(0.0, ceiling);
            self.tribute.insert(
                sub,
                Tribute { assessment: next, last_seen_population: now_pop, ..rel },
            );
```

with:

```rust
/// How fast a patron corrects its demand toward its subordinate's health — a
/// vassal that grew can bear more, one that shrank is being over-milked. The
/// signal is two-signed, so this is a feedback loop rather than a ratchet.
/// Bounded well below the period-doubling threshold of a first-order feedback
/// with delay; the stability test demonstrates it rather than asserting it.
const ADAPT_RATE: f64 = 0.2;
```

`collect_tribute` re-gains the `era` parameter Task 3 dropped — it is read now.

### Task 5c: The discount rule — the patron's horizon sets its target

**Files:** modify `windows/worldgen/src/history_bake.rs`, `windows/worldgen/src/lib.rs`; test `windows/worldgen/tests/history_bake.rs`

**Interfaces:** consumes `BakeConfig` (the psych channel), `collect_tribute`, `FARM_FLOOR`, `eff_capacity`. Produces `BakeConfig.time_horizon: BTreeMap<KindId, f64>`; `Bake::target_stock(patron_people, eff) -> f64`.

- [ ] **Step 1: Thread `MindVector.time_horizon` into `BakeConfig`**, exactly parallel to `disposition` and `in_group_radius` — same fallback (a people absent from the map is unaffected), populated at the composition root beside them. Authored spread is bugbear 0.3 / hobgoblin 0.5 / kobold 0.8; **goblin is raid-vetoed, so only three values are reachable patron-side** — say so in the doc, because it bounds how much variety this can produce.

- [ ] **Step 2: Write the failing test — strategies must differ.** Two fixtures identical but for the *patron* people's `time_horizon`. Assert the generational patron leaves its vassal **markedly larger** at `now` than the immediate one does, and that both extracted something. This is the first test in the campaign that binds patron-side character; it must fail before the rule exists.

- [ ] **Step 3: Implement the setpoint.**

```rust
/// The stock a patron of this horizon steers its vassal toward. A generational
/// patron targets maximum sustainable yield — the peak of the logistic
/// increment at `eff/2` — so its relation persists indefinitely. An immediate
/// one targets the floor and strips. Between them lie the protection racket and
/// the Danegeld: the family is generated, not enumerated (spec §4.3a).
fn target_stock(&self, people: KindId, eff: f64) -> f64 {
    let h = self.horizon_of(people); // absent ⇒ the neutral middle, not 0
    FARM_FLOOR + h * ((eff / 2.0) - FARM_FLOOR)
}
```

The demand then steers toward `target_stock` rather than taking everything above the floor: a vassal **above** target is drawn down, one **below** is left to recover. §4.3's health feedback stays — it is the controller that reaches this setpoint, and it now corrects around a meaningful target.

- [ ] **Step 4: Run, mutation-verify, measure.** Mutation: make `target_stock` ignore the horizon (return a constant) — the strategy test must redden. Report the seed-42 census **and the extraction-rate spread by patron people** — a single value there means the rule is inert.

- [ ] **Step 5: Commit** — `feat(history): the patron's horizon is a discount rate on sustainable yield (the-tithe T5c)`
