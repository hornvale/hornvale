# Stage 1 — the instrument, minted before the cut

## Task 1: the hash constants, control first

**Goal.** A campaign-time identity witness (decision 0541) that is *known* to
be able to see the fold this campaign migrates.

- New file `windows/vessel/tests/suite/the_kerf.rs`, declared in
  `tests/suite.rs`. It reuses `crate::ledger_hash_witness::{fnv1a,
  run_fixed_script, run_emitter_witness, EMITTER_SEED}` — the same
  cross-module path `the_detent.rs` already uses — and follows
  `the_detent.rs`'s constant shape exactly: a fresh session per hash, the
  constant asserted, the value printed on every run.

**Steps.**

- [ ] **Step 1 — run the controls BEFORE minting anything. TWO of them, in
      this order** (controller resolution, ledger #7 — the plan and spec
      originally named only the second, which is the sharper control and the
      weaker *reach* test):
      - **Control A, reach.** Make `KnownWater::absorb` return immediately.
        The belief set is then empty at every instant, so the hash MUST move
        on any script where the belief set is load-bearing at all. This is
        the one that decides whether the campaign has an identity proof.
      - **Control B, sharpness.** `if day < *first` → `if day > *first`
        (keep the LATEST visit instead of the first). This changes
        `water_at`'s admission ONLY at a past instant, so it moves the hash
        only where a past-instant belief read is load-bearing. B moving is a
        bonus finding, not a requirement; **B not moving while A moves is a
        result to record, not a failure** — it says the script reaches the
        fold but not its past-instant branch.

      Run both against each candidate script and record whether the ledger
      hash moves:
      - the seed-42 fixed script (`run_fixed_script`);
      - the seed-6 emitter script (`run_emitter_witness`, `EMITTER_SEED`);
      - a `WALKING_SEED` script, if the two above are blind.

      Restore the mutation with `git checkout -- windows/vessel/src/resident.rs`
      (never by retyping) and **rebuild** before taking any real reading — a
      restored mutation can leave a stale binary.

      Branch table, on **control A**:
      - **a script moves** → mint the constant on that script.
      - **the seed-42 script does not move** → it does not reach the fold
        under migration; mint on whichever of the others does, and record in
        the module doc which scripts were blind and why (the same finding
        The Detent recorded for its own seed-42 half).
      - **no script moves under A** → STOP. There is no identity proof
        available and the campaign cannot know it changed nothing. Report
        and re-plan.

**Cost, measured rather than guessed** (controller resolution, ledger #8).
`docs/timings/test-baseline-lefford.tsv` records
`the_detent_seed_42_walk_is_deterministic` at **64.937 s** and
`the_detent_emitter_walk_is_deterministic` at **25.671 s** — and each of those
runs its script TWICE, for the two-fresh-runs-agree half. The Kerf needs the
constant, not a second determinism witness (the Detent's two survive on
`main` and are not being replaced), so **run each script ONCE**: ~32 s +
~13 s. If a `WALKING_SEED` script is needed after all, measure it and apply
the same 60 s ceiling and branch table §3 rule 2 gives the Task 3 witnesses.
- [ ] **Step 2 — mint.** Write the constants with the control's evidence
      (command, before/after hash) in the module doc beside them, and the
      note that they retire at close per decision 0541.
- [ ] **Step 3 — green, commit.** `test(the-kerf): campaign-time identity
      constants, control first`.

**Report must contain:** the control's before/after hashes per script, the
minted constants, and the wall time of each witness.

## Task 2: what the three indexes hold, and what advancing them costs

**Goal.** K1 and K2 instrumented, and the BEFORE reading taken.

- [ ] **Step 1 — `entries()` and `held_bytes()` on `Trail`, `KnownWater` and
      `LatestVisit`.** Summed the way `GroundHazards::held_bytes` and
      `FrighteningGround::held_bytes` already sum theirs, carrying the
      identical caveat verbatim in the doc comment: an ESTIMATE of held data,
      not an allocator measurement — neither `BTreeMap`/`Vec` overhead nor
      allocator slack. Each needs its `type-audit: bare-ok(count: return)`
      tag. Unit tests: a hand-built two-entity fixture whose counts are
      derivable by hand, asserted exactly.
- [ ] **Step 2 — the store exposes them.** `ResidentFolds` accessors so the
      bench can read all three without a second `borrow_mut` (the one-guard
      rule). Follow the existing accessor shape.
- [ ] **Step 3 — K2's readout.** In `session_length_scaling.rs`, per band:
      time a COLD `ResidentFolds` advanced over the band's whole ledger and
      divide by `ledger.len()` → ns/fact. Cold is deliberate and the opposite
      of `probe_fold_us`'s warm reads: this measures `absorb`, and a warm
      store absorbs nothing. Scoped `#[allow(clippy::disallowed_types)] //
      benchmark harness` on the `Instant`, as the file already does.
- [ ] **Step 4 — the columns.** Six K1 columns (entries + bytes × three
      indexes) and one K2 column, in the band table beside `ground_len` and
      friends, each with a doc comment on its `Band` field.
- [ ] **Step 5 — the BEFORE reading.** Run the bench in `--release`, at least
      three runs (the spec's own `≥ 3` convention). Record every band's K1 and
      K2 columns and the existing `believed_water_us` /
      `shared_believed_water_us` columns (K3 — already instrumented; this step
      builds nothing for it). Save the raw output under the campaign's scratch
      and put the band-10 row in the ledger.
- [ ] **Step 6 — green, commit.** `feat(the-kerf): what the three indexes
      hold, and what advancing them costs`.

**Report must contain:** the band-10 K1/K2/K3 numbers from every run, the box
and its load averages (all three), and the bench's wall time.

## Task 3: FOLD equals SCAN on two real shapes

**Goal.** The oracle that Stage 2 will re-point, proven green against
*today's* `KnownWater` — because a test written after the change cannot show
that the change preserved anything.

- [ ] **Step 1 — the descending-order fixture.** A hand-built ledger that
      commits one room's sightings in DESCENDING day order, so the first fact
      absorbed for that room is not its first visit. Assert `water_at` admits
      that room at the EARLIEST instant and not at the first committed one.
      Guard it against vacuity the way
      `the_hand_built_ledger_is_not_already_in_sorted_order` guards the
      ordering assertions: assert the fixture really is out of order.
- [ ] **Step 2 — the two shapes.**
      - **possession**: a real `Session` at `WALKING_SEED`, short fixed
        script.
      - **lab**: `crate::the_detent::bench_shape(seed, ticks, agents)`, whose
        `ledger`, `npcs`, `ctx`, `mesh_memo` and `ground` are already `pub`.
      Both need a terrain the `is_water` filter is non-trivial over.
- [ ] **Step 3 — the chaos schedules.** For each shape, both schedules —
      discard and rebuild at every position, and at every third — comparing
      the resident store, the discarded-and-rebuilt store, and
      `known_water_scan_oracle` (kept VERBATIM; it is the only surviving
      statement of the pre-Pawl loop) at every prefix, for every roster
      entity, at instants that include past ones.
- [ ] **Step 4 — the floors, asserted and printed.** Per §3 rule 3: some
      entity has a non-empty `water_at` at the final instant, and some
      comparison runs strictly before that entity's last committed sighting.
      Follow the branch table in the spec if either cannot be met; do not
      weaken a floor to make a shape work.
- [ ] **Step 5 — the cost.** Time each new witness. Under 60 s → record the
      number at the test. Over → shorten the script, re-measure, and record
      BOTH numbers and what reach was lost.
- [ ] **Step 6 — green, commit.** `test(the-kerf): FOLD equals SCAN for the
      belief read on the possession and lab shapes`.

**Report must contain:** each witness's wall time, both floors' measured
values per shape, and — if a script was shortened — the before/after pair.

### Stage 1 close

MAIN-FIRST and re-take Task 2's BEFORE reading (§3 rule 6). Then
`make sluice-stage BRANCH=campaign/the-kerf REF=<full-sha>`.

# Stage 2 — the cut

## Task 4: `water_at` becomes a read over `LatestVisit`

- [ ] **Step 1 — the read.** Private `rooms_at_where(entity, t, keep)` on
      `LatestVisit`; `rooms_at` and `water_at` become its two callers.
      `days.first()`, never `days[0]`. The doc states that `water_at`'s
      correctness now depends on the ascending invariant, and names Task 3's
      fixture as what pins it.
- [ ] **Step 2 — delete `KnownWater`.** The type, its `LedgerFold` impl, the
      `known_water` field, its `advance_to` call, its `position()` assert,
      `ResidentFolds::known_water`, and Task 2's `held_bytes`/`entries` on it.
      Rename `known_water_and_trail` → `latest_visit_trail_and_witness` with
      the new return type. Update `believed_water`'s one line and
      `session.rs`'s doc reference. Remove the benchmark's two `KnownWater`
      fields, reads and table columns at the same time; the AFTER report
      compares the surviving rows directly and records the absent BEFORE row
      as the saving rather than preserving a zero-valued tombstone.
- [ ] **Step 3 — retarget the tests.** Every `resident_folds.rs` site that
      names `KnownWater`, including Task 3's new witnesses and the existing
      `store_discard_schedule`. Where a test compared first-visit maps via
      `KnownWater::of`, derive the comparison locally from `LatestVisit::of`
      rather than adding pub API nothing in production wants.
- [ ] **Step 4 — the discrimination proof (§3 rule 4).** Mutate
      `LatestVisit::water_at`'s membership test (`days.first()` →
      `days.last()`) and confirm every retargeted witness goes RED. Assert the
      target text exists before substituting it — a no-op mutation produces
      evidence and is worse than none. Restore with `git checkout --` and
      rebuild.
      - **all red** → the retarget kept its discrimination; record which
        tests fired.
      - **any green** → that test was pinned to the type, not the behaviour.
        Fix the test, re-run the whole table.
- [ ] **Step 5 — the identity witness.** Task 1's constants must be
      UNCHANGED. A moved constant is the campaign's central claim failing;
      STOP and report rather than re-minting.
- [ ] **Step 6 — green, commit.** `perf(the-kerf): the belief set is a read
      over the visit lists, not a fold of its own`.

**Report must contain:** the mutation table (test × verdict), the hash
constants before and after, and the full workspace gate result.

## Task 5: the AFTER reading, and the close

- [ ] **Step 1 — the AFTER reading.** The same bench, the same number of
      runs, on the same box; report K1, K2 and K3 side by side with Stage 1's
      BEFORE. K1's prediction — `KnownWater`'s row is the whole saving and no
      other row moves — is checked, and a moved `Trail` or `LatestVisit` row
      is reported as a finding rather than absorbed.
- [ ] **Step 2 — retire the constants** (decision 0541): delete the asserted
      values, keep the two-fresh-runs-agree witnesses and every floor, and
      record the constants and their control as dated history in the module
      doc and the chronicle.
- [ ] **Step 3 — the decisions.** 0726 (the earns-its-keep criterion); 0727
      only if the shared-predicate form proved worth binding beyond this type.
- [ ] **Step 4 — the DoD.** Chronicle entry; retrospective; registry rows
      (`TOOL-known-water-is-latest-visit` → shipped with the measured saving;
      `TOOL-place-predicate-index`'s clause rewritten;
      `TOOL-known-water-plan-per-water-room` noted as the axis's sole
      survivor); book freshness sweep; spec §11 filled; `make rebaseline` and
      the drift check (the type-audit report WILL move — pub items changed).
- [ ] **Step 5 — commit, absorb `main`, regenerate, re-gate, G6 digest,
      `make sluice`.** The close commit carries this exact permanent trailer,
      in the final trailer block:

      `Sluice-Headline: one resident index fewer — the water belief moves onto visit lists, byte for byte`

## Standing rules for every task

- Cost-order the iteration, but a crate-scoped green is not a branch green:
  the workspace enforcement tests live in `cli/`. Finish on
  `make gate-commit`.
- `cargo fmt` is the last step before every commit.
- Push the branch at every task boundary.
- Ledger rulings to `docs/superpowers/ledgers/2026-09-04-the-kerf.md` as they
  occur — never to `.superpowers/sdd/`, which is scratch and dies with the
  worktree.
- Three attempts, then stop and report.
