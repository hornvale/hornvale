# The Pyx Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish, by measurement, whether Hornvale's census goldens are
reproducible — by the canonical host across time, by a clean rebuild, and by a
second platform — and record the result as evidence for or against decision
0063's single-canonical-platform ruling.

**Architecture:** Three independent measurement layers, cheapest-first, run in
sequence because two of them contend for the same box. No production code
changes. The only new artifact is one study JSON (data, per decision 0011);
everything else is a run, a diff, and a written finding.

**Tech Stack:** `scripts/census-run.sh` (dispatched to lefford over `ssh
lefford`), `cargo build --release`, `hornvale lab run`, `sha256sum`, `git
diff`.

**Spec:** `docs/superpowers/specs/2026-07-30-the-pyx-design.md`. Predictions
are frozen in its §5 — read them before running anything, and do not edit them
afterwards.

## Global Constraints

- **Nothing this campaign runs may commit a golden.** Every layer is a
  comparison. The only files committed are the study JSON, the plan/spec, and
  the write-ups.
- **Census authorization covers L0 only** (Task 1). It does not extend to any
  additional census run; if Task 1 must be repeated, ask first.
- **Evidence goes to a file, never to a pipe.** No `| tail`, no `| head` on a
  long run. A surprise must never cost a re-run.
- **Host placement (decision 0086):** Tasks 1 and 2 run on **lefford** via
  `ssh lefford`. Task 3 runs on **both** lefford and the Mac. Task 4 is
  writing, on the Mac.
- **The regeneration worktree on lefford is SHARED.** Verify its HEAD before
  use; never assume it is parked where you left it.
- **`HV_CENSUS_REF` must be a full SHA**, never a branch name — it feeds
  `checkout --force` then `reset --hard` (`scripts/census-run.sh:79-93`).
- Campaign branch: `the-pyx`. Worktree:
  `.claude/worktrees/the-pyx/`.

### Task 2: L1 — build reproducibility

**Goal:** is the release binary a pure function of the source on one host?

**Files:**
- Create: `/tmp/pyx-evidence/L1-hashes.txt` (on lefford)
- Commits: none

**Interfaces:**
- Consumes: `L0 GREEN` from Task 1.
- Produces: a verdict (`L1 GREEN` = hashes match / `L1 RED-BENIGN` = hashes
  differ) consumed by Task 4. **Spec §5 predicts RED-BENIGN.** A red result
  here is the expected outcome, not a failure — it closes the cheap
  binary-oracle path and makes Task 3 the primary measurement.

Censuses build under `--release` (`scripts/regenerate-artifacts.sh:344-346`),
so the release binary is the one that matters.

- [ ] **Step 1: Build twice, in two different directories, from clean**

Two directories, because absolute paths are what Rust embeds absent
`--remap-path-prefix`. Same SHA, same flags, same toolchain.

```bash
ssh lefford 'set -e; mkdir -p /tmp/pyx-evidence
  SHA=9855048da84ca7c3b050b88f8b9160a02e75db92
  for d in /tmp/pyx-build-a /tmp/pyx-build-b; do
    rm -rf "$d"
    git -C ~/Projects/hornvale worktree add --force --detach "$d" "$SHA" >/dev/null 2>&1
    (cd "$d" && cargo build --release -p hornvale) > "$d/build.log" 2>&1
    echo "built $d"
  done' 
```

- [ ] **Step 2: Hash both binaries**

```bash
ssh lefford 'sha256sum /tmp/pyx-build-a/target/release/hornvale \
                       /tmp/pyx-build-b/target/release/hornvale \
             | tee /tmp/pyx-evidence/L1-hashes.txt'
```

- [ ] **Step 3: If the hashes differ, localize the difference**

Only run this if Step 2 shows two different hashes.

```bash
ssh lefford 'A=/tmp/pyx-build-a/target/release/hornvale
  B=/tmp/pyx-build-b/target/release/hornvale
  { echo "=== sizes ==="; ls -l "$A" "$B"
    echo "=== differing byte count ==="; cmp -l "$A" "$B" | wc -l
    echo "=== paths embedded in A but not B ==="
    diff <(strings "$A" | grep -c pyx-build-a) \
         <(strings "$B" | grep -c pyx-build-b) || true
  } >> /tmp/pyx-evidence/L1-hashes.txt 2>&1
  cat /tmp/pyx-evidence/L1-hashes.txt'
```

Record the differing-byte count and whether the embedded build paths explain
it. That distinction is the finding: path-only differences are benign;
anything else is not.

- [ ] **Step 4: Record the verdict and clean up**

```bash
ssh lefford 'git -C ~/Projects/hornvale worktree remove --force /tmp/pyx-build-a
             git -C ~/Projects/hornvale worktree remove --force /tmp/pyx-build-b
             git -C ~/Projects/hornvale worktree list'
```

Expected: neither `pyx-build-*` appears. Orphaned worktrees on the canonical
box are a recorded recurring hazard — sweep them.

Deliberately named outside the census convention (see spec D5) so it can run on any machine; nothing it writes is ever committed.",
