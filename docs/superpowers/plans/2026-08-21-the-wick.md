### Task 1: Torch intensity ×4, with the fence pinned

**TDD scenario:** Modifying tested code — run `cargo test -p hornvale-vessel lantern` first, record green.

**Files:**
- Modify: `windows/vessel/src/light.rs` (a small `pub fn scaled(illuminant: &Illuminant, k: f64) -> Illuminant` helper if none exists — check `kernel/src/color.rs` first; prefer vessel-local)
- Modify: `windows/vessel/src/session.rs::chamber_sources` (torch source only)
- Modify: `windows/vessel/tests/lantern_light.rs` (new pin test)

**Steps:**
1. Write the failing pin test FIRST: relative brightness between two cells at Chebyshev distances d1 < d2 from the torch must still follow `(1+d2²)/(1+d1²)` exactly (e.g. d=1 vs d=2 → 2.5/1.0... compute: ratio of lights = (1+4)/(1+1) = 2.5). This is the H4a fence made executable — it must hold BEFORE and AFTER the change.
2. Write a second new test: the torch-lit cell brightness at distance 4 is ~4× its pre-change value (assert via the public seam — e.g. chamber palette colour bytes rise for a far cell on a known lattice).
3. Run both: the first PASSES today (it pins existing behaviour), the second FAILS. Record both.
4. Implement: scale ONLY the torch source's illuminant by 4.0 in `chamber_sources`. Hearth and doorway sources untouched — but CHECK hearth visibility per spec §2.1: render/inspect whether hearth-lit entries are now swamped everywhere; report findings, don't silently adjust.
5. Full `cargo test -p hornvale-vessel` green; note which OTHER tests moved (colour-byte assertions will — that's expected; update them as "moved with the change" not "relaxed").
6. Commit: `feat(vessel): implicit torch burns four times brighter (fence pinned)`.
