# The Cupel Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure, with the Touchstone belief-delta instrument, whether the myth
crossing penalty's *derived* magnitude `span(FINEST)/(1+edges)` changes any
belief that a matched *constant-denominator* penalty `span(FINEST)/D` would not
— settling `KNOW-derived-vs-constant-penalty`.

**Architecture:** Add a penalty-parameterized sibling of the traced walk in
`windows/hearsay/src/traced.rs` (measurement code; the shipped `Crossing`/
`derive.rs` are untouched, and the existing agreement battery still pins the
derived arm == shipped). A fast hand-built fine-ladder control proves the
instrument's day channel discriminates the two magnitudes when the ladder can
express the difference. A heavy readout battery runs three arms (Free / Constant
/ Derived) over the 12-seed panel through the belief-delta instrument and reports
the day / route / width tails against the frozen preregistration.

**Tech Stack:** Rust 2024, `cargo nextest`; `hornvale_hearsay::{traced,
touchstone, transmission, accumulate, ladder, durations}`; the shared test
harness in `windows/hearsay/tests/common/mod.rs`; worldgen for panel builds.

**Spec:** `docs/superpowers/specs/2026-08-20-the-cupel-design.md` (read §2–§6
before starting; §3/§4 are the frozen substrate and preregistration).

## Global Constraints

- **Determinism:** no `HashMap`/`HashSet` (use `BTreeMap`/`BTreeSet`/`Vec`); no
  wall-clock time; float ordering via `to_bits()`/`total_cmp`, never `==`.
- **Dependencies:** `serde`, `serde_json`, `libm` only — no new crates.
- **Docs:** every `pub` item, field, and variant gets a one-line `///`.
- **Type audit:** every primitive at a `pub` boundary carries a `type-audit:`
  tag; run `cargo run --manifest-path tools/type-audit/Cargo.toml -- check`.
- **Heavy tests:** an `#[ignore]`d live-worldgen test's reason string must be the
  **verbatim canonical** string (a drift-guarded roster —
  `cli/tests/suite/heavy_tier.rs` fails on any other): `heavy: live-worldgen
  battery; deferred from the commit gate to the heavy set (decision 0132)`.
- **Do NOT register a lab metric** — a metric runs on ~2000 census worlds
  forever (`windows/lab/CLAUDE.md`). Everything here is a hearsay-crate test.
- **Measurement discipline (decision 0016):** re-derive `D` and every number on
  the tree the test runs on; never transcribe a number from the spec or probe
  into an assertion. A falsified prediction is the finding; never retune `D`.
- **fmt last:** `cargo fmt` before every commit.
- **The traced walk agrees with the shipped walk holder-for-holder** — the
  agreement battery `windows/hearsay/tests/traced_walk.rs` must stay green after
  Task 1; the derived arm is defined as the shipped magnitude.

### Task 1: Penalty-parameterized traced walk

Generalize the traced walk so a caller can price a crossing three ways, without
touching the shipped `Crossing` enum or `derive.rs`. The penalty feeds the
width-first ordering key, so the constant arm must be *re-walked*, not
post-processed.

**Files:**
- Modify: `windows/hearsay/src/traced.rs` (add `PenaltyModel`,
  `traced_variants_with_penalty`; generalize the private `crossing_info`; make
  `traced_variants_about_accumulating` a thin wrapper).
- Test: `windows/hearsay/tests/suite/cupel_penalty.rs` (new fast module) +
  register it in `windows/hearsay/tests/suite.rs`.

**Interfaces:**
- Consumes: existing `Walk`, `PeopleLadders`, `PeopleDurations`, `Accumulation`,
  `HeldTelling`, `Crossing` (all already `pub` in `hornvale_hearsay`).
- Produces (later tasks rely on exactly these):
  ```rust
  /// How a cross-people step is priced, for The Cupel's measurement arms.
  #[derive(Clone, Copy, Debug, PartialEq)]
  pub enum PenaltyModel {
      /// A people boundary costs nothing (the shipped `Crossing::Free`).
      Free,
      /// The derived magnitude `span(FINEST)/(1+edges)` (shipped `ContactWeighted`).
      Derived,
      /// A constant denominator: `span(FINEST)/D`, the same divisor on every
      /// crossing whatever the two peoples' edge count. `D` must be finite and
      /// positive; the caller (the readout) sets it to the matched-mean value.
      ConstantDenominator(f64),
  }

  pub fn traced_variants_with_penalty(
      walk: &Walk,
      ladders: &PeopleLadders,
      durations: &PeopleDurations,
      rule: Accumulation,
      subject: EntityId,
      predicate: &str,
      penalty: PenaltyModel,
  ) -> Vec<HeldTelling>;
  ```
  `traced_variants_about_accumulating` keeps its signature and its behaviour
  (maps `Crossing::Free → PenaltyModel::Free`, `Crossing::ContactWeighted →
  PenaltyModel::Derived`, then delegates).

- [ ] **Step 1: Write the failing test — the penalty parameter is live.**

Create `windows/hearsay/tests/suite/cupel_penalty.rs`. Build a small two-peoples
fixture from the shared harness where a claim genuinely crosses a people
boundary (`common::two_peoples_joined_by_one_raid` gives edges=1), assemble its
`PeopleLadders`/`PeopleDurations` the way `touchstone_controls_probe`'s
`claim_shapes` does, and assert the PROPERTY: **the constant arm's held tellings
differ from the derived arm's on at least one holder** (compare `width.to_bits()`
across the two `Vec<HeldTelling>` merge-joined by holder), for a `D` chosen so
`span/D != span/(1+edges)` (any `D` other than `1+edges`; edges here is 1, so any
`D != 2`). Name the property in the test doc; do not hard-code an expected count.

```rust
// sketch — the assertion is on the PROPERTY, not a transcribed number
let derived = traced_variants_with_penalty(&walk, &ladders, &durs, RULE, subj, PRED, PenaltyModel::Derived);
let constant = traced_variants_with_penalty(&walk, &ladders, &durs, RULE, subj, PRED, PenaltyModel::ConstantDenominator(4.0));
let differs = /* merge-join by holder; any holder with derived.width.to_bits() != constant.width.to_bits() */;
assert!(differs, "the penalty parameter must be live: a constant denominator D != 1+edges must move at least one holder's width");
```

- [ ] **Step 2: Run it, confirm it fails to compile** (`PenaltyModel` /
  `traced_variants_with_penalty` do not exist yet):
  `cargo test -p hornvale-hearsay --test suite -- cupel_penalty` → FAIL (unresolved).
  A compile-error red is not yet evidence the assertion works; Step 4 gives the
  behavioural red.

- [ ] **Step 3: Implement `PenaltyModel` + generalize `crossing_info`.**
  In `traced.rs`: add the `PenaltyModel` enum (doc every variant; the `f64` in
  `ConstantDenominator` is a `pub`-boundary primitive — add a `type-audit:` tag,
  most likely `bare-ok(ratio: denominator)`; confirm with `type-audit check`).
  Change the private `crossing_info` to take `penalty: PenaltyModel` and select
  the magnitude: `Free → 0.0`, `Derived → unit/(1+edges)`, `ConstantDenominator(d)
  → unit/d`, where `unit = ladder.span(FINEST)`; keep the `from == to → (0.0,
  None)` guard first (a same-people step pays zero under EVERY model — this is
  what preserves ingroup-preference-as-output and the negative control). Add
  `traced_variants_with_penalty` as the current body of
  `traced_variants_about_accumulating` with `crossing_info(.., penalty)` threaded
  through, and reduce `traced_variants_about_accumulating` to the thin wrapper.

- [ ] **Step 4: Behavioural red check (prove the assertion catches a dead
  parameter).** Temporarily make `traced_variants_with_penalty` ignore its
  `penalty` argument (always use `Derived`); run the Step-1 test and confirm it
  now FAILS on the assertion (not a compile error). Restore. This is the
  "name the property, then prove the property's test can fail" step — do not
  prescribe this as the shipped mutation; it is a one-off check that the test is
  non-vacuous, recorded in the task report.

- [ ] **Step 5: Run the new test + the agreement battery.**
  `cargo test -p hornvale-hearsay --test suite -- cupel_penalty` → PASS.
  `cargo nextest run -p hornvale-hearsay --run-ignored all -E 'test(traced_walk)'`
  → PASS (the derived arm still equals the shipped walk holder-for-holder; this
  is the regression guard that the wrapper preserved behaviour).

- [ ] **Step 6: fmt, clippy, type-audit, commit.**
  `cargo fmt`; `cargo clippy -p hornvale-hearsay --all-targets -- -D warnings`;

### Task 2: Fine-ladder day-channel liveness control

Prove the instrument's *day* channel can distinguish Derived from Constant when
the ladder is fine enough — so the panel's day-null (§3) is read as ladder
coarseness, not instrument blindness. Fast, hand-built, in the commit-gate suite.

**Files:**
- Test: `windows/hearsay/tests/suite/cupel_fine_ladder.rs` (new fast module) +
  register in `windows/hearsay/tests/suite.rs`.
- (No source change — uses Task 1's `traced_variants_with_penalty`.)

**Interfaces:**
- Consumes: `PenaltyModel`, `traced_variants_with_penalty` (Task 1);
  `common::{two_peoples_joined_by_one_raid, two_peoples_joined_by_three_raids}`
  (four-moon fixtures whose rungs straddle a fraction-of-a-day penalty — see
  their doc comments), `PeopleLadders`, `PeopleDurations`, `Accumulation`.
- Produces: nothing consumed downstream (a leaf control).

- [ ] **Step 1: Write the failing test — the day channel discriminates on a fine
  ladder.** In `cupel_fine_ladder.rs`, build a four-moon fixture where a crossing
  lands the accumulated width near a rung boundary (the
  `two_peoples_joined_by_*_raid*` family is engineered for exactly this — read
  their doc comments for the rung spacing). Assert the PAIRED property, which
  makes the test self-verifying rather than needing an external mutation:
  1. with `ConstantDenominator(D)` for a `D != 1 + edges`, some holder's
     **remembered day** (`claim.object`) or **rung** (`claim.precision`) differs
     from the `Derived` arm's; AND
  2. with `ConstantDenominator((1 + edges) as f64)` (the constant that reproduces
     the derived magnitude on this single-edge fixture), the two arms are
     **bit-identical** on every holder.
  Part (2) is the built-in non-vacuity proof: if the instrument were blind to the
  magnitude, part (1) could not distinguish them either. Read `edges` from the
  fixture's `HeldTelling::crossings[..].edges` rather than assuming it.

- [ ] **Step 2: Run it, confirm it passes** (Task 1 already provides the walk):
  `cargo test -p hornvale-hearsay --test suite -- cupel_fine_ladder` → PASS.

- [ ] **Step 3: Mutation-verify the mechanism personally (task report).** Confirm
  the property is real by making part (1)'s `D` equal `1 + edges`: part (1) must
  then FAIL (the arms agree), and part (2) is what asserts that agreement. Record
  the before/after in the task report. (Per the campaign's discipline, name the
  property; the implementer finds the exact fixture holder that moves.)

- [ ] **Step 4: fmt, clippy, commit.**
  ```bash
  git add windows/hearsay/tests/suite/cupel_fine_ladder.rs windows/hearsay/tests/suite.rs
  git commit -- <those paths>
  ```

### Task 3: The heavy readout battery

Run three arms over the panel through the belief-delta instrument; report the day
(primary), route (co-primary, over the discriminating holders), and width
(mechanism) tails; re-derive `D`; assert the frozen §4 bands and the §5 negative
control.

**Files:**
- Test: `windows/hearsay/tests/cupel_readout.rs` (new top-level heavy binary,
  `#[ignore]`d — mirrors `touchstone_readout.rs`'s structure).
- (No source change.)

**Interfaces:**
- Consumes: `PenaltyModel`, `traced_variants_with_penalty` (Task 1);
  `hornvale_hearsay::touchstone::{tail_counts, changed_tail, belief_deltas,
  TailCounts}`; `common::{PANEL, PREDICATE, RULE, build, read_world,
  Ending::is_foreign, people_homogeneous, pct}`; `Contact`, `Transmission`,
  `Walk`, `Crossing`.
- Produces: nothing (a leaf readout).

- [ ] **Step 1: Write the failing skeleton (controls first, no headline yet).**
  Create `cupel_readout.rs` with the canonical heavy `#[ignore]` reason (see
  Global Constraints), the `claim: structural(seed: panel)` tag (copy from
  `touchstone_readout.rs`), and the panel loop. For each seed, `build` + panel
  `read_world`; over foreign endings run the **derived arm**
  (`WithRaidSeam`, `PenaltyModel::Derived`). First assert only anti-vacuity:
  the derived arm reaches `> 0` cross-people holders (holders with non-empty
  `crossings`). Run it (`cargo nextest run -p hornvale-hearsay --run-ignored all
  -E 'test(cupel_readout)'`) and confirm the anti-vacuity assertion is reached
  and passes — this proves the harness wiring before any measure exists.

- [ ] **Step 2: Re-derive `D` (panel-wide and per-world) on this tree.** From the
  derived arm's realized crossings (`HeldTelling::crossings[..].edges`), compute
  `D_panel = 1.0 / mean_over_all_winning-route-crossings(1.0/(1.0+edges))` and,
  per world, `D_world = 1.0 / mean_over_that_world's_crossings(...)`. Print both.
  Do NOT hard-code 4.7881 — re-derive it; print it so a reader can compare to the
  frozen §3 value and see whether the substrate moved. Assert only that `D_panel`
  is finite and `> 1.0` (a sanity floor: every crossing has `edges >= 1`, so the
  mean discount is `<= 0.5`, so `D >= 2`).

- [ ] **Step 3: The three arms and the belief-delta tails.** For each foreign
  ending, run all three arms with the parameterized walk under `WithRaidSeam`:
  `Free`, `ConstantDenominator(D_panel)`, `Derived`. Merge-join (via
  `tail_counts`, which needs ascending-by-holder inputs — the walk already
  returns that) to accumulate, over the whole panel:
  - `day`, `route`, `rung`, `hops`, `width`, `any` mover counts and
    `reached_both`, for **Derived vs Constant** (the headline comparison). **The
    primary denominator is precise: the set S of holders whose *derived-arm*
    winning route has a non-empty `crossings` vector; filter BOTH arms' vecs to S
    before `tail_counts`, so same-people holders (who pay zero under every
    magnitude and would only dilute the rate) are excluded, not padded in.**
    Report separately — a footnote count, not in the denominator — any holder
    same-people in the derived arm but cross-people in the constant arm (a route
    that flipped across the boundary; expected ~0). Accumulate across
    endings/seeds with an `add_counts` helper exactly like
    `touchstone_readout.rs`'s.
  - the same for **Constant vs Free** and **Derived vs Free** (context), each
    over its own derived-side ≥1-crossing set.
  Print a headline table: the day tail (primary), the width tail (mechanism), and
  the route tail — each as `count / denominator (pct)`, denominator named.

- [ ] **Step 4: The route co-primary, holder-resolved.** Collect the holders
  whose derived-arm winning route crosses at `>= 2` distinct edge counts (the ~15
  discriminating holders) and those with `>= 2` crossings (the ~38), and for each
  report whether `route_changed` between Derived and Constant, listed
  individually (holder id, its crossing edge-counts, whether the account moved).
  This is an enumeration, not a sample — print every one.

- [ ] **Step 5: The negative control (provable zero), mutation-proven.** Restrict
  to holders whose derived-arm winning route has **empty** crossings (a route
  entirely within one people): Derived vs Constant must be bit-identical there
  (every step is same-people, `from == to` returns 0 under both magnitudes), so
  `negative_tail == 0`. Assert it, AND assert the sub-population is non-empty
  (`> 0` holders) so the control is not vacuous. **The controller (not a subagent
  report) re-fires the mutation personally:** delete the `from == to` guard in
  `traced.rs::crossing_info`, confirm this negative assertion reddens, restore,
  confirm green — recorded in the close, per the Touchstone rule that a negative
  control is the one place a vacuous green is invisible.

- [ ] **Step 6: Report the primary against the frozen §4 bands; assert the
  controls and non-vacuity, NOT the day tail itself.** REVISED by controller
  ruling (pre-unblinding): the P5 upper bound assumes the *same route* in both
  arms, but the constant penalty can change which route WINS, and a route change
  can move a rung in a way P5 never bounded — so a day tail above 5% may be a
  legitimate route-driven finding, not a bug. Hard-failing on it would fail the
  test on a real result and couple pass/fail to a prediction. So:
  - **Print** the `day` tail against the §4 bands (`<= 5%` → "DECORATIVE on the
    day channel"; `> 5%` → "a route/width decomposition is needed to attribute
    this"). This is the reading rule, read by a human — NOT an assertion.
  - **Assert** instead the things that must hold regardless of the world: the §5
    negative control (`negative_tail == 0`, sub-population `> 0`); the primary
    denominator `> 0`; `D_panel` finite and `> 1.0`; and **width non-vacuity** —
    the Derived-vs-Constant `width` tail is `> 0` (the two magnitudes genuinely
    differ) AND the Constant-vs-Free `width` tail is `> 0` (the constant penalty
    is genuinely non-zero). These make the readout non-vacuous without asserting
    the headline number.
  - **A loose gross-breakage tripwire only:** assert `day_tail < 0.50`,
    documented in the assert message as "a tripwire against gross substrate
    movement or a wiring bug, NOT the hypothesis — the real reading is the band
    above plus the route decomposition." Do not tighten it toward the prediction.
  - The route co-primary has **no** frozen floor (enumerated, not sampled) — it
    is reported (Step 4), not asserted. Print, do not assert, the robustness arm
    (`D_world`) day tail beside the primary.

- [ ] **Step 7: Run the full readout; capture its output to the scratch for the
  chronicle.**
  `cargo nextest run -p hornvale-hearsay --run-ignored all -E 'test(cupel_readout)' --no-capture 2>&1 | tee <scratch>/cupel-readout.txt`
  → PASS, with the headline table printed. Read the table; the day tail and route
  count are the campaign's result.

- [ ] **Step 8: fmt, clippy, commit.**
  ```bash
  git add windows/hearsay/tests/cupel_readout.rs
  git commit -- windows/hearsay/tests/cupel_readout.rs
  ```
