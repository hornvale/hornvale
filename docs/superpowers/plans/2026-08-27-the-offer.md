# The Offer (Arc IV.a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Objects advertise the verbs they afford, derived from a kind-level property table, so that authoring cost is M verbs + N objects rather than M×N outcomes.

**Architecture:** A vessel-local `ComponentStore<AnchorKind, ObjectTraits>` holds properties as build-state. A pure query intersects the object's properties with each verb's declared requirements, then narrows by the acting body's capacities (Gibson) and the observer's knowledge. The four existing ad-hoc advertisement surfaces are re-pointed at that one query. Nothing is committed and nothing is serialized, which keeps every precondition at or below the "derived state" rung of the spec's §2 scale.

**Tech Stack:** Rust edition 2024; `serde`/`serde_json`/`libm` only (workspace allowlist); `cargo nextest`; no new crates.

**Spec:** `docs/superpowers/specs/2026-08-27-the-offer-design.md` — read §2 (the scale and the arc cut), §3 (the mechanism), §6 (the acceptance test) and §9 (non-goals) before starting. The plan argues from the spec; where they disagree, the spec governs and you should say so in your report.

## Global Constraints

- **Layering is constitutional.** `kernel/` → `domains/*` → `windows/*` → `cli/`. A domain depends on `hornvale-kernel` and nothing else — never another domain, never a window. Enforced by `cli/tests/architecture.rs`.
- **No `HashMap`/`HashSet`.** `BTreeMap`/`BTreeSet`/`Vec` only. Enforced workspace-wide by `clippy.toml` `disallowed-types`.
- **No wall-clock time.** `Instant` is banned, including in tests.
- **Every crate sets `#![warn(missing_docs)]`.** Every public item, field, and variant gets a one-line doc comment.
- **Nothing in this campaign commits a fact or serializes state.** If a task seems to require either, STOP — you have found the IV.a/IV.b line and it is a report, not a workaround.
- **`cargo fmt` is the final step before every commit.** Fmt-gate skips are the most common review finding here.
- **Run `make gate-commit` before each commit.** A warm tree is ~25 s; a kernel-layer edit costs more. This campaign touches no kernel source, so expect the fast path.
- **Doc comments carry `type-audit:` verdict tags** on primitives at a `pub` boundary. See neighbours for the eleven ratified `bare-ok` classes (`tools/type-audit/src/tag.rs:4`). A fieldless enum needs no tag.
- **Never use `--no-verify`.** Never disable a test to make a gate pass.

- **A regression test is specified by the MUTATION it must fail, never by the
  property it should assert.** This campaign has already shipped two vacuous
  tests, both traced to this plan's text: Task 2's asserted a static fact about
  a helper instead of exercising the query, and Task 3's asserted
  `offered_to(k,b)` is a subset of `offered_by(k)`, which is an invariant of
  `Iterator::filter` and true for *any* predicate — including one that refuses
  everything. Both read as the safety property; both were structurally
  incapable of failing; both were caught only when a reviewer ran a mutation.
  **So: for every test whose job is to catch a regression, write the mutation
  into its doc comment, run it, and paste the RED.** A property can be asserted
  vacuously. A mutation cannot be failed vacuously.

- [ ] **Step 1: Write the failing test**

```rust
/// Acceptance test (1): a new OBJECT kind ships with properties only — no
/// dispatcher change — and the right verbs appear on it.
#[test]
fn a_kind_gains_every_verb_its_properties_satisfy_with_no_dispatcher_edit() {
    // Pool carries HoldsLiquid; nothing anywhere names "pool" and "drink"
    // together. The verb arrives because the property matches.
    assert!(offered_by(AnchorKind::Pool).contains(&OfferedVerb::Drink));
    assert!(!offered_by(AnchorKind::Bed).contains(&OfferedVerb::Drink));
}

/// Acceptance test (2): a new VERB ships declaring required properties only —
/// no object change — and appears on every object that qualifies.
///
/// The witness is a verb declared ONLY here, in the test, against the real
/// query. If adding a verb required touching the object table, this cannot
/// pass without that edit — which is the whole point.
#[test]
fn a_verb_appears_on_every_kind_carrying_its_required_properties() {
    let want = BTreeSet::from([ObjectProperty::HoldsLiquid]);
    let reg = object_registry();
    let carriers: BTreeSet<AnchorKind> = reg
        .iter()
        .filter(|(_, t)| want.is_subset(&t.properties))
        .map(|(k, _)| *k)
        .collect();

    assert!(carriers.len() >= 2, "a one-carrier property proves nothing about M+N");
    for kind in carriers {
        assert!(
            offered_by(kind).contains(&OfferedVerb::Drink),
            "{kind:?} carries HoldsLiquid but is not offered drink"
        );
    }
}

/// The offer is a SUBSET relation, not an equality: an object carrying more
/// properties than a verb requires still affords that verb. Guards against an
/// implementation that matches property-sets exactly, which would silently
/// become M x N as objects gain properties.
#[test]
fn extra_properties_do_not_withdraw_an_offer() {
    let mut traits = ObjectTraits::default();
    traits.properties.insert(ObjectProperty::HoldsLiquid);
    traits.properties.insert(ObjectProperty::Encloses);
    assert!(required_properties(OfferedVerb::Drink).is_subset(&traits.properties));
}
```

- [ ] **Step 3: Implement `offered_by` as a subset query**

```rust
/// The verbs `kind` advertises: every verb whose required properties are a
/// SUBSET of the kind's. Subset, never equality — see
/// `extra_properties_do_not_withdraw_an_offer`.
pub fn offered_by(kind: AnchorKind) -> BTreeSet<OfferedVerb> {
    let reg = object_registry();
    // NOT an early return on None. A kind with no registered properties has
    // the EMPTY property set, and `Examine` requires the empty set — so it
    // must still be offered. An early `return BTreeSet::new()` withdraws the
    // universal verb from the 8 AnchorKind variants that carry no properties,
    // contradicting spec §3.3. (This plan said otherwise until Task 2's
    // implementer tested it and it failed.)
    let traits = reg.get(&kind).cloned().unwrap_or_default();
    OfferedVerb::all()
        .into_iter()
        .filter(|v| required_properties(*v).is_subset(&traits.properties))
        .collect()
}
```

`OfferedVerb::Examine` requires the empty set — it is universal (spec §3.3), and the empty set is a subset of everything, so this falls out rather than being special-cased.

- [ ] **Step 4: Run to verify it passes**

Run: `cargo test -p hornvale-vessel --test suite -- affordance`

Name that limit in the test's own doc comment (this project's rule: a check states the direction it enforces, so it cannot be mistaken for a guarantee). If you can write a stronger guard, do, and say what you changed.
