# The Twin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer two questions left open by The Pyx — whether glibc explains
decision 0063's divergence (half A), and whether velaryon produces
byte-identical output when the machine is the *only* variable (half B).

**Architecture:** No production code changes and no new repo surface. Every
arm is a `git clone` at a fixed SHA into `/build`, a `cargo build --release`,
and either a `sha256sum` or a probe-CSV comparison. The upstream
`rust:1.96.1` image supplies the pinned toolchain; nothing is built or pushed.

**Tech Stack:** `docker` (on lefford), `kubectl` (from the Mac),
`rust:1.96.1`, `studies/the-pyx-probe.study.json`, `sha256sum`, `diff`.

**Spec:** `docs/superpowers/specs/2026-07-30-the-twin-design.md`. Predictions
are frozen in its §5 — read them before running anything and do not edit them
afterwards.

## Global Constraints

- **Nothing here authors an artifact.** No census, no golden, no committed
  generated output. Probe runs write into the goldens tree (see below) and
  that directory is deleted after every run.
- **`/build` is the build path on every arm, without exception.** Decision
  0090 amendment 2: the binary-hash oracle is only valid when both sides build
  at the same absolute path, because two production `env!("CARGO_MANIFEST_DIR")`
  sites bake it into the binary. An arm built anywhere else measures nothing.
- **Evidence goes to a file.** `/tmp/twin-evidence/` on whichever host ran it.
  No `| tail` on a long run.
- **`target-cpu=x86-64-v2` stays.** The unflagged builds are throwaway
  diagnostics; nothing here proposes changing what ships.
- **lefford may be busy.** `the-winnowing` was running a heavy job at plan
  time. Check `bash scripts/census-run.sh status` before starting half A and
  expect contention if it is still live.
- Campaign branch: `the-twin`.

### Task 1: The unflagged build must actually be unflagged

**Goal:** prove the diagnostic arms differ from the shipping ones *before*
spending four builds on a comparison that might silently be flagged-vs-flagged.

**Files:**
- Create: `/tmp/twin-evidence/T1-flag-check.txt` (on lefford)
- Commits: none

**Interfaces:**
- Produces: the verified incantation for an unflagged build, consumed by
  Tasks 2 and 3.

This is the anti-vacuity step. `.cargo/config.toml` sets
`target-cpu=x86-64-v2` under `[target.'cfg(target_arch = "x86_64")']`. Cargo
resolves rustflags from the *first* source that matches, and `RUSTFLAGS` in
the environment outranks a `target.*` config entry — but that precedence is
**assumed until this task confirms it**, and if it is wrong the whole of half
A measures nothing.

- [ ] **Step 1: Build both ways and compare the machine code**

`roundsd` is the SSE4.1 floor instruction the flag enables; on the default
`x86-64` baseline LLVM cannot emit it and calls a library `floor` instead.
Its presence is the flag's fingerprint.

```bash
ssh lefford 'set -e; mkdir -p /tmp/twin-evidence
  SHA=<the SHA>
  rm -rf /tmp/twin-flagcheck && git clone -q --no-checkout \
    https://github.com/hornvale/hornvale /tmp/twin-flagcheck
  git -C /tmp/twin-flagcheck checkout -q "$SHA"
  cd /tmp/twin-flagcheck
  { echo "=== FLAGGED (repo default) ==="
    cargo build --release -q -p hornvale 2>&1 | tail -1
    objdump -d target/release/hornvale | grep -c roundsd
    echo "=== UNFLAGGED (RUSTFLAGS override) ==="
    rm -rf target
    RUSTFLAGS="-C target-cpu=x86-64" cargo build --release -q -p hornvale 2>&1 | tail -1
    objdump -d target/release/hornvale | grep -c roundsd
  } > /tmp/twin-evidence/T1-flag-check.txt 2>&1
  cat /tmp/twin-evidence/T1-flag-check.txt'
```

- [ ] **Step 2: Read the verdict**

Expected: a **non-zero** `roundsd` count for the flagged build and **zero**
for the unflagged one.

- Both non-zero → **`RUSTFLAGS` did not override the config.** Do not proceed.
  Fall back to deleting `.cargo/config.toml` in the clone (it is not compiled
  into anything, so removing it is safe) and re-run this task.
- Both zero → the flagged build is not getting the flag either; investigate
  before anything else, because that would mean `main` is not shipping what
  its config says.

- [ ] **Step 3: Record the confirmed incantation**

Write the working form into the evidence file. Tasks 2 and 3 use exactly it.

### Task 2: Half A — does glibc change the world?

**Goal:** cells `A`, `B`, `D`, `E`. Same machine, same rustc, two glibcs,
flag on and off.

**Files:**
- Create: `/tmp/twin-evidence/A.csv`, `B.csv`, `D.csv`, `E.csv` (on lefford)
- Create: `/tmp/twin-evidence/T2-halfA.txt`
- Commits: none

**Interfaces:**
- Consumes: Task 1's confirmed unflagged incantation.
- Produces: verdicts `A vs B` (control) and `D vs E` (the test), consumed by
  Task 4.

Compare **probe output, not binaries**: two glibcs link different symbols, so
the binaries differ for reasons that say nothing about world generation. What
matters is whether the *worlds* differ.

- [ ] **Step 1: Confirm the box is free enough**

```bash

```

A live heavy run means these builds will be slow; it does not make them
wrong. Proceed, but record the load in the evidence file.

- [ ] **Step 2: Run the two HOST arms (`A` flagged, `D` unflagged)**

```bash
ssh lefford 'set -e; SHA=<the SHA>
  rm -rf /tmp/twin-host && git clone -q --no-checkout \
    https://github.com/hornvale/hornvale /tmp/twin-host
  git -C /tmp/twin-host checkout -q "$SHA"
  cd /tmp/twin-host
  for arm in A D; do
    rm -rf target lab-out
    if [ "$arm" = A ]; then FLAGS=""; else FLAGS="-C target-cpu=x86-64"; fi

      lab run studies/the-pyx-probe.study.json > /tmp/twin-evidence/$arm.log 2>&1
    cp lab-out/the-pyx-probe/rows.csv /tmp/twin-evidence/$arm.csv
    rm -rf book/src/laboratory/generated/the-pyx-probe
    echo "$arm done"
  done'
```

- [ ] **Step 3: Run the two CONTAINER arms (`B` flagged, `E` unflagged)**

Identical procedure inside `rust:1.96.1`, cloning to `/build`.

```bash
ssh lefford 'set -e; SHA=<the SHA>
  for arm in B E; do
    if [ "$arm" = B ]; then FLAGS=""; else FLAGS="-C target-cpu=x86-64"; fi
    docker run --rm -v /tmp/twin-evidence:/out \
      -e ARM="$arm" -e SHA="$SHA" -e FLAGS="$FLAGS" rust:1.96.1 sh -c '"'"'
        set -e
        git clone -q --no-checkout https://github.com/hornvale/hornvale /build
        cd /build && git checkout -q "$SHA"

          lab run studies/the-pyx-probe.study.json > /out/$ARM.log 2>&1
        cp lab-out/the-pyx-probe/rows.csv /out/$ARM.csv
      '"'"'
    echo "$arm done"
  done'
```

- [ ] **Step 4: Record each arm's environment**

- [ ] **Step 5: Compare**

```bash

    echo "=== TEST: D vs E (unflagged, glibc differs) ==="; diff D.csv E.csv && echo IDENTICAL
    echo "=== flag effect on one glibc: A vs D ==="; diff A.csv D.csv && echo IDENTICAL
```

- [ ] **Step 6: Read out seed 681 across all four arms**

```bash
ssh lefford 'cd /tmp/twin-evidence && python3 -c "
import csv
for arm in (\"A\",\"B\",\"D\",\"E\"):
    for row in csv.DictReader(open(arm+\".csv\")):
```

- [ ] **Step 7: Record the verdicts**

- `A == B` → the control holds; glibc is irrelevant when `floor` is an
  instruction, as the hypothesis itself predicts.
- `D == E` → **the codegen hypothesis is dead** (the frozen prediction).
  0063's divergence remains unexplained; the surviving candidates are CPU

- `D != E` → **the hypothesis is confirmed.** Record exactly which columns

- `A != B` → cross-platform byte-identity is violated *with* the flag. Stop
  and report; this outranks the campaign.

### Task 3: Half B — does the machine matter when nothing else does?

**Goal:** cells `B` and `C`. Identical image, glibc, rustc, and `/build` path.
The machine is the only variable.

**Files:**
- Create: `/tmp/twin-evidence/B-binary.txt` (lefford),
  `/tmp/twin-evidence/C-binary.txt` (Mac, from `kubectl logs`)
- Commits: none

**Interfaces:**
- Consumes: the SHA. Independent of Task 2.
- Produces: the `B` vs `C` hash verdict, consumed by Task 4.

- [ ] **Step 1: Build `B` — the container arm on lefford**

Note this is a *binary* hash, so unlike Task 2 it must not run the probe.

```bash
ssh lefford 'SHA=<the SHA>
  docker run --rm -e SHA="$SHA" rust:1.96.1 sh -c '"'"'
    set -e
    git clone -q --no-checkout https://github.com/hornvale/hornvale /build
    cd /build && git checkout -q "$SHA"
    cargo build --release -q -p hornvale
    echo "--- ENV ---"; rustc --version; ldd --version | head -1; uname -m; pwd
    echo "--- HASH ---"; sha256sum target/release/hornvale
  '"'"' | tee /tmp/twin-evidence/B-binary.txt'
```

- [ ] **Step 2: Write the velaryon Job manifest**

Both tolerations are mandatory — velaryon carries `platform=x86:NoSchedule`
and `gpu=true:NoSchedule`, and a Job missing either stays `Pending` forever
rather than failing.

```bash
cat > /tmp/twin-job.yaml <<'YAML'
apiVersion: batch/v1
kind: Job
metadata:
  name: twin-probe
  namespace: default
spec:
  backoffLimit: 0
  ttlSecondsAfterFinished: 3600
  template:
    spec:
      restartPolicy: Never
      nodeSelector:
        kubernetes.io/hostname: velaryon
      tolerations:
        - { key: platform, operator: Equal, value: x86, effect: NoSchedule }
        - { key: gpu, operator: Equal, value: "true", effect: NoSchedule }
      containers:
        - name: build
          image: rust:1.96.1
          command: ["sh", "-c"]
          args:
            - |
              set -e
              git clone -q --no-checkout https://github.com/hornvale/hornvale /build
              cd /build && git checkout -q "$SHA"
              cargo build --release -q -p hornvale
              echo "--- ENV ---"; rustc --version; ldd --version | head -1; uname -m; pwd
              echo "--- HASH ---"; sha256sum target/release/hornvale
          env:
            - { name: SHA, value: "<the SHA>" }
          resources:
            requests: { cpu: "8", memory: "8Gi" }
            limits: { cpu: "20", memory: "24Gi" }
YAML
kubectl apply -f /tmp/twin-job.yaml
```

- [ ] **Step 3: Confirm it actually scheduled — do not just wait**

```bash
kubectl get pod -l job-name=twin-probe -o wide
kubectl describe pod -l job-name=twin-probe | tail -20
```

`Pending` with a `FailedScheduling` event means a toleration or the
nodeSelector is wrong. **Fix the manifest; do not wait it out.** Confirm the
`NODE` column reads `velaryon`.

- [ ] **Step 4: Wait for completion and capture the log**

```bash
kubectl wait --for=condition=complete --timeout=45m job/twin-probe \
  || kubectl describe job/twin-probe | tail -20
kubectl logs -l job-name=twin-probe --tail=50 | tee /tmp/twin-evidence/C-binary.txt
```

- [ ] **Step 5: Compare, and check the environments matched**

```bash
echo "=== B (lefford, container) ==="; ssh lefford 'cat /tmp/twin-evidence/B-binary.txt'
echo "=== C (velaryon, container) ==="; cat /tmp/twin-evidence/C-binary.txt
```

Before comparing hashes, confirm the two `--- ENV ---` blocks agree on rustc,
glibc, arch, and `pwd` (`/build`). **If `pwd` differs the comparison is void**
— that is 0090 amendment 2's condition, and a differing path alone is enough
to make two correct builds disagree.

- [ ] **Step 6: Record the verdict**

- Hashes equal → velaryon is byte-identical to lefford under a fixed
  environment. This is evidence toward 0063's "proven byte-identical" clause;
  it is **not** authorization to author (spec D6).
- Hashes differ → velaryon cannot author, 0063 is reinforced on fresh
  evidence, and for the first time the difference is **diagnosable**, because
  only one variable moved. Capture `cmp -l | wc -l` and localize before
  writing up.

- [ ] **Step 7: Clean up**

```bash
kubectl delete job twin-probe --ignore-not-found
ssh lefford 'rm -rf /tmp/twin-host /tmp/twin-flagcheck'
```
