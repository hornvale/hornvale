# The Long Age Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give lifespan an authoring channel — a per-kind dimensionless pace
factor that leaves lifespan *derived* — and make `cascade_regime_of`'s
`Settled` arm read it, without moving a single world.

**Architecture:** `LifeSchedule` becomes a seventh field on `BiosphereTraits`,
authored `Allometric` on all thirty rows. The four allometric time laws take it
and multiply by its factor exactly where they already multiply by
`pace_multiplier(class)`. Because every existing kind's factor is exactly
`1.0`, and multiplication by `1.0` is an IEEE-754 no-op, every derived value is
bit-identical and no committed artifact moves except the type-audit report.

**Tech Stack:** Rust 2024, no new dependencies (workspace allowlist is `serde`,
`serde_json`, `libm` only). `cargo nextest`, `make gate`.

## Global Constraints

Copied verbatim from the spec and the repo's standing rules. **Every task's
requirements implicitly include this section.**

- **No new dependencies.** The allowlist is `ALLOWED_EXTERNAL` in
  `cli/tests/architecture.rs`: `serde`, `serde_json`, `libm`.
- **No `HashMap`/`HashSet`** — `BTreeMap`/`BTreeSet`/`Vec` only. Enforced
  workspace-wide by `clippy.toml` `disallowed-types`.
- **No wall-clock time.** `std::time::Instant` is banned in **test code too**.
- **No new seeded draw, no new stream label, no epoch.** This campaign adds
  none. If you find yourself adding one, stop — the plan is wrong.
- **Every `pub` item, field and variant gets a one-line doc comment**
  (`#![warn(missing_docs)]`).
- **Every bare primitive at a `pub` boundary carries a `type-audit:` tag.**
  The exact form is `bare-ok(<class>: <field-or-return>)` — e.g.
  `bare-ok(ratio: factor)`. A malformed tag like `bare-ok(class: field)` is a
  recurring plan-text defect; write the real class name.
- **`cargo fmt` is the final step before every commit.** Fmt-gate skips are
  the single most common review finding on this project.
- **THE COMPILER IS THE ENUMERATION.** The file lists in this plan are
  orientation, **not the sweep.** For every signature and struct change, let
  `cargo build`/`-D warnings` finish the enumeration. **Never silence an
  exhaustiveness or missing-field error with a wildcard, a `..`, or a stub.**
  The Deep Realm's plan named 3 match sites, got 2 of them wrong, reading found
  5, and the compiler found 7.
- **Run tests once, capture, then grep the file** — never re-run a suite to
  find a second line:
  `cargo nextest run -p <crate> 2>&1 | tee /tmp/hv-<task>.txt`
- **Gate timing.** `make gate` is ~15 min on this Mac and has been measured at
  22–37 min in a worktree. Budget `timeout: 3600000`. Other sessions are live
  on this box — **stagger, never parallelise, gates.**
- **THE PRE-COMMIT HOOK IS WORKSPACE-WIDE.** *(Learned during Task 1; this
  plan's task decomposition did not anticipate it.)* `scripts/hooks/pre-commit`
  runs `make quick` — `cargo clippy --workspace --all-targets -D warnings` plus
  the type-audit **check and report-freshness** — on every Rust-relevant
  commit, regardless of what is staged. Consequences:
  - **No task can commit while the workspace is broken.** Task 1's signature
    change necessarily dragged in the call sites the plan assigned to Tasks 3
    and 4. That was handled correctly: they were given
    `LifeSchedule::ALLOMETRIC` as a semantically-null placeholder (an IEEE-754
    no-op) in commit `35b1f9de`, with **none** of Tasks 3/4's behaviour,
    tests, or mutations implemented.
  - **Tasks 3 and 4 must therefore REPLACE, not add.** Every
    `LifeSchedule::ALLOMETRIC` literal at a site that has a real row in scope
    becomes `bio.schedule` / `biosphere.schedule`. Find them all:
    `grep -rn "LifeSchedule::ALLOMETRIC" --include=*.rs windows/`. **A
    placeholder left behind is a silent bug** — the consumer would compile,
    pass, and ignore the authored schedule forever. That is exactly the
    rung-2 failure this campaign exists to avoid.
  - **The type-audit report is regenerated by the hook**, not deferred to
    Task 5. Do not treat its movement as unexpected drift.
- **Type-audit tags on an enum go on the ENUM's own doc comment**, using
  `Variant.field` naming — `bare-ok(ratio: Paced.factor)`, following
  `domains/astronomy/src/anchor.rs`'s `bare-ok(flag: Spinning.retrograde)`.
  Not on the variant's doc, not on the field's. *(Task 1's `check` refused the
  other placements; this plan's Task 1 code block had them wrong.)*

- [ ] **Step 3: Add `LifeSchedule` to `domains/species/src/lib.rs`**

```rust
/// How a kind's time-law quantities are scheduled against its mass (The Long
/// Age, spec §3). Mass and [`MetabolicClass`] are the other two inputs to the
/// same law; this is the third, and it is the only one that is a free
/// authoring choice rather than a physical measurement.
///
/// An enum rather than a bare `f64` so that a *staged* schedule — a
/// metamorphic kind whose larval phase runs on its own curve before merging
/// into the adult one — arrives later as a new variant rather than a new
/// axis, changing no consumer's signature.
#[derive(Clone, Copy, Debug, PartialEq)]
pub enum LifeSchedule {
    /// Pure allometry: every time-law quantity is a function of mass and
    /// metabolic class alone. Every kind in the roster today.
    Allometric,
    /// Allometry with an authored dimensionless pace factor: lifespan,
    /// maturity and reproductive tempo all stretch by `factor` at unchanged
    /// mass, and the basal metabolic rate does not move. Construct through
    /// [`LifeSchedule::paced`].
    /// type-audit: bare-ok(ratio: factor)
    Paced {
        /// The dimensionless stretch. `1.0` is [`LifeSchedule::Allometric`];
        /// above 1.0 is longer-lived and later-maturing, below 1.0 shorter.
        /// type-audit: bare-ok(ratio)
        factor: f64,
    },
}

impl LifeSchedule {
    /// The default every kind carries unless authored otherwise.
    pub const ALLOMETRIC: LifeSchedule = LifeSchedule::Allometric;

    /// A paced schedule, or `None` if `factor` is not finite and strictly
    /// positive. A zero or negative factor is not a fast-living creature; it
    /// is a creature with no lifespan, which the time laws cannot express.
    /// type-audit: bare-ok(ratio: factor)
    pub fn paced(factor: f64) -> Option<LifeSchedule> {
        if factor.is_finite() && factor > 0.0 {
            Some(LifeSchedule::Paced { factor })
        } else {
            None
        }
    }

    /// The multiplier this schedule contributes to the time laws — `1.0` for
    /// [`LifeSchedule::Allometric`], so the default path is an IEEE-754
    /// no-op and every pre-campaign value is preserved bit-for-bit.
    /// type-audit: bare-ok(ratio: return)
    pub fn factor(self) -> f64 {
        match self {
            LifeSchedule::Allometric => 1.0,
            LifeSchedule::Paced { factor } => factor,
        }
    }
}
```

Re-export it from the crate root alongside the allometry re-exports (see

```rust
fn cascade_regime_of(bio: &hornvale_species::BiosphereTraits) -> hornvale_language::CascadeRegime {
    // `life_history` is the honest source: it returns `None` for an
    // `Ametabolic` kind, which has no mass-derived lifespan at all. The bare
    // `lifespan` call this used to make returned a number for a construct
    // (xorn: 64.97 yr) that the model says does not exist.
    let long_lived = hornvale_species::life_history(bio.mass, bio.metabolic_class, bio.schedule)
        .lifespan
        .is_some_and(|l| l.get() >= LIFESPAN_THRESHOLD_YEARS);
    match bio.social_form {
        // Many speakers, but turnover falls with lifespan: a settled people
        // that lives past the threshold accrues far fewer transmission events
        // per century, so its tongue drifts slower without freezing (0066).
        hornvale_species::SocialForm::Settled => {
            if long_lived {
                hornvale_language::CascadeRegime::new(1, 2)
            } else {
                hornvale_language::CascadeRegime::SETTLED
            }
        }
        hornvale_species::SocialForm::Gregarious => hornvale_language::CascadeRegime::new(1, 2),
        hornvale_species::SocialForm::Solitary => {
            if long_lived {
                hornvale_language::CascadeRegime::new(0, 1)
            } else {
                hornvale_language::CascadeRegime::SETTLED
            }
        }
        hornvale_species::SocialForm::Sessile => hornvale_language::CascadeRegime::SETTLED,
    }
}
```
