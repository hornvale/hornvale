# The Weft Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the walk band density and legibility — a reader for placed
features that already exist but are never shown, and a derived feature surface
computed per facet from macro state modulated by position-continuous noise.

**Architecture:** Two halves sharing one delivery path. Half A adds the ruin
signature to `Brief` and renders it. Half B adds per-kind prevalence fields
(`blend_at` over a materialized field pack × `Fbm`), an occurrence draw, a
caller-owned residency window backed by `Derived<K, V>`, and four feature kinds
— one of which is a deliberate negative control.

**Tech Stack:** Rust 2024, workspace crates only (`serde`, `serde_json`, `libm`
— no new dependencies). `cargo nextest`. No `HashMap`/`HashSet`.

**Spec:** [`docs/superpowers/specs/2026-09-03-the-weft-design.md`](../specs/2026-09-03-the-weft-design.md)

**Worktree:** `.claude/worktrees/the-weft`, branch `campaign/the-weft`.
**Decision block:** 0686–0695 (mint inside this range only).

**Status (2026-09-04):** COMPLETE through Task 13. The canonical census is
accepted and Nathan approved G6; the remaining action is the authorized merge

## Global Constraints

Every task's requirements implicitly include all of these.

- **Anchor every command.** The shell cwd resets between calls in this
  environment. Use `git -C <abs-path>` and absolute paths; a compound
  `cd X && …` anchors one call only. Before any commit, assert the branch:
  `git -C "$WT" branch --show-current | grep -qx campaign/the-weft || exit 1`.
- **`lexicon_guard`** — in this repo `cell` means a mesh **vertex**. Use
  `Vertex` for the point and `Facet` for the patch. A new file has no inventory
  row and may carry **no** `cell`-bearing token; `Cell` (the std type) counts,
  and `cargo fmt` can wrap a same-line `// lexicon:` waiver out of view — re-run
  the guard *after* fmt. It is **not** in `gate-commit`; run it explicitly:
  `cargo nextest run -p hornvale --test suite -E 'test(lexicon_guard)'`.
- **`plumb:` tags** on every authored numeric constant (default-deny). Every
  per-kind scalar in this plan is an authored constant.
- **`type-audit:` tags** on every new `pub`-boundary primitive, and
  `make type-audit-report` regenerated **in the same commit**.
- **A new stream label** must be declared in the crate's `streams` module AND
  the golden `the_stamp_is_exactly_this_roster` (`cli/src/streams.rs`) updated.
  The roster is derived from `label_sources()`; the golden is not.
- **No `TypeId`-keyed component storage.** Its ordering is not build-stable and
  would put an unstable iteration order under a byte-identity guarantee. Use
  `ComponentStore<K, C>` (one typed store per shape).
- **No hidden cache inside a derivation.** Caller-owned, `&mut`-threaded, no
  `RefCell`/global/`OnceLock`. Every cached path needs a test pinning
  cache-present **byte-identical** to cache-absent.
- **`world.json` must not move.** Derived features are never committed facts.
  If `cli/tests/fixtures/world-seed-42.json` drifts, **STOP** — that byte-golden
  is written only by `make rebaseline-goldens`, never by `make rebaseline`.
- **Gate before every commit:** `make gate-commit`. Commit the `docs/timings.md`
  row it writes.
- **An `#[ignore]` reason** must carry a `claim:` shape (decision 0093) and, if
  untokenised, appear in `cli/tests/suite/heavy_tier.rs`'s frozen roster.

## Scope note — one hypothesis is deferred, deliberately

The spec preregisters **H4** ("every rumor names a region, and the region is
never empty"). **This plan does not build a rumor producer**, so H4 would be
vacuous — a hypothesis nothing can test. Rumors are listed in spec §5.5 as an
*existing seam* (`knowledge.rs`'s heard entries), not as a deliverable, and
building a producer would be a third half.

**Decision:** H4 and rumor generation are deferred together. Task 10 records the
deferral and files a registry row. Do **not** write a test that "passes" by
having no rumors — that is the vacuous-guard shape this repo has shipped five
times.

use crate::brief::RuinSignature;

/// The walk-band line for a ruin. Never empty — a causeless ruin still reads
/// as a ruin, because absence of a recorded cause is not absence of a ruin.
#[must_use]
pub fn ruin_line(sig: &RuinSignature) -> String {
    let ending = match (&sig.cause, sig.by_hand) {

## Task 4: the field pack

**Files:** Create `windows/worldgen/src/fieldpack.rs`; modify `windows/worldgen/src/lib.rs`

**Interfaces:**
- Consumes: `GeneratedTerrain::{drainage_at, crust_age_at, boundary_distance_at, material_at}`
  (per-vertex accessors returning `f64`, `f64`, `Option<u32>`, `MaterialBuffer`).
  `MaterialBuffer` is five `[0,1]` scalars: `silica`, `grain`, `induration`,
  `carbonate`, `metamorphic_grade`.
- Produces: `pub struct FieldPack { pub carbonate: VertexMap<f64>, pub induration: VertexMap<f64>, pub drainage: VertexMap<f64> }`
  and `pub fn field_pack_from(terrain: &GeneratedTerrain) -> FieldPack`.

**Why this exists:** `blend_at` takes a `&VertexMap<f64>`, but macro state is
exposed only as per-vertex accessors. Each scalar must be materialized once per
world. `predator_pressure_from(wc, terrain, report) -> VertexMap<f64>` is the
existing precedent for the shape.

**Read continuous causes, never categorical labels.** `Biome` is an `enum` and
cannot be bilinearly blended — that is *why* the biome monotony defect exists.
Never put a biome in a field pack.

- [ ] **Step 1: Write the failing test** (`windows/worldgen/tests/suite/weft_fieldpack.rs`):

## Task 5: prevalence and occurrence, for one kind

**Files:** Create `windows/worldgen/src/weft/mod.rs`, `windows/worldgen/src/weft/kinds.rs`;
modify `windows/worldgen/src/streams.rs`, `cli/src/streams.rs`

**Interfaces:**
- Produces:
  `pub fn prevalence(kind: WeftKind, facet: &Facet, ctx: &LocaleContext, pack: &FieldPack) -> Option<f64>`
  and `pub fn occurs(kind: WeftKind, facet: &Facet, seed: Seed, p: f64) -> bool`.

**The mechanism (spec §5.1):** prevalence = macro state (`blend_at` over the
field pack) modulated by position-continuous `Fbm`; occurrence = a second,
decorrelated position-continuous sample against `p`.

**Noise is keyed on POSITION, never on facet address.** The Ford states the
falsification directly: address-hashed noise "leaked into a band edge". Sample
`Fbm` at the facet's *centre position*, not at its packed id.

**Nothing normalises across kinds.** Per-kind prevalences do not sum to 1; a
simplex constraint is exactly the structural cap on enterable density the spec
forbids.

## Task 9: the preregistered readout

**Files:** `windows/lab/src/metrics.rs`, `windows/lab/tests/suite/weft_density.rs`

Register and measure, per spec §7:

- **H1 — density, TWO numbers.** *existence density* (fraction of land facets
  carrying any derived feature, god's-eye) and *encounter rate* (features met per
  unit travel on a seeded walk). H3 measured only the first; observation-scoped
  discovery makes them different questions. Report both separately.
- **H2 — coherence.** A standard spatial-autocorrelation statistic (Moran's I or
  Ripley's K), **paired with an anti-vacuity companion** in The Ford's shape, so
  a degenerate world cannot score perfectly.
- **H3 — legibility, and it may fail.** Mutual information between local macro
  state and the feature set, per kind. **The preregistered prediction is the
  ORDERING:** `spring > thicket > overhang > erratic`, with the erratic near
  zero. If the erratic does not score near zero, the instrument is measuring
  something other than legibility and *that* is the finding.
