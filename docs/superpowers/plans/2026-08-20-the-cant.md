# The Cant Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Derive a relational, 0021-clean **snap-judgment predisposition**
`v(A→B)` between the 15 modeled peoples — a pure function of their authored
attribute vectors, projected onto warmth × competence → an emotion — and measure
whether it is *believable* (asymmetric, non-degenerate, likes as well as loathes,
distinct per-people personalities). Layer 1 of the evaluative-beliefs program.

**Architecture:** A new window `windows/sentiment` (crate `hornvale-sentiment`)
holds a pure species-catalog derivation: per-axis normalized distances between two
peoples, weighted by the judging people's own psychology, projected onto a
warmth×competence plane and classified to an emotion (contempt/envy/pity/
admiration). No world is built (every axis reads authored model cards), so no
worldgen, no heavy tier. A fast believability readout reports the 15×15 landscape
and asserts loose structural tripwires; a human reads believability off the report.

**Tech Stack:** Rust 2024, `cargo nextest`; `hornvale_species` (model cards /
attribute vectors), `hornvale_demography` (`guild_overlap`, predation) and
`hornvale_language` (authored articulation vectors) as needed; `hornvale_kernel`.

**Spec:** `docs/superpowers/specs/2026-08-20-the-cant-design.md` (read §3, §5, §7
before starting; §5 is the axis set, §7 the believability criteria).

## Global Constraints

- **0021 is load-bearing:** every axis is a real attribute *distance*; the only
  thing that ranks is a people's own derived weight-vector applied to itself as
  judge. No constant encodes a preference between two named peoples. Assert only
  *structural* properties; *report* specific pairs — never assert "human dislikes
  drow" (that authors the expectation).
- **Determinism:** no `HashMap`/`HashSet` (`BTreeMap`/`BTreeSet`/`Vec`); no
  wall-clock; float compares via `to_bits()`/`total_cmp`, never `==`.
- **Dependencies:** `serde`, `serde_json`, `libm` only (the `ALLOWED_EXTERNAL`
  allowlist in `cli/tests/architecture.rs`). No new external crates.
- **Layering:** `hornvale-sentiment` is a **window** — it may depend on kernel and
  domains, never on `cli` or another window. The rank/allowlist checks in
  `cli/tests/architecture.rs` (and its generated book page) must be updated to
  include the new crate in the same commit that adds it.
- **Docs:** every `pub` item/field/variant gets a `///`. **Type audit:** every
  primitive at a `pub` boundary carries a `type-audit:` tag; run `type-audit check`.
- **No world, no heavy tier:** the derivation reads only the species catalog; the
  readout is a fast test (no `#[ignore]`, no worldgen).
- **fmt last:** `cargo fmt` before every commit.
- **No epoch:** no kernel `Value`/`Claim` change, no committed predicate, no
  save-format change. This campaign only *reads* authored facts.

### Task 1: Scaffold `windows/sentiment` + the per-axis distance functions

**Files:**
- Create: `windows/sentiment/Cargo.toml`, `windows/sentiment/src/lib.rs`,
  `windows/sentiment/src/axes.rs`.
- Modify: root `Cargo.toml` (`members`), `cli/tests/architecture.rs` (rank +
  allowlist for `hornvale-sentiment`), and regenerate its book layering page if
  the test emits one (`make rebaseline` for that page).
- Test: `windows/sentiment/tests/suite.rs` + `tests/suite/axes.rs` (per-axis unit
  tests) and `tests/suite/axis_spread_probe.rs` (the early degeneracy probe).

**Interfaces:**
- Consumes: `hornvale_species` attribute types/predicates (verify exact names at
  the start — the survey cites `HabitatRealm`, `ResourceVector`, `ConditionNiche`,
  `SocietyVector`, `PerceptionVector`, `reproductive_tempo`, `SPECIES_MASS_KG`,
  `IN_GROUP_RADIUS`, articulation vectors), `hornvale_demography::niche::guild_overlap`,
  and the species-catalog enumeration (find how to list all 15 peoples — the Cupel
  used `components.biosphere.get_by_label`; here find the catalog/registry that
  enumerates species without a world).
- Produces:
  ```rust
  /// One people, as this crate identifies it (the species catalog's key).
  pub type PeopleId = /* the species KindId/label type — verify */;

  /// The eight world-invariant snap-judgment axes (spec §5).
  #[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
  pub enum Axis { Habitat, DietPredation, ConditionNiche, Sociality, ActivityCycle, Reproductive, Language, SizeThreat }

  impl Axis {
      pub const ALL: [Axis; 8];
      pub fn label(self) -> &'static str;
      /// Whether the axis is directional (predation, size) or mutual.
      pub fn is_asymmetric(self) -> bool;
  }

  /// The normalized distance A→B on one axis, in [0,1]. Symmetric axes satisfy
  /// distance(x,a,b) == distance(x,b,a); asymmetric ones need not.
  pub fn axis_distance(axis: Axis, a: &PeopleTraits, b: &PeopleTraits) -> f64;
  ```
  (`PeopleTraits` = the crate's bundle of one people's read-out attribute vectors;
  define it to hold exactly what the axes need, read once from the catalog.)

- [ ] **Step 1: Scaffold the crate and make it build empty.** Create the Cargo.toml
  (deps: kernel, species, demography, language — serde/libm only externally),
  add to root `members`, add `hornvale-sentiment` to `cli/tests/architecture.rs`'s
  rank table and allowlist. Run `cargo build -p hornvale-sentiment` and
  `cargo test -p hornvale --test suite -- architecture` → both green (the layering
  test accepts the new window). Regenerate the layering book page if that test
  emits one (`make rebaseline`; commit the page).

- [ ] **Step 2: Write failing per-axis unit tests (one per axis).** For each of
  the 8 axes, a test on two hand-built or two real `PeopleTraits` asserting the
  PROPERTY the axis must have — normalized to `[0,1]`, and *symmetric* axes
  return the same value both directions while *asymmetric* axes (DietPredation,
  SizeThreat) can differ. Do NOT hard-code an expected magnitude for a specific
  real pair (that authors an outcome); assert the structural property
  (range, symmetry/asymmetry, and monotonicity — a bigger underlying attribute
  gap gives a bigger distance). Run → FAIL (functions absent).

- [ ] **Step 3: Implement the axis distances.** In `axes.rs`, read each people's
  needed fields into `PeopleTraits`, then implement `axis_distance` per the spec
  §5 table: categorical axes (Habitat) → 0/1 or a small ordinal distance; scalar
  axes (SizeThreat from `SPECIES_MASS_KG`) → a normalized log-ratio distance;
  vector axes (ConditionNiche, Sociality, ActivityCycle, ResourceVector for
  DietPredation, articulation for Language) → a normalized vector distance
  (cosine or scaled Euclidean — pick and document). DietPredation folds in
  `guild_overlap` and the predator/prey direction (asymmetric). Every axis
  normalized to `[0,1]`. Run the Step-2 tests → PASS.

- [ ] **Step 4: The early degeneracy probe (Cupel discipline).** Write
  `axis_spread_probe.rs`: enumerate the 15 peoples, and for each axis print the
  distribution of its pairwise distances across all 15×15 ordered pairs (min,
  max, mean, sd, and how many distinct values). Assert only anti-degeneracy: at
  least *most* axes have sd > 0 (they vary). Run it and READ the output — if an
  axis is degenerate (every people identical), that is a finding to record in the
  task report (it contributes nothing and the readout will show a bare region);
  do not silently drop it.

- [ ] **Step 5: fmt, clippy, type-audit, commit.**
  `cargo fmt`; `cargo clippy -p hornvale-sentiment --all-targets -- -D warnings`;
  `type-audit check`. Commit the crate, the root/architecture changes, the layering
  page, and the tests.

### Task 2: The weight-vector, the warmth×competence projection, and `snap_judgment`

**Files:**
- Create: `windows/sentiment/src/weights.rs`, `windows/sentiment/src/judgment.rs`.
- Modify: `windows/sentiment/src/lib.rs` (re-exports).
- Test: `windows/sentiment/tests/suite/judgment.rs`.

**Interfaces:**
- Consumes: Task 1's `Axis`, `axis_distance`, `PeopleTraits`.
- Produces:
  ```rust
  /// A people's derived per-axis weights — its "prejudice personality." A pure
  /// function of the JUDGER's own psychology (in_group_radius as a global
  /// multiplier; threat_response weighting SizeThreat/DietPredation;
  /// status_basis/sociality weighting Sociality). Weights are non-negative.
  pub fn weight_vector(judger: &PeopleTraits) -> [f64; 8];   // indexed by Axis::ALL order

  /// The 2-D valuation and the emotion it classifies to.
  #[derive(Clone, Copy, Debug, PartialEq)]
  pub struct Judgment { pub warmth: f64, pub competence: f64, pub emotion: Emotion }

  #[derive(Clone, Copy, Debug, PartialEq, Eq, PartialOrd, Ord)]
  pub enum Emotion { Admiration, Envy, Pity, Contempt }   // the four warmth×competence quadrants

  /// v(judger → target): weighted axis distances projected onto warmth×competence
  /// per each axis's signature (spec §3 table), then classified. Relational and
  /// asymmetric by construction.
  pub fn snap_judgment(judger: &PeopleTraits, target: &PeopleTraits) -> Judgment;
  ```

- [ ] **Step 1: Failing tests for the weight-vector's PROPERTIES.** Assert: an
  insular judger (max `in_group_radius`) has element-wise ≥ weights than a
  cosmopolitan one (min `in_group_radius`) — insularity is a global up-weight; a
  high-`threat_response` judger weights `SizeThreat`/`DietPredation` above a
  low one. Property-level, not magnitudes. Run → FAIL.

- [ ] **Step 2: Implement `weight_vector`.** Derive the 8 weights from the
  judger's psychology fields (verify exact APIs). Document the weight law in the
  module doc. Run Step-1 tests → PASS.

- [ ] **Step 3: Failing tests for `snap_judgment`'s PROPERTIES.** Assert: (a)
  **relational asymmetry** — construct/choose a pair differing on an asymmetric
  axis and show `snap_judgment(a,b) != snap_judgment(b,a)`; (b) **symmetric
  floor** — a judger evaluating an identical-traits people yields max warmth /
  the Admiration-or-neutral region (self-similar = liking, not contempt); (c) the
  emotion classification matches the quadrant of (warmth, competence). Do NOT
  assert a specific real pair's emotion. Run → FAIL.

- [ ] **Step 4: Implement the projection + classification.** `snap_judgment` =
  for each axis, `weight × axis_distance` projected onto warmth and/or competence
  by that axis's signed signature (spec §3 table: e.g. Habitat → −warmth;
  Sociality → −competence; SizeThreat → −warmth,+competence; DietPredation →
  −warmth,+threat-competence), summed; classify the (warmth, competence) point to
  an `Emotion` quadrant. Document each axis's signature in the module doc. Run
  Step-3 tests → PASS.

- [ ] **Step 5: fmt, clippy, type-audit, commit** (as Task 1 Step 5).

### Task 3: The believability readout

**Files:**
- Test: `windows/sentiment/tests/believability.rs` (a fast, non-ignored readout).

**Interfaces:**
- Consumes: Task 2's `snap_judgment`, `weight_vector`, `Emotion`; the species
  catalog enumeration (Task 1).

- [ ] **Step 1: Build the 15×15 landscape and print the report.** Enumerate the
  15 peoples; compute `snap_judgment(A,B)` for every ordered pair; print: the full
  15×15 emotion matrix; the strongest pair in each of the four emotions; each
  people's weight-vector; and the **axis-space coverage map** (for each axis and
  each emotion quadrant, how populated it is — which corners are bare, the
  spec §7 deliverable that feeds a principled roster expansion). Run it and read
  the report.

- [ ] **Step 2: Assert only loose STRUCTURAL tripwires (spec §7), never a specific
  pair.** Add assertions, each documented as "structural tripwire, not the
  hypothesis": (a) **non-degenerate** — more than one distinct `Emotion` appears
  across the matrix (not all one emotion); (b) **it likes** — at least one pair is
  `Admiration` (the system is not a pure hate-generator); (c) **asymmetry exists**
  — at least one pair with `snap_judgment(a,b) != snap_judgment(b,a)`; (d)
  **similarity → warmth** — the correlation across pairs between total axis
  distance and warmth is negative (report the coefficient; assert only its sign);
  (e) **distinct personalities** — not all peoples' weight-vectors are equal.
  These are sanity floors; the believability judgment is READ from the Step-1
  report by a human, not asserted. Run → PASS.

- [ ] **Step 3: Capture the report to scratch** for the chronicle, fmt/clippy,
  commit.
