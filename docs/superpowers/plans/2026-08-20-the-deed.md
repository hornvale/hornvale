# The Deed — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Unify the player's verbs and the creature action suite into one
`Action` type where in-character/out-of-character is a property of the
action, gated by a body-state table, with in-character player acts charging
time and posting facts.

**Architecture:** Eight tasks, ordered so each is independently reviewable.
The language-side change lands first because everything downstream depends on
a concept being registrable without acquiring a word. The suite then grows in
three passes — classification, gate, routing — with the two behaviour-visible
passes (the `!` rename, the time-charging) last, so expected artifact drift
arrives in identifiable commits rather than smeared across the arc.

**Tech Stack:** Rust 2024, `cargo nextest`, no new dependencies (decision
0004 — `serde`, `serde_json`, `libm` only).

**Spec:** `docs/superpowers/specs/2026-08-20-the-deed-design.md`

## Global Constraints

- **No new crates.** The allowlist is `ALLOWED_EXTERNAL` in
  `cli/tests/architecture.rs`.
- **No `HashMap`/`HashSet`** — `BTreeMap`/`BTreeSet`/`Vec` only, enforced by
  `clippy.toml` `disallowed-types`.
- **No wall-clock time.** Time is `WorldTime { day: f64 }`.
- Every crate sets `#![warn(missing_docs)]`; every public item, field and
  variant needs a one-line doc comment.
- **`cargo fmt` is the final step before every commit.**
- Every commit must pass `make gate-commit`.
- **Integration tests are consolidated into ONE binary per crate**, under
  `tests/suite/<name>.rs`, declared in `tests/suite.rs` as
  `#[path = "suite/<name>.rs"] mod <name>;`. **Never add a new top-level file
  under `tests/`.** Select with `--test suite -- <name>`.
- **Renaming a `#[test]` function is a commit-gate change.**
  `docs/timings/subfloor-roster.tsv` selects by EXACT name under an
  exclude-unknown rule, so a stale id silently drops tests while the gate goes
  green FASTER. If you rename a test, rewrite that file in the same commit and
  prove it with `bash scripts/subfloor-roster.sh | tr "|" "\n" | grep -c
  <name>`, never by watching the gate pass.
- **`docs/audits/type-audit-report.md` is an AGGREGATE** — counts by class and
  crate, zero per-symbol rows. For a pure rename or intra-crate move it must
  NOT move; movement means a `type-audit:` tag was dropped or duplicated. For
  a task adding `pub` primitives it moves by exactly that count.
- **Never run the workspace suite twice to ask it two questions.** Capture
  once to a file, then grep the file.

### Task 1: `GapReason::Extradiegetic` and the draw filter

A concept naming an out-of-character act has **no referent in the world at
all**, so no tongue can ever have a word for it. The three existing
`GapReason` variants all describe gaps that could in principle close; this one
cannot.

The variant is not merely a rendering label. `lexicon::proto_root_universe`
filters `GapReason::Unnameable` out of the universe **before**
`assign_proto_roots` runs, which is what stops the nine spectral classes
(accession epoch 6) from drawing roots nobody speaks. Without the same
treatment, every out-of-character concept would draw a proto-root and every
culture would end up with a word for `!why`.

**Files:**
- Modify: `domains/language/src/lexicon.rs` (the `GapReason` enum, its
  `Display` impl, and `proto_root_universe`'s filter)
- Modify: `windows/worldgen/tests/suite/exposure.rs` (exhaustive matches at
  ~1151 and ~1212, plus pattern sites near 67/75/1314/1329)
- Test: the in-module test block in `domains/language/src/lexicon.rs` that
  already holds `proto_root_universe_excludes_unnameable_concepts`

**Interfaces:**
- Consumes: nothing.
- Produces: `hornvale_language::GapReason::Extradiegetic(String)`, excluded
  from `proto_root_universe` exactly as `Unnameable` is. Task 2 classifies
  out-of-character concepts with it.

### Task 2: The concept roster for the suite

The spec deliberately refuses to carry a concept count, because
`Action::concept_name` already folds `MoveTo` and `MoveWithin` onto one
`move` — *"a language has a word for going, not two words separated by how
far."* This task derives the roster against the live registry rather than
from a list written in advance.

**The folding rule, which is the deliverable:** concepts name **what the act
is**, never which verb typed it. By that rule `go`/`back`/`enter`/`out`/
`dive`/`surface`/`delve`/`climb` are all *going* and reuse the existing
`move`; they mint nothing.

**Files:**
- Modify: `domains/language/src/accession.rs` (append ONE new cohort)
- Modify: whichever domain registers the act concepts — find it, do not guess
  (Step 1)
- Modify: `windows/worldgen/src/lib.rs` (the exposure derivation, to classify
  new out-of-character concepts as `Extradiegetic`)
- Test: `cli/tests/suite/accession.rs` (existing; must go red then green)

**Interfaces:**
- Consumes: `GapReason::Extradiegetic` from Task 1.
- Produces: registered concepts for every act the suite will carry, each with
  an accession entry. Tasks 5-7 attach `Action` variants to them.

- [ ] **Step 1: Read these findings — the controller already ran this down**

Settled empirically by dumping the live registry, not by grep:

- `move`, `drink`, `eat`, `rest` are registered by the **language** domain
  with concept class `act`, from the `PackEntry` roster in
  `domains/language/src/packs.rs` (`PackEntry { concept, kind, doc,
  ladder_rank }`).
- **`sleep` ALREADY EXISTS** as a registered concept — `packs.rs`,
  `ConceptKind::Act`, *"to rest unconscious"* — distinct from `rest`
  (*"to stop and recover strength"*). Mint neither.

**THE TRAP, and it would have been silent.** `packs.rs` is a Swadesh-style
CORE-VOCABULARY roster, and `windows/worldgen/src/lib.rs:5796` maps pack
membership straight to `ExposureClass::Steeped`. A `Steeped` concept is never
`Unknown`, so **Task 1's `Extradiegetic` filter would never be consulted** and
every out-of-character concept would draw a proto-root anyway. Registering an
operator instrument as core daily vocabulary is also just false.

**So out-of-character concepts must NOT be added to `packs.rs`.** The
precedent for a concept that is registered but never lexicalised is
astronomy's nine spectral classes: registered with `lexeme:
Correspondent::Absent(Void::Unnamed(...))` (`domains/astronomy/src/lib.rs`
~458 — the only concepts in the workspace using `Void::Unnamed`), and
classified in the exposure derivation rather than the pack roster. Follow
that shape.

Record in your report which `Void` variant you chose and why: `Unnamed` means
*real and objective, nobody has named it*, which is true of a star's class and
FALSE of `!why`. If no existing variant fits, say so rather than forcing one
— that is a finding, not a blocker.

```rust
/// Whether an act is subject to the body's state or bypasses it. A property
/// of the ACTION, not of the invocation: `examine` and `!examine` are
/// different acts, so a verb never carries both moods (spec §2.1).
/// type-audit: bare-ok(return)
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum Mood {
    /// Subject to the body's state; charges time; may post facts.
    InCharacter,
    /// Bypasses the body's state, never the world's rules. May still commit,
    /// stamped with operator provenance (spec §2.2).
    OutOfCharacter,
}

impl Action {
    /// This act's mood. Exhaustive by variant with NO wildcard arm, so a new
    /// action fails to compile until it is classified — the same discipline
    /// as `action_variants_must_all_be_rostered`.
    pub fn mood(&self) -> Mood {
        match self {
            Action::MoveTo(_) | Action::MoveWithin(_) => Mood::InCharacter,
            Action::Drink | Action::Rest | Action::Eat => Mood::InCharacter,
        }
    }
}
```

```rust
#[test]
fn a_players_facts_survive_into_the_saved_world() {
    let mut s = test_session();
    s.handle("go n");
    let in_session = s.committed_agent_at_count();

    let played = s.into_played_world(test_seed());

        saved, in_session,

}
```

Note the precondition assertion: without it, a session that committed
nothing would compare `0 == 0` and pass while proving nothing.
