# The Ford — Implementation Plan (Stage 1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give Hornvale a river that is narrower than a cell — an edge-carried
polyline network with discharge-derived angular width, and a signed transverse
distance banded into channel / bank / floodplain / terrace — evaluable at any
point, with no consumer moved yet.

**Architecture:** Spherical geometry (signed distance to a polyline) lands in
the kernel beside the geosphere and room mesh. Hydrology (which polylines,
how wide, which band) lands in `domains/terrain`. Nothing outside the terrain
domain changes in this stage: `windows/locale`, the scene schemas, and every
client are untouched, so there is **no epoch event in this plan**.

**Tech Stack:** Rust 2024, `serde`/`serde_json`/`libm` only (decision 0004 as
amended by 0041). `cargo nextest` for tests. No new crates.

## Why this plan stops at stage 1

Spec §9 lists five stages. This plan implements **stage 1 alone**, and the
boundary is a measurement boundary rather than a size one:

- Stage 1 ends by measuring H1, H2 and H4 (spec §10). Those readouts decide
  whether the width law is calibrated.
- Stage 2 is an **epoch event** (`locale/room/v2` → `v3`). Campaign branches
  must not absorb main mid-measurement, and an epoch landing between a
  study's baseline and its readout breaks exactly that rule (spec §11.4).
- Stage 3 conditions **vegetation** on the bands. Doing that before H1/H3 are
  read would bake an uncalibrated band into biome output.

So: land stage 1, read the numbers, then plan stage 2 against what the numbers
actually said. If H1 falls outside `[0.005%, 0.5%]`, that is a finding to
report, not a constant to retune quietly (spec §10).

- **No `HashMap`/`HashSet`** — `BTreeMap`/`BTreeSet`/`Vec` only. Enforced

- **Run `cargo fmt` as the final step before every commit.**
- Iterate cost-ordered: `fmt` + `clippy` first, then `cargo test -p <crate>`.

```rust
//! Signed distance from a point to a polyline on the unit sphere, and the
//! banding of that scalar into ordinal zones. Pure geometry: this module
//! knows nothing about what the polyline represents — a river, a coastline,
//! a scarp and a treeline all band the same way.

use crate::math;

/// A polyline on the unit sphere: an ordered run of unit vectors joined by
/// great-circle segments.
/// type-audit: bare-ok(position: points)
#[derive(Clone, Debug, PartialEq)]
pub struct SphericalPolyline {
    /// The vertices, in travel order. Each must be a unit vector.
    pub points: Vec<[f64; 3]>,
}

/// Dot product of two 3-vectors.
/// type-audit: bare-ok(ratio: return)
fn dot(a: [f64; 3], b: [f64; 3]) -> f64 {
    a[0] * b[0] + a[1] * b[1] + a[2] * b[2]
}

/// Cross product of two 3-vectors.
/// type-audit: bare-ok(position: return)
fn cross(a: [f64; 3], b: [f64; 3]) -> [f64; 3] {
    [
        a[1] * b[2] - a[2] * b[1],
        a[2] * b[0] - a[0] * b[2],
        a[0] * b[1] - a[1] * b[0],
    ]
}

/// Normalize a 3-vector; returns the input unchanged if its norm is zero.
/// type-audit: bare-ok(position: return)
fn normalize(v: [f64; 3]) -> [f64; 3] {
    let n = (v[0] * v[0] + v[1] * v[1] + v[2] * v[2]).sqrt();
    if n == 0.0 { v } else { [v[0] / n, v[1] / n, v[2] / n] }
}

impl SphericalPolyline {
    /// Signed great-circle distance from `p` to the nearest point of the
    /// polyline, in radians.
    ///
    /// The sign is **left-positive** relative to travel direction: a point to
    /// the left of the nearest segment's direction of travel reads positive,
    /// to the right negative. Carrying the sign is what makes a *crossing*
    /// expressible — a ford is a path on which the sign flips — and what
    /// distinguishes the cut-bank from the point-bar of a meander.
    ///
    /// Returns `f64::INFINITY` for an empty polyline.
    /// type-audit: bare-ok(angle: return), bare-ok(position: p)
    pub fn signed_distance(&self, p: [f64; 3]) -> f64 {
        if self.points.is_empty() {
            return f64::INFINITY;
        }
        if self.points.len() == 1 {
            return math::acos(dot(p, self.points[0]).clamp(-1.0, 1.0));
        }
        let mut best = f64::INFINITY;
        let mut best_sign = 1.0f64;
        for w in self.points.windows(2) {
            let (a, b) = (w[0], w[1]);
            let n = cross(a, b);
            let nn = (n[0] * n[0] + n[1] * n[1] + n[2] * n[2]).sqrt();
            // Degenerate segment (coincident endpoints): fall back to the vertex.
            let (d, side) = if nn == 0.0 {
                (math::acos(dot(p, a).clamp(-1.0, 1.0)), 1.0)
            } else {
                let nu = normalize(n);
                // Foot of the perpendicular, projected onto the segment's plane.
                let foot = normalize([
                    p[0] - nu[0] * dot(p, nu),
                    p[1] - nu[1] * dot(p, nu),
                    p[2] - nu[2] * dot(p, nu),
                ]);
                // Inside the arc iff the foot lies between a and b.
                let inside = dot(cross(a, foot), nu) >= 0.0 && dot(cross(foot, b), nu) >= 0.0;
                let d = if inside {
                    math::acos(dot(p, foot).clamp(-1.0, 1.0))
                } else {
                    let da = math::acos(dot(p, a).clamp(-1.0, 1.0));
                    let db = math::acos(dot(p, b).clamp(-1.0, 1.0));
                    if da <= db { da } else { db }
                };
                // Left of travel is the +normal hemisphere.
                let side = if dot(p, nu) >= 0.0 { 1.0 } else { -1.0 };
                (d, side)
            };
            // Deterministic tie-break: strict `<` keeps the FIRST segment on
            // an exact tie, so the result never depends on iteration accident.
            if d < best {
                best = d;
                best_sign = side;
            }
        }
        best * best_sign
    }
}

/// Index of the band `|d|` falls in, given strictly ascending `edges`.
/// Returns `edges.len()` for anything beyond the last edge.
/// type-audit: bare-ok(angle: d), bare-ok(index: return)
pub fn band(d: f64, edges: &[f64]) -> usize {
    let a = d.abs();
    edges.iter().position(|e| a < *e).unwrap_or(edges.len())
}
```

- [ ] **Step 3: Implement the enum and the laws**

`Transverse` mirrors `WaterKind` in `water.rs` — read that file first and copy
its shape (explicit-`match` `index()`, `LEGEND`, `name()`), because a scene
legend will index into it in a later stage.

The width law is downstream hydraulic geometry, `w = a·Q^b` with `b ≈ 0.5`.
Express `a` as a fraction of the cell edge so the whole thing stays angular
(spec §5.3). Below `water::RIVER_MIN_DRAINAGE`, width is exactly `0.0`.

The band edges, outward from the centreline, are
`[w/2, w/2 + k·w, V/2]` where `V = g(Q, slope)` — the confinement law. A
steeper local gradient means a narrower valley: a gorge has no floodplain.
Take slope from the elevation difference to the downhill target over the
angular cell spacing.

- [ ] **Step 4: Build the network**

`ChannelNetwork::build(globe, geosphere, seed)` walks every cell whose
`water_kind` is `River`, follows `downhill` to the sea or a terminal sink, and
emits one `SphericalPolyline` per maximal run. Iterate cells in `CellId` order
and use `BTreeSet` for the visited set — never a `HashSet`.

- [ ] **Step 6: Prove the meander is position-continuous, not address-hashed**

This is the trap named in spec §5.2, and it needs a **positive control** — a

```rust
#[test]
fn meander_displacement_is_continuous_in_position() {
    let net = test_network();
    let a = net.meander_at(unit(1.0, 0.0, 0.0));
    let b = net.meander_at(unit(1.0, 1e-6, 0.0));

    assert!((a - far).abs() > 0.0, "field is constant, not noise");
}
```
