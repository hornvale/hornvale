# The Sett — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At the walk rung, draw the compass rose instead of a Mercator
projection, so that the box to the left of the mark IS where the left arrow
takes you — at every facet on every face.

**Architecture:** A new `clients/game/bin/src/rose.rs` builds a
`RoseRaster` — box `(col, row)` is the facet reached by walking the
observer's own `hornvale_locale::heading_rose` chains outward — together
with its inverse, `FacetId -> (col, row)`. The terrain layer addresses
through the raster instead of `mercator::unproject`; every overlay places
through a `Placement` seam that is Mercator for the map and the raster for
the walk view. `heading_rose` and everything sim-side is untouched.

**Tech Stack:** Rust 2024, no new dependencies. `clients/` is outside the
cargo workspace; its gate is `make game-check`.

**Spec:** `docs/superpowers/specs/2026-09-06-the-sett-design.md` —
**Amendment 1 (sections A0-A5) governs**; sections 3 and 4 are superseded
and kept verbatim beneath it. Evidence:
`docs/superpowers/ledgers/2026-09-06-the-newel.md` (R9, R10, R13, R14,
decisions #1/#7/#8) and `docs/superpowers/ledgers/2026-09-06-the-sett.md`
(S1-S8, decisions #1-#4).

## Global Constraints

- **`make gate-commit` does not scan `clients/`.** Almost all of this work
  is there. `make game-check` is the gate for it and runs `cargo clippy
  --all-targets` over both client crates, so **every example left behind
  must survive clippy or be deleted.** Run `make game-check` before every
  commit that touches `clients/`.
- **The lexicon guard scans the WORKING TREE, not the index** (`cli/tests/
  suite/lexicon_guard.rs`). The word `cell` in the mesh-vertex sense is
  banned; an untracked scratch file carrying it reddens a commit that
  touches no Rust at all. Say `facet` for a patch, `vertex` for a point,
  `box` for a character position on the plate. A line that must carry the
  word gets `// lexicon: <reason>` on it.
- **The `git stash` stack is shared across every worktree.** Never a bare
  `git stash pop` or `apply`. Use `git stash create` or `git show
  <sha>:<path>`.
- **Stage explicit paths. Never `git add -A`.** Other agents may hold live
  mutations in this worktree.
- **No gate runs rustdoc** (registry row `TOOL-no-gate-runs-rustdoc`). A
  task that moves a doc comment between items verifies by building the docs
  and reading the rendered output, not by reading the source.
- **Determinism:** nothing here is committed to a ledger or a save format.
  The plate is drawn, never stored. No `HashMap`/`HashSet` — `BTreeMap`,
  `BTreeSet`, `Vec` only (`clippy.toml` `disallowed-types`). No wall-clock
  time outside a bench, where the `#[allow(clippy::disallowed_types)]`
  precedent is `legend_redraw_bench.rs`.
- **Absorb `main` at every task boundary** via `make sluice-stage
  BRANCH=campaign/the-sett REF=<full-sha>`; a conflict is refused at the
  mouth in milliseconds, which is the signal to absorb locally and
  resubmit.
- Every crate sets `#![warn(missing_docs)]`. Every public item, field and
  variant gets a one-line doc comment.

The construction, stated once because every property below depends on it:

- The **centre column** is built first: from the anchor, `heading_rose(f)[0]`
  (N) repeatedly upward and `heading_rose(f)[4]` (S) repeatedly downward.
- Each **row** is then built outward from that column's facet:
  `heading_rose(f)[2]` (E) rightward, `heading_rose(f)[6]` (W) leftward.
- A `None` from `heading_rose` — which happens at exactly the 24 cube-corner
  facets, for exactly one bearing — **ends that chain**. Every box past it
  in that direction is `None`. It is never filled by a draw, a repeat, or a
  substitute (ledger decision #4).
- `w`/`h` are the drawn plate's own size and the anchor sits at
  `(w / 2, h / 2)`, so for an even `w` there is one more box to the left
  than to the right. Do not assume symmetry.

```rust
//! The rose raster's geometry, as committed assertions.
//!
//! **This file exists because The Newel's own probes did not.**
//! `newel_rasters.rs` and `newel_grid.rs` produced the measurements
//! decision #8 rested on and appear in no commit, so this campaign had to
//! re-derive every one of them from scratch (ledger S1-S8). These
//! assertions are the same measurements, kept.

use hornvale_game::rose::{RoseMemo, RoseRaster};
use hornvale_kernel::Facet;
use hornvale_locale::heading_rose;

/// The walk rung, and the plate at the enforced 80x24 terminal floor:
/// `spread::world_plate_width(80, 24) == 40` and
/// `spread::content_height(24) == 20`. **Not 53x27** — that is the plate at
/// 93x31, which The Newel's R14 misattributed to 80x24 (ledger S3).
const DEPTH: u32 = 13;
const W: u16 = 40;
const H: u16 = 20;

/// A facet at face-lattice `(x, y)`, built by descending the quadtree.
fn lattice(face: u8, x: i64, y: i64, depth: u32) -> Facet {
    let mut path = Vec::with_capacity(depth as usize);
    for level in (0..depth).rev() {
        path.push(((((x >> level) & 1) as u8) << 1) | (((y >> level) & 1) as u8));
    }
    Facet { face, path }
}

/// A uniform sweep over all six faces — the population R13 measured —
/// PLUS a targeted roster of facets whose own window crosses a face seam or
/// reaches a cube corner.
///
/// **The targeted half is not a garnish, and leaving it out is the defect
/// this doc comment exists to prevent.** A uniform sweep at any usable
/// `side` puts its nearest sample hundreds of facets from a face edge
/// (`side = 12` at depth 13 puts it at 341, against a plate half-width of
/// 20), so a uniform-only population never crosses a seam at all — and a
/// seam is exactly where a transport could flip handedness and where R14's
/// competing option blanks half the screen. A test that swept only the
/// interior would pass on a raster that fell apart at every face edge.
fn sweep(side: i64) -> Vec<Facet> {
    let scale: i64 = 1 << DEPTH;
    let mut out = Vec::new();
    for face in 0..6u8 {
        for i in 0..side {
            for j in 0..side {
                out.push(lattice(
                    face,
                    (2 * i + 1) * scale / (2 * side),
                    (2 * j + 1) * scale / (2 * side),
                    DEPTH,
                ));
            }
        }
        // Facets whose 40x20 window runs off the face's own lattice.
        for &(x, y) in &[
            (0, scale / 2),
            (scale - 1, scale / 2),
            (scale / 2, 0),
            (scale / 2, scale - 1),
            (3, scale / 3),
            (scale - 4, 2 * scale / 3),
            (2 * scale / 5, 1),
            (0, 0),
            (scale - 1, scale - 1),
            (2, 2),
        ] {
            out.push(lattice(face, x, y, DEPTH));
        }
    }
    out
}

/// How many of `facets` sit close enough to a face edge that a `W`x`H`
/// window runs off it. The tests assert this is non-zero before they assert
/// anything about seams — see [`sweep`].
fn crossing_a_seam(facets: &[Facet]) -> usize {
    facets
        .iter()
        .filter(|f| {
            let l = f.face_lattice();
            let hw = i64::from(W / 2);
            let hh = i64::from(H / 2);
            l.x < hw || l.x >= l.scale - hw || l.y < hh || l.y >= l.scale - hh
        })
        .count()
}

/// THE CAMPAIGN'S WHOLE CLAIM. Nathan's report is about the arrow keys, and
/// the arrows are the four cardinals (decision 0510: four-way primary).
/// Every cardinal must land in its own box, on every face — the polar caps
/// included, which is where the raster The Newel chose reaches 66.7%
/// (ledger S5).
#[test]
fn every_cardinal_lands_in_its_own_box() {
    let mut memo = RoseMemo::new();
    let facets = sweep(12);
    assert!(facets.len() > 400, "the sweep must be a population, not a spot check");
    assert!(
        crossing_a_seam(&facets) >= 60,
        "vacuity guard: only {} of the sampled facets have a window that crosses \
         a face seam, so this sweep would pass on a raster that fell apart at \
         every face edge",
        crossing_a_seam(&facets)
    );
    let mut checked = 0u64;
    for f in &facets {
        let r = RoseRaster::build(f, W, H, &mut memo);
        let (cc, cr) = r.centre();
        let rose = heading_rose(f);
        for (word, (dcol, drow)) in [(0usize, (0i32, -1i32)), (2, (1, 0)), (4, (0, 1)), (6, (-1, 0))] {
            let Some(want) = rose[word].as_ref() else { continue };
            checked += 1;
            let got = r.facet_at(
                (i32::from(cc) + dcol) as u16,
                (i32::from(cr) + drow) as u16,
            );
            assert_eq!(
                got,
                Some(want),
                "compass word {word} at {f:?} does not draw in its own box"
            );
        }
    }
    assert!(checked > 1600, "vacuity guard: only {checked} words were compared");
}

/// The picture after a step is the picture before it, shifted. This is what
/// makes the plate read as a map rather than re-deal itself every turn, and
/// it is the property that would license an incremental build (ledger S8).
/// The raster The Newel chose holds this on the equatorial faces and at
/// 66.7% on the caps.
#[test]
fn one_step_shifts_the_picture_and_changes_nothing_else() {
    let mut memo = RoseMemo::new();
    let mut compared = 0u64;
    let facets = sweep(6);
    assert!(
        crossing_a_seam(&facets) >= 60,
        "vacuity guard: this sweep crosses no face seam"
    );
    for f in facets {
        let before = RoseRaster::build(&f, W, H, &mut memo);
        let rose = heading_rose(&f);
        // East: the new picture's column j is the old picture's column j+1.
        if let Some(next) = rose[2].as_ref() {
            let after = RoseRaster::build(next, W, H, &mut memo);
            for row in 0..H {
                for col in 1..W {
                    compared += 1;
                    assert_eq!(
                        before.facet_at(col, row),
                        after.facet_at(col - 1, row),
                        "an east step moved more than the window at {f:?}"
                    );
                }
            }
        }
        // North: the new picture's row r+1 is the old picture's row r.
        if let Some(up) = rose[0].as_ref() {
            let after = RoseRaster::build(up, W, H, &mut memo);
            for row in 0..H - 1 {
                for col in 0..W {
                    compared += 1;
                    assert_eq!(
                        before.facet_at(col, row),
                        after.facet_at(col, row + 1),
                        "a north step moved more than the window at {f:?}"
                    );
                }
            }
        }
    }
    assert!(compared > 100_000, "vacuity guard: only {compared} boxes compared");
}

/// The inverse map answers for every box the raster drew, and for nothing
/// else. Task 4's overlays are placed entirely through it.
#[test]
fn the_inverse_map_agrees_with_the_raster_box_for_box() {
    let mut memo = RoseMemo::new();
    let mut round_tripped = 0u64;
    for f in sweep(4) {
        let r = RoseRaster::build(&f, W, H, &mut memo);
        for row in 0..H {
            for col in 0..W {
                let Some(here) = r.facet_at(col, row) else { continue };
                round_tripped += 1;
                assert_eq!(
                    r.box_of(here),
                    Some((col, row)),
                    "the inverse map disagrees with the raster at ({col}, {row})"
                );
            }
        }
    }
    assert!(round_tripped > 10_000, "vacuity guard: {round_tripped} boxes");
}

/// A cube corner refuses one bearing, so a chain through it ends. Nothing
/// fills the boxes past it — not a repeat, not a seeded draw, not a
/// substitute glyph (ledger decision #4, following R12).
///
/// This test also GUARDS ITS OWN NON-VACUITY: it first proves the chosen
/// facet really does produce blanks, so a future change that quietly filled
/// them would fail here rather than pass by never reaching the branch.
#[test]
fn a_chain_through_a_cube_corner_ends_and_nothing_fills_it() {
    let mut memo = RoseMemo::new();
    let corner = lattice(0, 0, 0, DEPTH);
    let r = RoseRaster::build(&corner, W, H, &mut memo);
    let mut blanks = 0u64;
    for row in 0..H {
        for col in 0..W {
            if r.facet_at(col, row).is_none() {
                blanks += 1;
            }
        }
    }
    assert!(
        blanks > 0,
        "non-vacuity: a raster anchored ON a cube corner must have blanks"
    );
    // Twenty steps in from the corner, the picture is whole again.
    let inland = lattice(0, 24, 24, DEPTH);
    let clean = RoseRaster::build(&inland, W, H, &mut memo);
    for row in 0..H {
        for col in 0..W {
            assert!(
                clean.facet_at(col, row).is_some(),
                "a facet well inside its face drew a blank at ({col}, {row})"
            );
        }
    }
}

/// Same anchor, same raster — twice, and from two memos in different
/// states. The memo is a performance choice and never a correctness one.
#[test]
fn the_raster_is_deterministic_and_the_memo_changes_nothing() {
    let anchor = lattice(2, 3000, 5000, DEPTH);
    let mut cold = RoseMemo::new();
    let a = RoseRaster::build(&anchor, W, H, &mut cold);
    let mut warm = RoseMemo::new();
    let _ = RoseRaster::build(&lattice(2, 3001, 5000, DEPTH), W, H, &mut warm);
    let b = RoseRaster::build(&anchor, W, H, &mut warm);
    assert!(warm.hits() > 0, "non-vacuity: the warm memo never hit");
    for row in 0..H {
        for col in 0..W {
            assert_eq!(a.facet_at(col, row), b.facet_at(col, row));
        }
    }
}
```

```rust
/// Everything `terrain_at_tile` reads once the facet is known.
///
/// `at` is the point INSIDE `facet` the reading is taken at — the tile's
/// own centre for a projected raster, the facet's own centroid for a graph
/// one. It is a parameter and not derived here; see below.
#[allow(clippy::too_many_arguments)]
pub fn terrain_at_facet(
    terrain: &GeneratedTerrain,
    geo: &Geosphere,
    index: &NearestVertexIndex,
    memo: &mut RoomMeshMemo,
    facet: &Facet,
    at_position: [f64; 3],
    ctx: Option<&hornvale_locale::LocaleContext>,
    at: WorldTime,
    season: u32,
    reflectance_cache: Option<&mut ReflectanceCache>,
) -> TileTerrain;
```

`terrain_at_tile` keeps its signature and becomes: unproject to `(lat,
lon)`, `unit_sphere_from_lat_lon`, `Facet::containing`, then **call
`terrain_at_facet` with that same position**. There is one copy of the
reading, and the extraction is exactly behaviour-preserving.

**`at_position` is a parameter for a measured reason, and collapsing it to
`facet.centroid()` inside the function would be a silent behaviour
change.** `terrain_at_tile` uses its unprojected point twice more after
resolving the facet: as the `Facet::containing(pos, grid_level)` fallback
when `facet.ancestor(grid_level)` is `None`, and — the one that bites — in
the dot products that pick *the nearest of the grid-level quad's four
corners to the tile's own centre*. At the walk rung that quad spans 128
facets on a side, so the tile centre and the facet centroid lie in the same
quad but can fall either side of its diagonal midlines, and the resolved
`vertex` — hence `ocean`, `water`, and the snapped elevation fallback —
flips there.

So the choice of point is the CALLER's, made visibly:
`terrain_at_tile` passes the point it already computed, and Task 3's graph
arm passes `facet.centroid()`. That makes Task 3's centroid choice a named
decision rather than a consequence of a refactor, and it makes this task's
agreement test an exact identity rather than an approximate one.
