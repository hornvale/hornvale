# The Plumb Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Retire the concept-side fence The Wicket left standing — an exhaustive
match whose missing arm panics world genesis, and a hand-maintained list whose
missing entry silently defaults a concept to epoch 0 — and build a ladder audit
that makes an authored constant declare which rung it sits on, with `REST_BOUT`
as its first conversion.

**Architecture:** `concept_doc`'s match becomes a `doc` field on the
`ThingTraits` row that already exists, so coverage stops being a match arm
somebody must remember and becomes a field that will not compile without a
value. `EPOCH_COHORTS` keeps its hand-maintained shape — an epoch is a
historical fact and cannot be recomputed — and gains a default-deny gate so
omission fails at test time instead of defaulting at runtime. Then a
`tools/plumb` sweep on the `type-audit` model whose verdicts are the five rungs
a constant can vary along.

**Tech Stack:** Rust 2024, std-only plus `serde`/`serde_json`/`libm`.
`cargo nextest`; in-module `#[cfg(test)]` for domains; `tests/suite/*.rs` behind
one binary for windows and cli. `tools/` crates are **outside** the cargo
workspace and carry their own manifests.

**Spec:** `docs/superpowers/specs/2026-09-02-the-plumb-design.md`

**Ledger:** `docs/superpowers/ledgers/2026-09-02-the-plumb.md` — append a ruling
as it is made, not at the end.

## Global Constraints

- **Layering** (`cli/tests/architecture.rs`): `kernel` → `domains/*` →
  `windows/*` → `cli`. A domain depends on the kernel and **nothing else**.
- **Dependencies**: `serde`, `serde_json`, `libm` only, workspace-wide. `tools/`
  crates are outside the workspace and this allowlist does not bind them.
  **An earlier draft of this line said to "follow `type-audit`'s example and
  stay std-only anyway". `type-audit` is NOT std-only** — it depends on `syn`
  (features `full`, `visit`, `extra-traits`) and `proc-macro2` with
  `span-locations`, because it parses real Rust rather than scanning lines.
  Follow that example properly: a line-based scanner would be measurably weaker
  at exactly the job here.
- **A `tools/` manifest carries an EMPTY `[workspace]` TABLE**, and omitting it
  breaks in this campaign's own environment. `type-audit`'s manifest documents
  why: without it, a checkout nested under another cargo workspace — *"e.g. a
  worktree under `.claude/worktrees/` inside the main repo tree"*, which is
  exactly where this campaign runs — makes cargo walk past the package's own
  root and bind to the outer workspace. Also add `tools/plumb` to the root
  `Cargo.toml`'s `exclude` list, following `type-audit` and `digest` rather than
  the `board`/`seam-guard` omission CLAUDE.md flags.
- **No `HashMap`/`HashSet`** — `BTreeMap`/`BTreeSet`/`Vec` only.
- **`#![warn(missing_docs)]`**; every public item documented.
- **`tools/type-audit` is default-deny** and runs in the commit gate: any new
  primitive at a `pub` boundary needs a verdict tag as the last line of its doc
  comment. A new `pub` field or const will trip it.
- **Every test carries `MUTATION THIS MUST FAIL AGAINST:`** with the observed red
  pasted (decision 0353). And, from The Wicket's own finding: **precision in a
  failure message is not evidence the check performs what it says** — run every
  mutation, never infer from a green.
- **Never chain a correction to its own assertion.** Apply the edit, print the
  verification, stop, read it, then commit. A `&&` chain is not a conditional.
- **Decision numbers come from the reserved block 0586-0595.** Never max+1.
- **`cargo fmt` before every commit**; `make gate-commit` must pass. Never bypass
  a commit hook.
- Branch `campaign/the-plumb`; worktree `.claude/worktrees/the-plumb`.

## Stage 1 — the concept fence

### Task 1: `concept_doc` becomes a row

**Files:**
- Modify: `domains/thing/src/lib.rs`
- Test: same file, in-module `#[cfg(test)] mod tests`

**Interfaces:**
- Produces: `ThingTraits { display: &'static str, doc: Option<&'static str> }`.
  `concept_doc` **no longer exists**; `register_concepts` reads `traits.doc`.

- [ ] **Step 1: The BORROWED interaction is MEASURED, and it decides the field's type**

Measured before dispatch, so you do not have to discover it:

```text
  concept_doc arms          16
  THING_KINDS rows          17
  "hearth" glossed?         NO — it is BORROWED (ceded to settlement, 0025)
```

`register_concepts` only reaches the doc inside its `None` arm — the branch for
a label not already registered — and a BORROWED kind never gets there.
`concept_doc`'s own `unreachable!` message says exactly that.

**So the field is `Option<&'static str>`, and an earlier draft of this plan
recommended the opposite.** The reasoning that overturned it: giving `hearth` a
gloss in `domains/thing` would author a *second definition of a concept
`settlement` owns*. That is not a harmless unused value — it is a divergent
copy of someone else's prose, which is the exact class of defect this campaign
exists to remove. A `None` is not a second encoding of `BORROWED`; it says
something narrower and true — *this domain does not define this concept's
gloss*.

```rust
pub struct ThingTraits {
    pub display: &'static str,
    /// The gloss the concept registry publishes for this kind, or `None`
    /// where another domain owns the concept — see [`BORROWED`]. A gloss
    /// authored here for a borrowed kind would be a second, divergent
    /// definition of prose that domain already owns.
    pub doc: Option<&'static str>,
}
```

**Ledger this as a numbered entry**, including the overturn — the plan
recommended the other option and the code disagreed.

- [ ] **Step 2: Write the failing test**

```rust
    /// Every roster kind carries a non-empty gloss, and the gloss reaches the
    /// concept registry. This replaces `concept_doc`'s exhaustive match: the
    /// match could go short by one arm and panic at world genesis, where a
    /// missing struct field will not compile.
    ///
    /// **Direction: rostered ⊆ glossed.** Its converse — that no gloss exists
    /// for a kind outside the roster — is structural now rather than asserted,
    /// because a gloss can only exist as a field of a row.
    ///
    /// MUTATION THIS MUST FAIL AGAINST: give `hearth` a gloss (it is BORROWED,
    /// so the fourth arm must catch it), and separately set `bed`'s to `Some("")`.
    #[test]
    fn every_roster_kind_carries_a_gloss() {
        let reg = thing_registry();
        for label in THING_KINDS {
            let traits = reg
                .get(&KindId(label))
                .unwrap_or_else(|| panic!("roster names {label:?}, registry does not"));
            match (traits.doc, borrowed_owner(label)) {
                (Some(doc), None) => assert!(
                    !doc.is_empty(),
                    "{label:?} has an empty gloss — a registered concept with no \
                     doc renders as a blank line in the reference page"
                ),
                (None, Some(_)) => {}
                (Some(_), Some(owner)) => panic!(
                    "{label:?} is BORROWED by {owner:?} and also carries a gloss \
                     here — that is a second definition of their concept"
                ),
                (None, None) => panic!(
                    "{label:?} is not borrowed and has no gloss — nothing will \
                     describe it in the concept registry"
                ),
            }
        }
    }
```

- [ ] **Step 3: Run it and watch it fail to compile**

Run: `cargo test -p hornvale-thing`
Expected: compile error — `ThingTraits` has no `doc`. **That is not evidence**;
Step 6 captures the behavioural red.

- [ ] **Step 4: Add the field and move every gloss**

Add `doc` to `ThingTraits`, and move each of `concept_doc`'s arms onto its row
**verbatim** — this task changes where the strings live, never what they say.
Then delete `concept_doc` entirely, and re-point `register_concepts`
(`domains/thing/src/lib.rs:343`) at `traits.doc`.

The struct gains a `pub` field of a primitive type, so **type-audit will demand
a verdict tag**. `display` already carries
`type-audit: bare-ok(identifier-text: display)`; a gloss is prose, so the class
to add is `bare-ok(prose: doc)` — check `tools/type-audit/src/tag.rs`'s ratified
list rather than trusting this line.

- [ ] **Step 5: The acceptance criterion — an empty artifact diff**

The concept registry is a committed artifact, so this refactor must be
**behaviour-preserving**:

```bash
make rebaseline
git diff --exit-code -- $(grep -v '^#' docs/generated-paths.txt | grep -v '^$' | cut -f1)
```

Respond by branch:

  rewritten.
- **`book/src/reference/concept-registry-generated.md` moved** → a gloss changed

  accept it.
- **`docs/audits/` alone moved** → the type-audit report picked up the new

- [ ] **Step 6: Verify the mutation reddens, paste the red, revert**

Use `scripts/mutate.py`, not `sed`. Re-run after reverting and confirm green — a

### Task 2: the epoch gate

**Files:**
- Create: `cli/tests/suite/accession_coverage.rs`
- Modify: `cli/tests/suite.rs` (add the module)

**Interfaces:**
- Consumes: `hornvale_language::accession::{EPOCH_COHORTS, concept_epoch}`, and
  a fully-built `ConceptRegistry`.
- Produces: nothing other tasks consume.

- [ ] **Step 1: Understand what already exists, and what does not**

`domains/language/src/accession.rs` already has
`no_concept_appears_in_two_cohorts` (`:662`) — so **duplicates are covered**.
What is missing is the other direction: a concept registered by some domain and
listed in **no** cohort. `concept_epoch` (`:614`) walks the cohorts and
**returns 0** on a miss, and `a_listed_concept_reports_its_cohort_and_an_unlisted_one_reports_zero`
(`:674`) pins that fallback as intended.

So the gate must assert the **authored set has no unlisted members** without
contradicting the function's documented fallback. Do not change
`concept_epoch`; a refusal at that depth would ripple through every caller for a
case the gate prevents.

The gate lives in `cli/` because that is the only crate that can build the whole
registry — `ConceptRegistry::manifests` enumerates it in deterministic
concept-name order (`cli/src/concepts.rs:100` uses exactly this).

- [ ] **Step 2: Write the failing test**

```rust
//! The accession-coverage gate (The Plumb): every concept any domain registers
//! must sit in exactly one `EPOCH_COHORTS` cohort.

/// **Direction: registered ⊆ cohorted.** `accession.rs`'s own
/// `no_concept_appears_in_two_cohorts` already holds the converse — no concept
/// in two cohorts — so the pair is two-way, and neither half can be repaired
/// by deleting the other.
///
/// Why this is a gate and not a change to `concept_epoch`: that function
/// returns 0 on a miss and its own test pins the fallback as intended. The
/// fallback is a reasonable runtime answer; what was missing is anything
/// preventing the authored set from relying on it. A concept that silently
/// lands in epoch 0 re-sorts the proto-root churn The Accession closed.
///
/// MUTATION THIS MUST FAIL AGAINST: delete `"brazier"` from its epoch-18
/// cohort in `domains/language/src/accession.rs`. It compiles, every existing
/// accession test stays green, and the kind silently becomes epoch 0.
#[test]
fn every_registered_concept_sits_in_a_cohort() {
    let registry = /* build the full registry the way cli/src/concepts.rs does */;
    let mut unlisted: Vec<String> = Vec::new();
    for manifest in registry.manifests() {
        let name = &manifest.concept.name;
        if !EPOCH_COHORTS.iter().any(|c| c.contains(&name.as_str())) {
            unlisted.push(name.clone());
        }
    }
    assert!(
        unlisted.is_empty(),
        "registered concepts in no accession cohort — each silently reports \
         epoch 0 and re-sorts the proto roots: {unlisted:?}"
    );
    assert!(
        registry.manifests().count() > 100,
        "the registry is too small for this sweep to mean anything — it did not build"
    );
}
```

The registry construction is deliberately left to you: read
`cli/src/concepts.rs` and follow how it builds one, rather than taking a
constructor from this plan. A plan author does not know which builder is
current; the implementer does, after reading.

- [ ] **Step 3: Run it — it may PASS immediately, and that is expected**

If the authored set is already complete, the test is green on arrival. **Green
here is not the evidence.** Step 4 is.

- [ ] **Step 4: Apply the mutation, paste the red, revert**

```bash
python3 scripts/mutate.py domains/language/src/accession.rs '"brazier"' '"brazier-x"'
cargo test -p hornvale --test suite -- every_registered_concept_sits_in_a_cohort
```

Confirm the failure names `brazier`. Then `git checkout --` the file, re-run,
and confirm green.

**If the test does NOT redden**, the sweep is not reaching the concepts you
think it is — that is a finding, not a fixture to adjust. Report it.

- [ ] **Step 5: Note the anti-vacuity assertion is absolute, not relative**

The `> 100` floor is deliberate: a relative check (`> 0`) passes on an empty
registry, which is the failure mode The Wicket catalogued twice. Pin a real
number and let a future registry growth move it deliberately.

- [ ] **Step 6: Format, gate, commit, push**

```bash
cargo fmt
make gate-commit
git add -A
git commit -m "test(cli): every registered concept sits in an accession cohort"
git push
```

## Stage 2 — the ladder audit

### Task 3: `tools/plumb` — the walk and the vocabulary

**Files:**
- Create: `tools/plumb/Cargo.toml`, `tools/plumb/src/{main,lib,args,walk,tag,audit,report}.rs`
- Modify: nothing in the workspace

**Interfaces:**
- Produces: a binary invoked as
  `cargo run --manifest-path tools/plumb/Cargo.toml -- <check|report>`;
  `plumb::tag::Rung` with the six variants below; and
  `plumb::tag::parse_tag(&str) -> Result<Rung, _>`, which Task 4's `check`
  consumes.

- [ ] **Step 1: Read the model before writing anything**

`tools/type-audit/` is the shape to follow, and it is not a loose analogy — it
is a default-deny scanner over Rust source with three-valued verdicts, a
`check` subcommand for the gate and a `report` subcommand for a committed
artifact. Read `src/tag.rs` (verdict parsing, and `BARE_OK_CLASSES` as a
ratified vocabulary), `src/walk.rs` and `src/extract.rs` before designing.

**It is OUTSIDE the cargo workspace** (like `type-audit` and `seam-guard`), so
it has its own manifest and its own toolchain reach. It is **not** in the
workspace `members` list and must not be added to it.

- [ ] **Step 2: The verdict vocabulary is the ladder**

```rust
/// Which axis an authored constant varies along. The rungs are
/// `MAP-one-kind-model`'s three additions seen from the numeric side, so a
/// verdict here is also a registration: a constant tagged `PerPeople` names
/// a consumer for the kind-edge campaign that does not exist yet.
pub enum Rung {
    /// Varies by nothing — a physical or lattice constant.
    Universal,
    /// Varies by seed and pins — a property of the world, not of the code.
    PerWorld,
    /// Varies by `KindId` — belongs in a species component table.
    PerSpecies,
    /// Varies by what a people does — needs a kind-to-kind edge.
    PerPeople,
    /// Varies by the individual — derived from `Lineage`, never stored.
    PerIndividual,
    /// Not yet judged. Carries a wave, exactly as type-audit's does.
    Pending(String),
}
```

Tag syntax, following `type-audit:`'s placement rule — **last line of the doc
comment**, one verdict, a reason in parentheses:

```rust
/// Ticks in one standard day. The lattice's own unit.
/// plumb: universal(the tick lattice is a kernel constant, not a world property)
pub const TICKS_PER_STD_DAY: i64 = 100_000;
```

- [ ] **Step 3: Write the failing test for the parser**

Put the parser's tests in the tool's own crate, in-module, matching
`type-audit`'s layout.

```rust
    /// A verdict with no reason is a parse error, not a lenient default.
    /// `seam-guard` made the same choice for `expect(survives: …)` and its own
    /// doc explains why: a reasonless declaration is one nobody can review.
    ///
    /// MUTATION THIS MUST FAIL AGAINST: make the reason optional in the parser.
    #[test]
    fn a_verdict_without_a_reason_is_refused() {
        assert!(parse_tag("plumb: universal").is_err());
        assert!(parse_tag("plumb: universal(the tick lattice)").is_ok());
    }
```

- [ ] **Step 4: The walk finds numeric consts, and reports its own scope**

Scan for `const <NAME>: <numeric> = …` — `f64`, `i64`, `u64`, `u32`, `usize`.
Measured population, so the implementer knows what to expect rather than
discovering it: **610** workspace-wide across `domains/*/src` and
`windows/*/src`; **269** in files that also mention a species, a `Body` or a
`KindId`.

The `report` subcommand must print the scope it walked and the count it found.
A scanner that silently walks less than a reader assumes is this project's
recurring defect; make the denominator visible in the output.

- [ ] **Step 5: `check` is REPORT-ONLY in this task**

Do not make it fail yet. Task 4 turns it into a gate, once the backlog is
seeded. A default-deny check landing before its backlog reddens on 610 items and
teaches everyone to ignore it — which is the failure mode this project already
names for a gate that goes red on day one.

- [ ] **Step 6: Format, test, commit, push**

```bash
cargo fmt --manifest-path tools/plumb/Cargo.toml
cargo test --manifest-path tools/plumb/Cargo.toml
make gate-commit
git add -A
git commit -m "feat(plumb): a sweep that asks which axis a constant varies along"
git push
```

**Nothing runs this tool's tests for you.** `tools/` crates are outside every
gate and there has been no CI since decision 0125, so run
`cargo test --manifest-path tools/plumb/Cargo.toml` by hand on anything that
touches it.

### Task 4: seed the backlog, then close the ratchet

**Files:**
- Modify: many, one tag line each
- Modify: `tools/plumb/src/audit.rs` (make `check` refuse)

- [ ] **Step 1: Declare the uncontested crates in bulk**

Scope by **how arguable a rung is**, not by which file a constant sits in. The
kernel's lattice, `domains/terrain`'s and `domains/astronomy`'s physics are
`universal` and say so in a word each. Declare them.

**Do not tag a constant `universal` merely because you cannot see why it would
vary.** That is the inherited fixedness this campaign exists to convert into a
chosen one. If the reason does not write itself in half a line, it is
`pending(wave-1)` and someone will judge it later.

- [ ] **Step 2: Judge the contested middle**

`windows/vessel` (drives, clock, liveness) and `domains/species` are where the
answer is genuinely arguable. Work these by hand. Expect several
`per-species` and at least one `per-world` — `REST_BOUT` is Task 5's, and
finding more is the point rather than a surprise.

**Any constant you judge `per-species` or above is a fidelity finding, and it
goes to Nathan rather than being converted here.** This campaign ships the
audit; it does not re-tune the world. `REST_BOUT` is the sole exception, and
only because it is already a named regression with a measured bound.

- [ ] **Step 3: Everything else is `pending(wave-1)`**

A pending verdict is honest and cheap. The ratchet's value does not depend on
the backlog being empty.

- [ ] **Step 4: Close the ratchet, and prove it can fail**

Make `check` refuse an untagged numeric const. Then prove the gate is real:

```bash
# add an untagged `const PLUMB_PROBE: f64 = 1.0;` to a scanned file
cargo run --manifest-path tools/plumb/Cargo.toml -- check
# expect: non-zero exit naming PLUMB_PROBE
```

Paste that output into the report, then remove the probe and confirm the check
passes. **A gate nobody has watched fail is not known to work** — this campaign
inherited that lesson twenty-five times over.

- [ ] **Step 5: Decide whether `check` joins `make gate-commit`, and record it**

`type-audit`'s `check` is in the gate; `seam-guard` deliberately is not, because
each of its call sites costs a scoped test run. `plumb check` is a source scan
with no build, so cost is not the objection — but a third default-deny scanner
in the commit gate is a decision, not a default.

Measure it (`time` the check), decide, and **ledger the decision with the
number**. Either answer is defensible; an unrecorded one is not.

- [ ] **Step 6: Format, gate, commit, push**

```bash
cargo fmt
make gate-commit
git add -A
git commit -m "feat(plumb): the ratchet closes -- a new untagged constant fails"
git push
```

### Task 5: `REST_BOUT` — the worked example

**Files:**
- Modify: `windows/vessel/src/liveness.rs`
- Test: `windows/vessel/tests/suite/fatigue_stock.rs`

- [ ] **Step 1: The conversion is local — `act_span` already has what it needs**

`REST_BOUT` (`liveness.rs:2398`) is `TickSpan::from_ticks(TICKS_PER_STD_DAY / 4)`
and is consumed at exactly one place: `act_span`'s `Action::Rest => Some(REST_BOUT)`
(`:2603`). That function's signature already carries `terrain: &dyn Terrain`
(`:2598`), which is how `next_awake_day` reaches the world's day length in the
`Action::Sleep` arm directly below. **No signature changes.**

Follow the tidal-lock convention rather than inventing one:
`clock::ticks_per_local_day(day: Option<TickSpan>)` returns the base rate when
there is no day to divide, and its doc states that as the convention.

- [ ] **Step 2: The bound this closes, stated so the test can pin it**

`REST_BOUT`'s doc asserts a calibration — the repayment must clear
`HYSTERESIS_H` (0.1). Since The Wicket's fix round the repayment is
`REST_FALL * 0.25 / L` in local days, so it **falls below the band at any local
day longer than 1.25 standard days** — about 30 hours, on worlds that legally
admit up to 100 (`RotationPin::PeriodHours`, `domains/astronomy/src/pins.rs:81`).
At 100 hours it repays 0.03 against a floor of 0.1.

- [ ] **Step 3: Write the discriminating test**

```text
  a saturated body on a 100-hour world, resting: the repayment clears
  HYSTERESIS_H after the conversion, and does not before it
```

Name the mutation as **reverting the conversion**, and confirm the test reddens.
If it stays green, the fixture's world is not slow enough to discriminate and
the test is measuring nothing — widen the world, not the assertion.

- [ ] **Step 4: Tag it, and let it be the audit's exhibit**

`REST_BOUT` gets `plumb: per-world(a rest's length is a fraction of the local
day, not of the standard one)`. Cite it in the tool's own docs as the worked
example: a constant whose rung was arguable, judged, and converted.

- [ ] **Step 5: Read the artifact branch table**

This changes behaviour on slow-rotating worlds. Seed 42's day is not slow, so
the expected outcome is **no artifact movement** — but read the branch table
rather than predicting: nothing moved → proceed and say so; a golden moved → name
the seed and the mechanism; a census column moved → report it, since the census
refresh is the controller's and belongs at pre-merge close.

- [ ] **Step 6: Format, gate, commit, push**

```bash
cargo fmt
make gate-commit
git add -A
git commit -m "fix(vessel): a rest's length is a fraction of the LOCAL day"
git push
```
