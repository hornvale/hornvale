# The Winze Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A delving stops where it finds something — and what it found is legible only to the people it killed, and only for as long as anyone remembers.

**Architecture:** Three things this needs are declared and unproduced, which is why the wound itself is the *last* task rather than the first. Occupations get a **function** derived from ore (so mines exist at all), a committed **delve depth**, and a per-increment **hazard** whose breach ends the delving. Nothing selects on depth: breached delvings sit at their own maximum by construction, so "a fraction of the extreme minima" is an output. The consequence lands on the finders, never on the ground.

**Tech Stack:** Rust 2024, `serde`/`serde_json`/`libm` only. `cargo nextest`. No new crates.

**Spec:** `docs/superpowers/specs/2026-08-19-the-winze-design.md`

## Global Constraints

Copied from the spec. Every task's requirements implicitly include this section.

- **Nothing is named.** A breach records that a delving ended by breaching. It does not record what came through, because nothing knows. No field name, no doc comment, no almanac line hints otherwise.
- **`thaumic` stays 0.0. UNI-2 stays unratified.** If a task needs a thaumic value, stop and report.
- **No avoidance-as-placement-penalty.** Nathan's ruling: future people may resettle. If a task finds itself subtracting from a cell's suitability because of history, stop — that is the explicit non-goal.
- **Exactly one function is derived.** `Mine`, from ore. `Trade`/`Cult`/`Fort` each want their own argument and are out of scope.
- **Nothing selects on depth.** The survivorship shape is an output of the hazard. If a task adds a rule of the form "if depth > X then wound", stop and report — that is the design this spec replaced.
- **No `HashMap`/`HashSet`** — `BTreeMap`/`BTreeSet`/`Vec` only. Float sorting uses `total_cmp` with deterministic tie-breaks.
- **No wall-clock time.** `Instant` is banned in tests too.
- **`cargo fmt` before every commit.**
- Integration tests live behind one `tests/suite.rs` binary per crate: a new test file goes in `tests/suite/` with a `#[path = "suite/<stem>.rs"] mod <stem>;` line. **A top-level `tests/*.rs` is a new compilation unit costing ~0.6 s of kernel time on every gate** (`PROC-gate-commit-is-not-its-tests`).
- Capture long output to a file and grep the file; a repo guard refuses two test invocations in one command. Whole-workspace invocations need `HV_TEST_OK=1` and are measurements, never gates.

### Ruling 1 — real assertions

**Every `#[test]` this plan sketches must carry real assertions expressing what its comment describes. A test that compiles with no assertion is a task failure.** If a test as specified cannot assert what it claims, say so and propose one that can.

### Ruling 2 — mutations

Prove a check can fail with `python3 scripts/mutate.py <file> <old> <new>`, never `sed`. It refuses unless the target is found **and unique**. **This plan never prescribes which expression to mutate** — it names the property the mutation must demonstrate. You are reading the code; the plan author was not.

### Ruling 3 — heavy-tier tests are `#[ignore]`d

A live-worldgen probe carries `#[ignore = "heavy: …"]`, so a plain `--test suite` invocation **selects it and runs nothing**, printing `0 tests run` — which reads as success. Use `--run-ignored all` and **assert the count is what you expect, not zero.**

### Ruling 4 — this campaign moves every world's history

Task 4 adds a **draw** inside the bake's epoch loop. Stream consumption order is a save-format contract, so every seed's history changes from that commit onward. This is deliberate and stated in spec §5.3. **Re-pin goldens in the commit that causes the move, never deferred**, and never treat an unexpected *absence* of drift as good news.

### Task 4: The hazard

**The campaign's mechanism.** Read Ruling 4 before starting.

**Files:**
- Modify: `domains/history/src/record.rs` (`CauseOfEnd::Breached`)
- Modify: `windows/worldgen/src/history_bake.rs` (the hazard; the close)

**Interfaces:**
- Consumes: `Bake::close(&mut self, idx: usize, year: f64, cause: CauseOfEnd, ended_by: Ended<BakeId>)`; the delve depth from Task 3.
- Produces: `CauseOfEnd::Breached`, live in every match over that enum.

- [ ] **Step 1: Widen the enum and let the compiler enumerate**

Add `Breached` with a one-line doc comment, then `cargo check --workspace --all-targets > /tmp/hv-enum.log 2>&1`. **This plan deliberately contains no match-site list** — for an enum widening the compiler *is* the enumeration and a written list goes stale. Work the errors.

For each arm you add, decide deliberately whether `Breached` behaves like an existing cause or needs its own. `vestige.rs`'s `CauseOfEnd -> HazardKind` map is the one where the answer is probably "its own" (`HazardKind::Numinous` exists), but **verify against the code and say what you chose and why.**

- [ ] **Step 2: Choose the stream label and read the discipline first**

The hazard draws. Read `domains/history/src/streams.rs` and `domains/CLAUDE.md` on seed labels: **a new label is safe; a changed or reused label is an epoch.** State which label you added.

- [ ] **Step 3: Write the failing test** — a built world contains at least one occupation with `cause == Some(CauseOfEnd::Breached)`, pooled over the panel.

- [ ] **Step 4: Run, verify it fails.**

- [ ] **Step 5: Implement the per-increment hazard**

Each increment of delving carries a small breach probability. A delving that breaches closes with `CauseOfEnd::Breached` and `Ended::Nature` — **nothing is named**, so there is no antagonist entity. If you find yourself wanting `Ended::By(..)`, that is the design drifting toward naming something; stop and report.

**Do not scale the hazard so hard that it becomes a depth rule.** The Global Constraint stands: nothing selects on depth. The hazard may be uniform per increment; if you make it depth-dependent, say so explicitly and justify it, because that is the boundary between "survivorship" and "a threshold in disguise".

- [ ] **Step 6: Run, verify pass.**

- [ ] **Step 7: Prove the hazard fires AND does not fire**

Both directions, per Ruling 2 and spec §5.4's discipline:
- neutralise the hazard → breached count goes to zero
- force it to certainty → *every* delving breaches

**A rule that fires on everything and a rule that works are identical in a count.** Paste both reds; choose the mutations yourself.

Every world's history moves — the draw changed stream consumption. Expected and deliberate (Ruling 4).

### Task 5: Does the survivorship shape appear?

**A measurement whose null is publishable.** This is the campaign's central claim under test.

**Files:** Create `windows/worldgen/tests/suite/survivorship_probe.rs`

- [ ] **Step 1: Write the probe.** Pooled across the panel: the `delve_depth_m` distribution of **breached** delvings versus **ordinarily-ended** ones; counts of each; the overlap.

- [ ] **Step 2: Run once, inspect many.**

- [ ] **Step 3: Apply the branch table**

```
breached and ordinary distributions are indistinguishable
    -> the survivorship claim is FALSE and the mechanism is decoration.
       Report it as the headline. Do NOT tune the hazard to separate them
       --- retuning a constant to rescue a prediction after unblinding is
       the thing this project's preregistration discipline exists to stop.
breached are deeper, with overlap
    -> the claim holds. Report the separation AND the overlap honestly;
       a clean separation would actually be suspicious, since the hazard
       is not supposed to be a depth rule.
breached are deeper with NO overlap
    -> report it and investigate: perfect separation suggests the hazard
       became a threshold in disguise (Task 4 Step 5).
```

- [ ] **Step 4: Pin the readout as a witness**, with a doc comment naming what would change the verdict. fmt, gate, commit.
