# The Ken — decision ledger

Campaign A of a three-campaign split over a batch of 13 client bug reports
(Nathan, 2026-09-05). Decision block **0816–0825**.

The split itself was Nathan's call at the brainstorm, not an auto-resolved
gate: **A** = prose and knowledge-leak (this campaign), **B** = command
grammar and rendering, **C** = the `Room`/`Chamber` vocabulary question.
A and B are independent; C is last because it touches save-format contracts.

#1 [Q] — **Which of the 13 reports belong to this campaign?**
· *Decision*: #2, #5, #6, #7, #12 — the five whose common cause is the
  observer's frame, not the renderer or the parser.
· *Why*: they share one mechanism (author's-frame or sim-frame content
  reaching creature's-frame prose), so one spec fixes all five; the other
  eight share a different one.
· *Alternatives discarded*: grouping by file (they span `windows/vessel`,
  `windows/locale`, `domains/astronomy`) — would have split one cause
  across two campaigns.
· *ideonomy passes / overturns*: 1 / 0 (the pass that produced the
  `Chamber` tree also confirmed the frame axis as the grouping principle).
· *Capture*: the four non-A groups recorded in the brainstorm; C's naming
  candidates carried into this ledger's Follow-ups.

#2 [Q] — **Is there an existing precedent for "the creature's frame"?**
· *Decision*: yes — adopt the existing `!` prefix convention rather than
  invent a mechanism.
· *Why*: `!whoami`, `!why`, `!examine` already mark the author's/debug
  frame, and `domains/astronomy/src/facts.rs:14` already states the rule
  this campaign enforces: the star class is committed as a concept id
  `"yellow-dwarf"`, *"never as Morgan-Keenan prose — no creature in this
  world could have invented that taxonomy"*, with `windows/book` rendering
  the author's-frame display. The leak is that possession prose uses the
  author's-frame rendering.
· *Alternatives discarded*: a new per-string frame tag (invents vocabulary
  for a distinction the codebase already draws); a config flag (makes a
  constitutional rule optional).
· *ideonomy passes / overturns*: 1 / 0.
· *Capture*: this is the spec's organising principle, §2.

#3 [G2] — **`[room <id>, day <fraction>]` — replace or delete?**
· *Decision*: replace with creature-legible orientation; the ids and the
  fractional day are not lost, because `!whoami` already reports both.
· *Why*: verified live — `!whoami` answers *"A white-dragon of the wilds
  (agent 9630022852472602624), day 0, room 3733133217."* The author's-frame
  data already has a legitimate home, so the header is a duplicate of it in
  the wrong frame.
· *Alternatives discarded*: deleting the header outright (it is a real
  transcript anchor and a per-turn orientation line).
· *ideonomy passes / overturns*: 1 / 0.
· *Capture*: spec §4.2.

#4 [G5] — **Task 2's plan text would have produced four vacuous tests.**
· *Question*: Task 2 makes the "the nearest ground lies" line optional. What
  happens to the tests that consume it?
· *Decision*: re-point each affected test at a room that still emits the
  clause; never soften its guard.
· *Why*: the pre-dispatch brief check (dispatching-hornvale-subagents step 1)
  found four consumers in `windows/vessel/tests/suite/session.rs` — lines
  533, 602, 672, 758. Two hold `.expect(...)` guards, and line 533 is the
  load-bearing invariant *every printed way out is a command you can type*.
  The tempting repair — softening `.expect()` to `if let Some(..)` — makes
  all four PASS while asserting nothing, which is indistinguishable from
  success at review time.
· *Alternatives discarded*: deleting the four tests (destroys a real
  invariant); guarding them behind the new `Option` (the vacuous-green
  failure above).
· *ideonomy passes / overturns*: no pass was run for this — it is a
  mechanical verification finding, not a design choice.
· *Capture*: plan Task 2 gained a new Step 6 stating the table and the
  prohibition; subsequent steps renumbered.

#5 [G5] — **The turn header carries no time at all — an ideonomy pass overturned the spec's own §4.2.**
· *Question*: §4.2 requires the header's time phrase to share a derivation
  with the sky line. What is that shared source?
· *Decision*: there isn't one, and the header should carry **no time**. It
  names a place; the time of day stays where it already lives, in the sky
  line one row below.
· *Why*: the phase logic (`fraction`, `dawn`, `dusk`, `TWILIGHT_MARGIN`, the
  `progress` arc words) is inside `sky_at`'s body in
  `domains/astronomy/src/provider.rs`, baked into a description string. No
  time-of-day accessor exists — `calendar.rs` exposes `year_phase`,
  `season_phase` and `moon_phase`, none of which is it. Honouring §4.2
  literally meant minting public astronomy API so two callers could share one
  derivation; the inversion pass asked why the header restates a time the
  next line already gives in the character's own words. Removing it needs no
  new API, makes disagreement between the two impossible rather than merely
  managed, and indoors — no sky line — leaves a character not knowing the
  hour, which is the campaign's thesis rather than a gap.
· *Alternatives discarded*: (a) new `daypart()` in `domains/astronomy`
  (public API to remove duplication, when deleting the duplicate was
  available); (b) parsing the phase back out of the SkyReport description in
  vessel (couples prose to prose, fragile); (c) recomputing the fraction in
  vessel (a second clock — the exact disagreement §4.2 was written to
  prevent).
· *ideonomy passes / overturns*: 1 pass (inversion) / **1 overturn** — the
  pass reversed the controller's own spec text, which is the case the
  autopilot's "adopt the improved version" clause exists for.
· *Capture*: plan Task 3 Step 4 rewritten to state the ruling and to refuse
  a new astronomy public item; spec §4.2 is superseded by this entry and the
  plan, and is flagged for Nathan at G6 rather than edited silently.
