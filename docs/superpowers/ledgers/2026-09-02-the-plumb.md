#6 [G4] — **OVERTURN, caught by verifying the brief against the code before
dispatch: `ThingTraits.doc` is an `Option`, and the plan recommended the
opposite.** Measured:

```text
  concept_doc arms   16        THING_KINDS rows   17
  "hearth" glossed?  NO — it is BORROWED, ceded to settlement (decision 0025)
```

The plan said to prefer a plain `&'static str` on every row, with a borrowed

The test becomes a four-way match rather than a non-empty assertion, which is
strictly more than the original asked for — it now catches a borrowed kind that
grows a gloss, which is the direction that would actually do damage. Two
mutations, not one.

**Recorded as an overturn rather than an edit** because the plan's recommendation
was reasoned and wrong, and the thing that caught it was the mandatory
verify-the-brief-against-the-code step running one task ahead — the same step
that caught four defects in The Wicket. Cost if the ruling is wrong: a `None`
that should have been a string, visible the moment anything reads a borrowed
kind's gloss, which nothing does.

#14 [G4] — **Instances 30 and 31, both mine, both in the plan's Global
Constraints, and one would have broken in this campaign's own worktree.**

**30.** The constraints said `tools/` crates should "follow `type-audit`'s

**31.** The constraints never mentioned that a `tools/` manifest needs an

written out: without it, a checkout nested under another cargo workspace —

is precisely where this campaign runs.** An implementer following my plan would
have hit a confusing cargo failure in its first minute.

Both were caught by the pre-dispatch verify step, by reading the manifest I was
telling someone to imitate. Neither is subtle once read; both were invisible
from the outside, which is the whole argument for the step running one task
ahead rather than at plan-authoring time.

#19 [G5] — **RULING: the walk inverts its type filter, because the project's own
discipline is making the tool blind.** Task 3's reviewer found
`Excluded: non-numeric type | 520` covers ~26 authored numbers: `i32`×7, `u8`×7,
`u128`×1 outside `NUMERIC_TYPES`, plus ~11 newtype-wrapped quantities —
`TickSpan`×3, `WorldTime`, `Gyr`, `SurfaceWetness`, `Snowpack`, `Dispersion`.

Two consequences, and the second is why this is a ruling rather than a bug fix:

1. **`REST_BOUT` is invisible.** It is `TickSpan`, so the tool cannot see the
   constant spec §4.4 titles *"the worked example"*. Worse,
   `tools/plumb/src/walk.rs:1-9` says a `pub` filter "would have walked straight
   past both" — true of visibility, false of type, written as though it covered
   both. The campaign's shape, inside the campaign's own tool.
2. **The blind zone GROWS with code quality.** This repo pushes constants toward
   typed newtypes — `type-audit` exists to do exactly that — so every crate that
   improves becomes less visible to `plumb`. An audit whose coverage decays as
   the codebase gets better is worse than no audit, because its silence reads as
   a clean bill.

Decision: **denylist, do not allowlist.** Judge every `const` except those whose
type is declared non-quantity (`&str`, `bool`, `char`, and container/marker
types), rather than admitting a fixed list of numeric primitives. A newtype over
a number is the *most* quantity-like thing in the tree — `Gyr` is a duration —
and the rung question applies to it unchanged. Cost if wrong: the denominator
grows and some entries need a `universal` verdict they would not otherwise have
needed, which is cheap and visible; the alternative is a scanner that quietly
stops seeing the code it was built for.
