### #1 [G1] — reconcile records; do not archive history

**Question:** How should the project review completed and incomplete campaign
documentation without turning its historical record into a disposable archive?

**Decision:** Run an evidence-led exception audit. Preserve specs, plans,
chronicles, retrospectives, ledgers, and decisions in place. Classify each
campaign's closure state from durable evidence; route each unresolved residue
once, to the registry only when it is an enduring speculative direction.

**Why (precedent cited):** The Frontier makes registry IDs permanent and says
that an idea draining into a spec flips status rather than being deleted.
The Cartulary establishes a committed campaign ledger as the durable home for
rulings and deferred findings. `docs_consistency.rs` already freezes the
spec-plan matcher’s blind spots and the pre-ledger exemption population; the
campaign should extend that evidence rather than infer completion from a
checkbox or filename.

**Alternatives discarded:** Broad archival/deletion would erase provenance;
adding every unfinished item to the registry would turn a speculative backlog
into an issue tracker; trusting only the exact filename matcher would preserve
the known coverage hole.

**Ideonomy passes / overturns:** 2 / 0. The first matrix pass separated
artifact lifetime from residue type. The second atlas pass made the audit’s
asymmetry explicit: a historic record may close without a registry row, while
an unresolved product direction must have one durable home.

**Capture actions:** Spec §3; the reconciliation report; this ledger.

### #2 [G4] — make reconciliation a total, checked map

**Question:** Is a prose audit sufficient, or must the campaign leave an
executable guard over the relationship map it constructs?

**Decision:** The audit ledger is a TSV with a narrow Rust parser and
total-coverage checks in `docs_consistency.rs`. It covers the four campaign
record directories exactly once per path and validates dispositions, evidence,
residue routing, and registry targets. It does not infer aliases or truth from
filename similarity; those remain cited human judgements in the TSV.

**Why:** The existing exact matcher explicitly trades recall for a checkable
rule: 54 unmatched plans never enter its ledger assertion, while 244 historic
records are exempt. A prose result would recreate that asymmetry without any
way to notice later drift. Existing TSV guard patterns use std-only parsing
with a literal header and line-numbered errors, so this is the smallest
consistent mechanism.

**Alternatives discarded:** A fuzzy global matcher would manufacture plausible
but false campaign pairs; a one-off prose report would be unable to prove its
own population; adding all deferred observations to the registry would violate
The Frontier’s distinction between ideas and process/repair work.

**Ideonomy passes / overturns:** 1 / 0. Atlas × dimension-identification,
with connectivity and symmetry prompts: the same audit must show both its
linked closure trails and its isolated records, and total coverage must be
symmetric across the four source directories.

**Capture actions:** plan Tasks 1–4; permanent `docs_consistency` checks;
this ledger.

### #3 [G5] — delay the live coverage assertion until the audited data exists

**Ruling:** Move the live `every_campaign_record_is_reconciled` assertion
from Task 2 to the opening of Task 3. Task 2 keeps the parser, closed
vocabularies, per-row validation, and a unit-tested population helper; Task 3
first makes the total assertion red against the schema-only TSV, then turns it
green by writing the audited rows.

**Why:** A total-coverage check over an intentionally empty schema artifact
must fail, so requiring it to pass before the data-writing task would make the
Task 2 commit impossible. The spec requires the final guard, not a false
intermediate green.

**Cost if wrong:** The audit may discover that the data task needs a different
coverage interface; the assertion is still isolated in the same module and
can be corrected with the TSV before any historic source repair is made.

### #4 [G5] — test the population helper against the repository, not a new temp tree

**Ruling:** Task 2’s population-helper test reads the existing four audit
directories and asserts known inclusions, `README.md` exclusion, path
existence, and directory membership. It does not create a temporary fixture.

**Why:** This repository’s temp-path ratchet treats new `temp_dir()` sites as
a potential fixed-path collision. A synthetic tree would add that unrelated
surface merely to test a helper whose live directory layout is the contract.

**Cost if wrong:** A future directory-layout change may need a more isolated
fixture; the task can then introduce one only with a collision-safe name and
the required ratchet justification.
