#1 [G1] — **Which redundancy, and in which direction?** · Collapse
`KnownWater` into `LatestVisit`; refuse the `LatestVisit`-into-`Trail` merge.
· **Why:** the brief names both, and §1.1's read/index cross-product shows
`KnownWater`'s row is a strict subset of `LatestVisit`'s while the reverse is
impossible — a first-visit map cannot answer `latest_at`. Precedent:
`TOOL-known-water-is-latest-visit` (raw, med), The Pawl retrospective item 7,
The Pawl chronicle's "one redundancy shipped knowingly". · **Alternatives
discarded:** merging all three into `Trail` (undoes The Pawl Task 5's
measured O(rooms) result); keeping `KnownWater` as a zero-state view type
over `&LatestVisit` (a name for no state). · **ideonomy passes / overturns:**
1 / 0 (tuple: combination + substitution over a tree organon; dimensions
size, materiality, purpose). No overturn; three enrichments, ledgered as #2,
#3 and #4. · **Capture:** spec §1, §2, §8 (decision 0726).

#2 [G2] — **What does the ideonomy pass's size axis produce that the brief
did not state?** · The three indexes form a *chain of projections*, and the
rule that both deletes `KnownWater` and refuses the `Trail` merge is one
criterion, not two judgements: *a resident index earns its keep only if some
read it serves is asymptotically cheaper on it than on its parent.* ·
**Why:** the brief asks for the `Trail` refusal to be justified "in the
spec"; a criterion is a better artifact than a justification because it binds
the next tenant too. · **Alternatives discarded:** stating the refusal as a
one-off measured preference (the form the brief offered; it does not
generalise). · **ideonomy passes / overturns:** part of #1's pass. ·
**Capture:** spec §1.2 and decision 0726 (to be minted).

#3 [G2] — **Two reads or one form with two predicates?** · `rooms_at` and

membership rule is stated once. · **Why:** writing `water_at` as an
independent copy of the first-visit test re-creates, at method scale, exactly

#1's pass (purpose axis). · **Capture:** spec §2.1; provisional decision
0727, minted only if the rule proves worth binding beyond this type.

#4 [G2] — **Is "held bytes + advance work per fact" the whole measurement?**
· No — add K3, the belief read's own µs/call. · **Why:** `water_at` moves
from walking a `BTreeMap<Facet, WorldTime>` to a
`BTreeMap<Facet, Vec<WorldTime>>` — same key count, larger value, identical
complexity class, and a constant that may move on cache locality. Asserting
"a subtraction cannot slow anything down" is exactly the claim-class the

PROC-12 twice). · **Alternatives discarded:** arguing it from The Detent's
finding that `plan_to_room` dominates the belief read at 99.08% — true, and
still an inference where a measurement was available. · **ideonomy passes /
overturns:** part of #1's pass (materiality axis). · **Capture:** spec §4 K3,
§3 rule 5.

#7 [G5] — **Is one positive control enough for the hash witness?** · No —
two, in order: **A (reach)** makes `KnownWater::absorb` return immediately;
**B (sharpness)** flips `if day < *first` to `if day > *first`. · **Why:** B
is the control the spec and plan originally named alone, and it is the
*narrower* of the two: flipping first-visit to latest-visit changes
`water_at`'s admission ONLY at a past instant, so it moves the hash only
through the chain past-instant read → different admitted set → different
chosen room → different committed fact. A control that can stay still for
four separate reasons cannot tell "the script does not reach this fold" from
"the fold is reached and this branch is not". A empties the belief set
outright and answers the reach question directly. Precedent: the
dispatching skill's step 1 (read every imperative for the outcome hiding
inside it) and memory, a mutation is evidence only if it could have moved. ·
**Alternatives discarded:** keeping B alone (found during pre-dispatch
verification to be a four-link chain); dropping B for A (B is the one that
tells us whether the past-instant branch is exercised, which is what makes
the `first_visit <= t` filter load-bearing). · **ideonomy passes /
overturns:** 0 — a verification finding, not a design choice; recorded
explicitly. · **Capture:** plan Task 1 Step 1; spec §3 rule 1 to be updated
at Task 1 close with what the controls actually measured.

## Task 1 — complete

**Controls, run before any constant was minted.** Control A (make
`KnownWater::absorb` return immediately) is the reach test; control B (flip
the min-keeping branch) is the sharpness test. Measured at merge base
`f20fdbecb`:

| script | A moved? | B moved? |
|---|---|---|
| seed 42 fixed script | no | no |
| seed 6 emitter (ledger + hazard) | no | no |
| seed 17, 12 waits | **YES** | no |
| seed 11, 12 waits | **YES** | no |

**Ruling 1 — the two inherited scripts are blind to this fold, so neither is
minted.** The seed-42 fixed script and the seed-6 emitter script both commit
byte-identical ledgers with the whole tenant neutralised. A constant on a
blind script costs ~15 s a run for a number that cannot fail for the right
reason, so the campaign mints on seeds 17 and 11 instead, found by sweeping
seeds 0..24 under control A (eight move). Rejected: minting on all four
anyway "for coverage" — a witness that cannot discriminate is decoration, and
0541's whole argument is that a constant must be shown to work before it is
trusted.

**Ruling 2 — the plan's own fallback was wrong, and the implementer caught
it.** The plan said to fall back to `WALKING_SEED` (14) if the first two were
blind. Seed 14 is *also* blind under A: its residents commit 2,668 positional
facts but reach **no water at all**, so `water_at`'s `is_water` filter is
vacuous there and emptying the tenant changes nothing. This is spec §3 rule
3's floor (a) failing, and that rule's own branch table — "choose a shape
where it is not; the possession shape's seed is the lever" — is what applied.
The plan text is the defect; the seed sweep is the fix.

**Ruling 3 — control B cannot fire on a walk-derived ledger, and the null was
mechanised rather than reported.** A third mutation put a `panic!` inside the
min-keeping branch; no script panicked, so the branch condition is never true
on these shapes. `DriveMovements` commits at the tick's own day and ticks
advance monotonically, so a room's first absorbed sighting already IS its
minimum.

**Ruling 3a — controller correction to ruling 3's SCOPE.** The Task 1 report
and the module doc generalised that to "any session-derived ledger" and drew
the conclusion that no script could rescue control B. The scope is right and
the framing invites a wrong inference: the branch is **not dead code**.
`liveness::place_agent(entity, room, day)` is a second, `pub` `agent-at`
writer that takes an ARBITRARY `WorldTime` and constrains nothing, and
`windows/lab/src/synthetic.rs` authors whole scenario ledgers with it —
`stranded_from_known_water` and its siblings each commit two placements at
hand-chosen days. Those ascend by happenstance, not by construction, and
`windows/lab`'s health calibration reads belief over exactly those ledgers.
So spec §5 step 2's min-vs-`days.first()` equivalence governs a case a
sibling window can construct **today**. Verified by reading `place_agent`
(`windows/vessel/src/liveness.rs:6311`) and its lab call sites, not inferred.
Precedent: memory, an invariant test is only as wide as the writers it
exercises — the walk was the only writer anyone had counted. · **Capture:**
`the_kerf.rs` module doc corrected in place; Task 3's dispatch carries the
sharpened reason for the descending-order fixture.

**Ruling 4 — the 60 s ceiling is judged against quiet readings, and both are
recorded.** The same binary measured 22.079/23.189 s quiet and
92.816-125.359 s at load averages from `78.99 49.74 29.59` to
`262.01 157.25 83.42` on ten cores. Rejected: shortening the script to chase
the contended number, which would freeze another campaign's contention into
this file. Precedent: memory, a quiet box needs all three load averages.
Seed 16 refused on cost (248.2 s quiet); seed 21 (49.7 s) passed over for
buying no more reach than seed 17.

**Minted.** `KERF_SEED_17_LEDGER = 0x7394_8823_9689_ce2a` (67 bodies, 928
`agent-at`, 28,601 belief reads, 1,194 at past instants) and
`KERF_SEED_11_LEDGER = 0xd4e4_a793_ed70_6478` (27 bodies, 290 `agent-at`,
7,973 belief reads, 0 past). Each script runs ONCE (ledger #8); each asserts
its floors; seed 11 deliberately asserts no past-instant floor, because it
records zero and asserting a floor a shape cannot meet is how a witness gets
quietly weakened. Both retire at close per 0541.

*No ideonomy pass was run for any of these rulings: each is a measurement
verdict or a correction of fact, not a choice among designs.*
