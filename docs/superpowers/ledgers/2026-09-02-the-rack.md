## Brainstorm (pre-G3)

### #1 [G1] — how does a turn stop re-deriving sixty-seven felt states?

**Question:** Three shapes were on the table. (A) Cache today's stateless
read (`affect_of_memo_occupied`) in a `Derived<EntityId, Affect>` with
`Ledger` validity, invalidated by day and by the ledger position. (B) A
struct-of-arrays roster the TICK writes — position and felt state per
slot — that every turn reads. (C) Make `snapshot`'s memos session-lived
(`&mut self` or interior mutability) and keep the per-turn fold.

**Decision:** (B), with the felt-state ruling in #2.

**Why:** Nathan's brief names (B) outright, and the survey found its two
halves already present: the tick keeps a `WalkState.affect` per walked body
and drops it (`liveness.rs:6320-6328`), and The Roll left three parallel
`Vec`s beside `bodies` (`on_roll`, `roll_keys`) as the archetype's first
columns. (A) misses on every room-scale move because the day advances, and
would keep the fold; (C) keeps the fold outright (the A\* plan-home and the
history folds are the cost, not the cold memo). Penstock §6.6: "handing
back a slice of a dense array avoids *allocating* it … 'iterated as an
array' … the profile suggests it is the main event."

**Alternatives discarded:** (A) — invalidated every move; (C) — warms the
memo, keeps the work.

**Ideonomy passes / overturns:** 1 / 0 — tree + combination (prompts:
longevity, cardinality). The tree's "what quantity" branch surfaced #2 as a
decision rather than a detail; the writer × longevity combination gave "the
tick writes, valid until the next tick" as the simplest member and named
invalidation-on-commit (Penstock §5.7) as the later rung; the cardinality
prompt added POSITION to the archetype — the four `agent_position`
fan-outs per wait read the same array the tick can write — an enrichment
the brief did not name. One pass reached a design with no open branch;
called converged.

**Capture:** spec §3.1–§3.3; `UNI-ecs-is-the-adaptive-cache` → elaborated.

### #2 [Q] — which felt state is the creature's: the read's or the tick's?

**Question:** `affect_of` is "the same arbitration a walk step runs, but
stateless" — no alarm field, `Mode::Idle`, empty frontier, the session's
day. The tick's `WalkState.affect` has all of those. Storing the tick's
value changes what `needs` and `sensed.present.felt` say.

**Decision:** The tick's. A creature feels what its own last resolution
felt; between ticks it does not re-feel. **Fidelity ruling, leads G3.**

**Why:** The stateless read was adopted (The Confidant) because the tick's
value was dropped before anyone could read it — a workaround for the
absence this campaign removes, not a modelling claim. The tick's resolution
is the one that moved the creature; reporting a different arbitration as
its feeling reports something it did not feel. `UNI-ecs-is-the-adaptive-
cache` already draws the line: snapshot-for-speed separated from
commit-for-truth, "tick-by-tick position and hysteresis state belong
there."

**Alternatives discarded:** compute the stateless quantity inside the tick
and store THAT (keeps today's wording, pays the fold once per tick per
body — but pins a re-imagining as the canonical feeling); store both and
let the client choose (two truths on the wire).

**Ideonomy passes / overturns:** 1 / 0 — the tree's quantity branch.

**Capture:** spec §3.4; decision 0596 at close.

### #3 [Q] — is `position` a view or content?

**Decision:** A view: it must equal `agent_position(&ledger, body, day)` at
every read, pinned by a VIEW ≡ SCAN test after every verb class (P3). The
tick writes it from the same `st.pos` whose `agent-at` fact it commits, so
equality is by construction and the test is the proof. **Cost if wrong:**
a mismatch is a writer bug, ruled fixed at the writer, never the fold.

**Ideonomy passes / overturns:** 1 / 0 — cardinality prompt in #1.

### #4 [Q] — where does the regression watch live?

**Decision:** A counted budget (`TurnWork` counters on `Session`; folds,
searches, position folds, shadowcasts, bodies scanned) asserted per verb
class in a COMMIT-tier test; the existing wall-clock gate stays as the
stage-tier instrument with its blind zone documented.

**Why:** `session_cost.rs` is `heavy:`-tiered, pooled, and its own doc says
20 of 50 samples exceed its ceiling while it passes; a wall-clock gate
cannot run in the commit gate on a loaded Mac without flapping (The
Repose), and The Roll's 10× went through it green. A count is
deterministic on every box (Penstock §7: "deterministic budgets are
drift-checked and gate-able"; `HomeNavCache::searches` is the shape).

**Alternatives discarded:** tighten the wall-clock ceilings (the same blind
zone, tighter); a per-verb wall-clock ceiling in the commit gate (flaps).

**Ideonomy passes / overturns:** 1 / 0 — longevity prompt: a gate that
lasts is one that does not depend on the box it runs on.

**Capture:** spec §3.5; new row `TOOL-turn-budget-counted`.
