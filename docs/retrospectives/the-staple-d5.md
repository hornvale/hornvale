# The Staple D5 — retrospective

*The chronicle carries the instrument's product story. This record carries
the process lessons and the work that must survive recycling.*

## Probe before mechanism

D5 began with a tempting implementation question—how to make a city—and
kept the more useful one: does the existing world already produce a
comparative flow-convergence apex? That inversion prevented a new label or
mechanism from manufacturing the evidence it was meant to discover.

## Missingness must remain visible

The first pure model review exposed four risks: control collapse required all
controls instead of any one, source counts could double-count one source,
availability was too coarse, and a single regime could look recurrent. The
corrections made each failure mode explicit. The live probe then added the
same discipline at the join boundary: missing, duplicate, orphan, and site
mismatch witnesses force an underpowered result rather than disappearing.

The general lesson is the same as D4's, one layer higher: a comparative
statistic is only as honest as the identity and provenance it carries. A
source count without source identity, or a recurrence without phase identity,
can be numerically plausible while measuring the wrong thing.

## Scratch, review, and ledger routing

The committed D5 ledger records the G1/G2/G4 decisions, task-boundary
corrections, focused results, and the final local verification. The scratch
directory contains the plugin progress record, task briefs, review packages,
and mutation diffs; these are process evidence, not product artifacts, and
their substantive findings are represented here and in the ledger.

Task 1 received an approved final review. Task 2's first review found missing
live joins; those findings were fixed and independently verified by the
corrected focused suite and full local gates, but the requested final review
seat did not return a written verdict after bounded finish requests. That
limitation is retained explicitly rather than reported as approval.

No deferred minor remains without an outcome. The fixed-roster measurement,
census, and city mechanism remain future work; the D5 probe's ignored readout
is the deliberate boundary for that work.

## Close evidence and process lesson

The branch first met `origin/main` at close and absorbed its 14-commit lead
before this package was written. That missed the preferred stage-boundary
absorption cadence, so the close procedure caught it rather than letting the
merge queue discover it later.

The D4/D5 compatibility suite passed 19/19 selected tests, the docs suite
passed 75/75, and the local commit gate passed. No census or fixed-roster
measurement ran. The durable lesson is that a green branch tip is not the
merge product: absorb `main`, write the close artifacts, then submit the exact
resulting SHA.
