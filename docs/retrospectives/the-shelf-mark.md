# The Shelf-Mark — retrospective

Process lessons only (decision 0020). Product is in
[the chronicle](../../book/src/chronicle/the-shelf-mark.md).

## 1. A measuring tool that models the format differently from the checker disagrees with it silently

This campaign made the same class of error twice, in two separate tools, and
caught both only by accident:

- Counting malformed rows with `awk -F'|'` reported **five** offenders. Two
  of them escape their pipes correctly (`\|`) and are fine — awk's field
  separator does not model markdown's escape. The real count is three.
- Counting over-cap Idea cells with an un-trimmed `awk` reported **278**. The
  registry pads short cells with trailing spaces for column alignment, so 42
  already-compliant rows were counted as bloated — `MAP-1`'s Idea cell is 80
  characters. The real count is 237.

Both numbers went into a spec and were presented to Nathan before being
caught. The first was caught because a follow-up command happened to
contradict it; the second because the enforcing test, once written, disagreed
with the script that had sized the work.

**The fix that generalizes:** the waiver fixture is now generated by *running
the enforcement check and reading its own failure output*, not by a parallel
script. A generator and a checker that share one parser cannot drift. Where
a campaign must size work before the checker exists, write the checker first
and let it do the counting.

This is a sibling of the existing lesson that a property test is only as
strong as its generator — here, a *measurement* is only as trustworthy as its
parser.

## 2. Verify a claim about a rendered artifact in the rendered artifact

The spec's first draft said the three malformed rows "render with extra
columns." That was inferred, and wrong. Building the book and counting `<td>`
elements showed mdbook truncates each row to the header's column count, which
shifts every cell left and **drops the last one** — the Where pointer, gone
from the published page.

The autopilot overlay already requires running the command rather than
reasoning about it. It earned its keep here: the true defect is materially
worse than the drafted one and became the campaign's headline. The wording
worth keeping is that acceptance criterion 3 checks the *rendered HTML*, not
the markdown source — the source looking right was never the property that
mattered.

## 3. A check that is green on arrival has demonstrated nothing

Three of the five checks pass the moment they land (the numbered-ID freeze
is generated from the current file; the empty-Where tripwire has no
violations; the cap is fully waived on day one). Each got an explicit
mutation step in the plan: append a violating row, confirm the check reddens,
restore. All three reddened.

Without that step the campaign would have shipped three checks with no
evidence any of them can fail — the exact "tests asserting nothing ship
GREEN" failure this project has recorded before, in its most seductive form,
because here the green is *expected* and therefore unsuspicious.

## 4. Declaring a struct field one task before it is read fails the gate

Task 1 defined `RegistryRow` with all five fields; `status` and `where_cell`
are not read until Tasks 2 and 3. Clippy's `dead_code` is `-D warnings` here,
so the pre-commit hook rejected it. The fix was to add each field in the task
that consumes it.

Worth writing into future plans that stage one data structure across several
tasks: **the interface block should list what each task ADDS, not the final
shape**, or every intermediate commit is red.

## 5. Scope was re-cut mid-execution, on measurement, and that was right

The plan committed to compacting all 81 over-cap `shipped` rows. After 13,
the real cost per row was clear and the remaining rows were much smaller.
Nathan cut the wave to rows over 1500 characters (43 rows), leaving the rest
to the ratchet.

This is what the ratchet was designed to permit and it is worth naming as a
positive pattern rather than a slip: **because the enforcement landed before
the cleanup, the cleanup became interruptible.** A campaign that had done the
cleanup first and the enforcement last would have had to finish or lose the
gain.

## 6. Cost note: prose compaction does not batch well

43 rows took 8 applier runs and roughly 20 trim iterations. Drafts
consistently landed 10–20 % over the 600-char cap; the working calibration is
about 90 words, and drafting to ~85 lands first try. A dry-run mode printing
every candidate's length — rather than only the failures — would have cut the
iterations roughly in half. Worth building before the next burn-down wave.
