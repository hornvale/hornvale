# 0114. A native client drives across the linker and reads across the serializer

**Status:** Accepted (2026-08-09, G6) · **Decider:** Nathan · **Relates:**
[0022](0022-sim-emits-data-clients-render.md),
[0023](0023-in-repo-clients-carry-their-own-toolchains.md),
[0055](0055-external-clients-consume-a-versioned-wasm-catalog.md),
[0115](0115-a-clients-mirror-may-omit-a-channel.md)

In the context of building `clients/game/`, a native character-grid client that
must *drive* a live possession rather than read a released catalog, facing a
`hornvale-vessel` public surface that offers a native caller `would_turn_hostile`,
`npc_grievance`, `committed_hostility_count`, `agent()`, `knowledge()` and
`session_ledger_json()` — all reachable across the linker, all forbidden by the
client's own brief — we decided that **a native client links the simulation to
drive it and consumes only serialized `vessel/session/v1` JSON to display it**,
and that this containment is **structural, never a lint**.

## The decision

Two crates, and the split is the mechanism:

- `hornvale-game` (the binary) depends on `hornvale-vessel`. Its **driver**
  (`driver.rs`) owns exactly three operations: start a session, hand it a line
  of text, return a snapshot as JSON — and *it* renders nothing; it never
  composes a cell. The crate as a whole does own the terminal (`term.rs` writes
  a composed `Grid` out; `main.rs` redraws), so the accurate statement is that
  the crate owns the terminal and the driver seam, and that all *composition*
  happens in the render crate below.
- `hornvale-game-core` (the render crate) **has no Hornvale dependency at all.**
  It takes a `&str` of JSON and returns a grid of cells. It does not open a
  terminal and does not run world generation.

The forbidden methods are therefore not discouraged in the render path — there
is no symbol to reach. `Session` is not in that crate's dependency graph.

This is the same seam `clients/vessel/wasm` already occupies: `hv_start` and
`hv_handle` link the possession layer, and every displayed datum returns through
`snapshot_json`. The difference is that wasm *forced* it there and this record
*chooses* it.

## Why this seam rather than either obvious one

**Reading the typed struct proves nothing.** `windows/explain` narrates a world
by reading only committed facts, and the architecture notes say that restriction
"is how it validates that the ledger is sufficient." A client that renders only
`vessel/session/v1` is that pattern aimed at the session snapshot: it is standing
evidence that the emitted contract is renderable. A client reading the in-memory
types is evidence of nothing, and the first time the snapshot lacks a field it
quietly reaches past the schema instead of the schema growing to meet it. The
Quire cashed this in: its exits row proved the contract *insufficient* to
distinguish an underground possession from a surface one, which a typed-struct
client would have papered over by reading `inside` directly.

**A subprocess-per-query client is measurably dead.** Driving `hornvale scene`
as a subprocess pays genesis on every invocation — 1.43 s measured — and has
nowhere to keep session state. It cannot host a game.

## The cost, priced

One JSON round trip per turn, against a measured 1.071 ms `handle` and 1.249 ms
snapshot emit, with rendering *episodic* — redrawn on a committed turn, never on
a frame. Not a budget concern at any plausible terminal size.

## Consequences

- **The render crate's suite is microseconds, not seconds.** Every visual
  assertion is a pure function over a committed `vessel/session/v1` fixture with
  no simulation present and no way to reach one. This is why interactive play
  became a viable feedback loop: a render change rebuilds two small crates and
  relinks.
- **The containment needs a gate, and the gate needs `--all-features`.**
  `make game-check` greps `cargo tree` for a `hornvale-` dependency in the render
  crate. Review demonstrated the first version was blind to a dependency declared
  `optional = true` — one manifest line and it printed `ok`. It now runs
  `cargo tree --all-features` on both the check and its failure dump. The
  `--target=all` axis (cfg-gated cross-target deps) is deliberately still open
  and is named as such in the script's comment rather than implied away.
- **The mirror's real risk is silent lag**, not overreach: a field can be added
  upstream and the client never notice. The answer is the committed fixture,
  regenerated by `regenerate-artifacts.sh` and drift-checked, so divergence
  surfaces as a diff rather than as an absence.
- **This record does not bind `clients/world-wasm`**, which is 0055's
  released-catalog posture and a different problem.
