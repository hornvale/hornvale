# 0099. Worlds are version-locked to the code that generated them

**Status:** Accepted (2026-08-04) · **Decider:** Nathan · **Supersedes:**
[0006](0006-seed-labels-are-permanent-contracts.md) · **Relates:**
[0001](0001-determinism-is-constitutional.md),
[0007](0007-seed-is-identity.md),
[0033](0033-serialized-floats-are-quantized-for-cross-platform-determinism.md),
[0037](0037-the-room-tier-ledger-is-chunk-partitioned.md),
[0055](0055-external-clients-consume-a-versioned-wasm-catalog.md)

In the context of a world model still changing shape weekly, facing the cost of
treating every seed-derivation label as a permanent cross-version contract, we
decided that **a world generated by version *V* is playable only by version
*V*** — accepting that no saved world survives an upgrade, and that we do not
get attached to any particular world.

## What this supersedes, and why the rationale evaporated

Decision 0006 made seed-derivation labels permanent save-format contracts, with
deliberate regeneration taking an epoch suffix (`settlement/name/v2`) rather
than a rename. Its stated reason was precise and, at the time, correct:
*"Renaming a label corrupts every saved world that depended on it, invisibly."*

If no saved world outlives its version, there is nothing to corrupt. The
epoch-suffix discipline was buying forward compatibility that we have now
decided not to want.

This is a continuation rather than a reversal: **0037 already narrowed the
frozen surface to a single item** — *"the only frozen save-format contract is
the room address (`RoomId`)"* — and reserved even the physical ledger form as
free to evolve "because it is rebuildable from the log." This record finishes
that move.

## What survives untouched

- **Byte-identity within a version stays constitutional.** Same seed + same
  pins + same version → byte-identical output (0001). That is what makes tests,
  goldens, byte-identity fixtures and the census work, and none of it is
  relaxed. Version-locking buys **forward-compatibility freedom, not
  determinism freedom.**
- **A label change becomes a cost, not a corruption.** Renaming a stream label
  still rebaselines every golden and re-runs the census. That bill is unchanged;
  only the silent-corruption hazard is removed. Epoch suffixes remain *available*
  as a courtesy where they aid legibility; they are no longer *required*.
- **Decision 0055's cross-repo scene schemas are a different contract and are
  unaffected.** `scene/system/v1`, `scene/tiles/v1` and their siblings are
  consumed by the external Orrery from released catalogs, so they remain
  additive-or-versioned. A world save is not a scene document; do not read this
  record as licence to break one.
- **`RoomId` stays frozen — within a version.** The play ledger references
  locale and chamber addresses (0069), so the address bijection must be stable
  for as long as a save is loadable, which is now exactly one version.

## Consequences

- **A save must carry a version stamp, and loading a mismatch must refuse
  loudly.** Silent partial loads are the failure this record would otherwise
  invite. The refusal names the generating version and the running one — same
  discipline as a failed pin under 0007.
- **`scout` and the world catalog are unaffected**: a seed is still a world's
  identity (0007). Sharing a *seed* stays meaningful across versions in the only
  sense that ever mattered — "generate this world with your build" — even though
  the resulting bytes may differ.
- **The regeneration reflex gets cheaper.** Changing a drawn quantity no longer
  requires reasoning about historical saves, so mechanism changes cost a
  rebaseline and nothing more.
- **This licence expires when the world stabilises.** The reason this is
  affordable is that everything is moving fast. When Hornvale reaches a state
  worth preserving worlds from, a successor record should re-freeze the surface
  deliberately — this is a decision about the current phase, and it says so.
