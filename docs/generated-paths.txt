# The drift-check path list — the single source of truth.
#
# TWO TAB-SEPARATED COLUMNS: `path<TAB>author`. `make rebaseline` diffs the
# path column; cli/tests/suite/generated_paths.rs asserts each path is
# TRACKED, because `git diff --exit-code <path>` is silently vacuous against a
# path with no index entry (CLAUDE.md, "Generated-artifact freshness") — and,
# since The Attestation, that its author is one the roster names. Every shell
# reader takes the path with `cut -f1`; do not word-split a raw line.
#
# THE AUTHOR COLUMN NAMES AN INVOCATION, NOT A PROGRAM. The three ROSTER
# values are the set names `scripts/lane-sets.tsv` already uses for the same
# thing (`artifacts`, `census`, `heavy`) — an author IS a roster set name IS
# the suffix of a `sluice:<set>` ledger label, so the whole chain joins with
# no separate mapping table. `scripts/regenerate-artifacts.sh` is the literal
# writer behind BOTH `artifacts` and `census`: the same script, gated by the
# `HV_CENSUS` flag, so naming the *script* here would collapse exactly the
# distinction this campaign draws between an ordinary rebaseline and a census
# refresh. Use the invocation the roster names, never the program underneath
# it.
#
# A FOURTH VALUE, `none(<reason>)`, DECLARES AN ABSENCE RATHER THAN DELETING
# THE ROW OR LEAVING A COARSER ROW FALSE FOR IT (Task 5, The Attestation —
# Nathan's ruling at G3). Some files a directory's declaration nominally
# reaches have NO writer at all: hand-written prose, a hand-edited file, a
# retired generator, or a study frozen and run by hand exactly once.
# `none(<reason>)` keeps the file's TRACKED-NESS guarantee (still `git
# add`-ed, exactly like any other declared path) while stating, reviewably,
# that no roster author writes it — the repo's existing ratchet idiom
# (type-audit's `waiver(<reason>)`, seam-guard's `expect(survives: <why>)`,
# `tropes check`), not a new invention. `none(...)` SCOPES STRICTLY TO "NO
# ROSTER AUTHOR" (artifacts/census/heavy), NOT "NO WRITER OF ANY KIND": a
# handful of `none(...)` rows below (the Casement client build's
# `vessel.js`/`vessel-worker.js`, the opt-in-flag-rebaselined
# `lexicon-inventory.tsv`, the byte-golden `layering-generated.md`) DO have a
# real writer, just not one this schema's three-value roster can name — the
# reason names that real writer so the fact is declared, not lost. THE
# REASON IS MANDATORY: a bare
# `none` or an empty `none()` is a PARSE ERROR, exactly as a reasonless
# `waiver(...)` or `expect(survives: ...)` is elsewhere — the reason is the
# whole value of the row, since it is what a future reader acts on.
# `every_declared_path_names_a_known_author` (cli/tests/suite/
# generated_paths.rs) enforces the syntax; a sibling check there catches a
# `none(...)` row gone STALE — one of the two known sources below starting
# to write a path declared absent — the same one-directional-declaration
# rot `expect(survives: ...)`'s STALE-DECL verdict exists to catch.
#
# PRECEDENCE, NEEDED ONLY BECAUSE `none(...)` EXISTS: THE LONGEST MATCHING
# DECLARED PATH GOVERNS A FILE'S TRUE AUTHOR. Several directories below pair
# a directory row (the author of MOST of its files) with individual file or
# subdirectory rows naming the TRUE author — often `none(...)` — for the
# files that are exceptions. `git ls-files` (the tracked-ness check) still
# matches every row that nominally covers a file, redundantly and
# harmlessly, exactly as it already did for the three individually-declared
# `docs/audits/` files below (The Stope, Task 2b). But for "is this row's
# author TRUE for this file", read a directory row's author as "true for
# every file under this path NOT more specifically declared elsewhere" —
# never as an unconditional claim about literally everything `git ls-files`
# would return for it. This is why `book/src/gallery/` still reads
# `artifacts` even though 11 of its 56 files are declared `none(...)`
# individually below it: the specific rows are what make that claim true.
#
# Adding a generated directory means adding it HERE, with its author, and
# `git add`-ing its contents in the same commit.
#
# THE CRITERION IS "REGENERATE-ARTIFACTS.SH WRITES IT", NOT "IT IS A COMMITTED
# FIXTURE" — and the difference is load-bearing enough that two sessions
# proposed widening this list the wrong way on 2026-08-23 before checking.
#
# THIS PARAGRAPH IS THE `artifacts`-ROW CRITERION ONLY, NOT THE WHOLE FILE'S
# (review finding I4, final review of The Attestation — left standing,
# unqualified, between the two paragraphs above and below it that state the
# actual, wider rule). Since Task 5, only 15 of this file's 72 rows (13
# `artifacts` plus 2 `census`, itself the same script under `HV_CENSUS`) are
# produced by `scripts/regenerate-artifacts.sh` at all; the other 57 are not,
# and 56 of those are declared `none(...)` — a roster author writes NOTHING
# there, by Nathan's G3 ruling (decision 0457), which this paragraph predates.
# The file-wide criterion is decision
# [0458](decisions/0458-tracked-ness-proves-coverage-never-freshness.md)'s:
# tracked-ness proves COVERAGE, never freshness. A path belongs in this file
# when it needs that coverage guarantee AND has a true author to declare
# (a roster set, or `none(<reason>)`) — this paragraph only narrows that to
# the `artifacts` rows' own stronger property, below.
#
# A path belongs here when `scripts/regenerate-artifacts.sh` PRODUCES it, so a
# stale copy is a bookkeeping failure the artifacts phase should fix on its own.
# `clients/game/core/tests/fixtures/` qualifies: regenerate-artifacts.sh:827-843
# writes those seed-42 session snapshots via `possess --snapshot`, and they are
# a cached INPUT — tests read them instead of paying for genesis.
#
# BYTE-GOLDENS ARE THE OPPOSITE AND MUST NEVER BE LISTED HERE AS THE
# `artifacts`/`census`/`heavy` AUTHOR OF THEIR OWN BYTES.
# `cli/tests/fixtures/`, `windows/vessel/tests/fixtures/` and
# `windows/worldgen/tests/fixtures/` are guarded by `kernel/src/golden.rs`,
# which PANICS on mismatch unless `REBASELINE=1`. They are ASSERTIONS, not
# inputs: a stale one means the world's bytes moved, which is exactly the
# determinism signal the project exists to protect. `make rebaseline` does not
# write them and must not — `make rebaseline-goldens` does, deliberately, so a
# human reviews the diff before accepting new bytes. (One byte-golden,
# `book/src/reference/layering-generated.md`, was found nested INSIDE a
# declared `artifacts` directory by Task 1 of this campaign; it is declared
# `none(...)` below rather than deleted from tracked-ness checking, but it is
# still never declared as `artifacts`-authored — see its row for detail.)
#
# Listing a byte-golden here as an `artifacts`/`census`/`heavy` author would be
# inert today (regeneration never touches it, so the diff is always empty) and
# actively harmful the moment anything did: the artifacts phase COMMITS the
# drift it finds, which would silently rebaseline a determinism golden and
# land it green. The gate phase failing on a stale golden is not a gap in this
# list. It is the design.
#
# AND `cli/tests/fixtures/` IS WORSE THAN THE OTHER TWO, not merely another
# golden. `kernel/src/golden.rs` says so in its own header:
#
#     Frozen *historical* pins (the `pre-<campaign>` fixtures under
#     `cli/tests/fixtures/`) are NOT goldens: their bytes must never track
#     current code, so they are compared directly and have no accept path.
#
# A golden has an accept path a human may deliberately take. A frozen
# historical pin has NONE, because its whole value is being a record of what
# the world used to emit. Declaring that directory is a category error rather
# than an inert mistake: there is no circumstance, including `REBASELINE=1`,
# under which regenerating it is correct.

# `docs/generated-path-writes.tsv` (Task 4, The Attestation) is Task 1's
# by-hand write-set measurement made a byproduct of every ordinary run: a
# footer inside scripts/regenerate-artifacts.sh counts, per other declared
# row above EXCEPT a `census`-authored one (see below), how many of that
# row's tracked files carry an mtime newer than a marker stamped at the top
# of the same run (mtime advanced, not content changed). Self-consistent
# rather than circular — the record of what an author wrote is written by
# that author and declared against it, so this row is genuinely tracked and
# genuinely authored by `artifacts`, and
# `every_declared_generated_path_is_tracked` covers it exactly the way it
# covers every other row.
#
# `census`-AUTHORED ROWS ARE EXCLUDED; `heavy`-AUTHORED AND `none(...)` ROWS
# ARE NOT (review finding I3, final review — this scoping was added after
# the fact, and its first draft over-excluded). A `census`-authored row is
# written by a DIFFERENT invocation of this same script (`HV_CENSUS=1`), so
# the SAME row's true written/tracked counts differ depending on which
# invocation last ran: a plain run leaves a census row's directory at
# `1/229` (only the unconditional schema-backfill touches it); a census run
# leaves the identical row at `229/229`. Before this fix the footer captured
# whichever shape the LAST run happened to be, `scripts/sluice-census.sh`'s
# `git add -u` committed a census run's `229/229` shape onto the delivery
# branch, and the next ordinary merge's `artifacts` phase silently wrote
# `1/229` back — perpetual, undetected two-way churn on a brand-new
# drift-checked artifact, because `measured_writes()` in
# `cli/tests/suite/generated_paths.rs` reads only key PRESENCE, never the
# counts.
#
# `heavy`-authored rows (`the-history/`, `the-sounding/`) and `none(...)`
# rows have NO such ambiguity to exclude for: this script never writes
# either kind of path under ANY flag it accepts (the heavy tier is a
# separate test binary; a `none(...)` row's whole claim is that nothing here
# writes it), so their captured counts are stable regardless of invocation.
# They also cannot be dropped without breaking a sibling check:
# `an_overriding_declaration_must_be_measured` requires every OVERRIDING row
# — of any author, `none(...)` included — to have a writes.tsv entry (key
# presence only, never the values), and most `none(...)` rows are exactly
# such overrides (e.g. `book/src/gallery/the-sky.md` overriding
# `book/src/gallery/`'s `artifacts`). Excluding only `census` loses no
# coverage that check needs, since every override case it resolves today is
# a non-`census` row overriding a less-specific `census` row (e.g.
# `.../the-census/schema.json` over `.../the-census/`), never the reverse.
#
# IT IS NOT GIVEN A ROW IN ITS OWN OUTPUT, AND THAT IS DELIBERATE (review
# finding, Task 4). A shell redirect on a compound command
# (`{ ...; } > docs/generated-path-writes.tsv`) stamps the target's mtime at
# open time, before anything inside the group runs — so a self-check would
# read this file's own mtime as "just written" on every single run,
# unconditionally, whether or not the footer's logic actually changed
# anything. That is guaranteed true by construction, not an observation, and
# Step 3's falsifier (delete the generator, watch the count drop to zero)
# cannot apply to it — deleting the footer deletes the file's only writer,
# so there is no "not written" state distinguishable from "not generated at
# all". The footer's own comment (scripts/regenerate-artifacts.sh, next to
# `write_capture_self_path`) names this path and excludes it from the rows
# it emits rather than fabricate a number that looks measured but isn't.
docs/generated-path-writes.tsv	artifacts
